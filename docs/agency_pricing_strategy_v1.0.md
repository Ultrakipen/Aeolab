## 1. 문제 진단

### 1.1 반증 절차 (개선과제 제안 전 필수)

> "너무 싸다"는 우려가 (a) 마진 (b) 확장성 (c) 포지셔닝/브랜드 (d) 판단 불가 중 어느 것인지 구분.

**A. 마진 문제인가?**

| 패키지 | 실제 시급 (2026년 기준) | 최저시급(10,320원) 비교 | 판단 |
|--------|----------------------|----------------------|------|
| 01 (49,000원 / 5.2h) | 9,423원/h | 미달 (-897원/h) | 마진 문제 **실재** |
| 02 (79,000원 / 6.0h) | 13,167원/h | 충족 (+2,847원/h) | 문제 없음 |
| 03 (119,000원 / 11.2h) | 10,625원/h | 충족 (+305원/h) | 거의 경계 |
| 코칭 (30,000원 / 1h) | 30,000원/h | 대폭 충족 | 문제 없음 |

근거: `delivery.py:57-85` work_hours 값 직접 확인 + 고용노동부 2026년 최저임금 10,320원.  
반증: 1인 개인사업자이므로 법적 최저임금 적용 의무 없음. 하지만 시급 미달은 지속 가능성 신호.

결론: **마진 문제는 01 패키지에 한해 실재한다.** 03은 경계선이나 코칭 포함이라 단순 시급 비교가 불리한 측면 있음(코칭 단독 30,000원/1h 가치를 포함하면 실질 수익률 더 양호).

**B. 확장성 문제인가?**

과거 계획: 자동화 후 주 5건, 월 최대 수익 약 160만원.  
현재 상황: 0건 주문으로 확장성 한계에 도달하기 전 상태.  
반증: 0건이므로 확장성은 아직 제약 요인이 아님. 10건이 넘은 시점의 문제.

결론: **확장성 문제는 현 시점에서 가상의 문제다.** 주문 월 5건 이상 발생 시 재검토 필요.

**C. 포지셔닝/브랜드 문제인가?**

49,000원 스마트플레이스 등록 대행은 시장 대비 50~89% 수준. 너무 싸면 품질 의심을 유발할 수 있다는 우려.  
반증 시도: 소상공인 심리에서 "싸고 좋은 것"을 찾는 경향이 강하다. TalkB는 49,000원/월 정기 모델로 운영 중이며 1회성 49,000원은 다른 포지션. 가격 자체가 신뢰를 해치는지는 신뢰 요소 부재 때문인지 구분 불가.

결론: 포지셔닝 문제는 **가격 때문만은 아닐 수 있다.** 가격보다 "누가 하는가", "결과가 보장되는가"의 신뢰 공백이 더 클 가능성 있음.

**D. 판단 불가한 것이 있는가?**

0건 주문 = 가격이 장벽인지, 발견(discovery) 문제인지, 신뢰 공백인지 데이터가 없음.  
**현재로서는 가격이 직접 원인인지 확인할 방법이 없다.** 이것이 핵심 제약이다.

### 1.2 과거 결정의 유효성 재검증

| 과거 전제 | 현재 유효성 |
|----------|-----------|
| "소상공인 1초 결정 가격" | 미검증. 0건이라 효과 확인 불가. |
| "01·03 최저시급 미달이지만 1인 부업 수준으로 운영 가능" | 여전히 유효하나, 2026년 최저시급 인상(9,160→10,320원)으로 gap 확대. |

**요약 진단:**
- **진짜 문제 1**: 01 패키지 최저시급 미달 (49,000원/5.2h = 9,423원/h)
- **진짜 문제 2**: 03 패키지 앵커 약화 (7% 할인 = 9,000원 절감은 결제 동기로 약함)
- **진짜 문제 3**: 0건이라 어떤 전략이 맞는지 측정 데이터가 없음
- **오판 후보 제거됨**: 확장성 문제(0건이므로 가상), 브랜드 문제(데이터 없음)

### 각 안 상세

#### A안 — 가격 동결 + 신뢰 인프라 우선

가격은 현행 유지. 대신 다음을 먼저 개선한다:
- 배달 페이지에 "운영자 소개" 섹션 추가 (누가 하는가)
- "7일 내 자료 미제출 시 자동 환불" 외 "결과 보장 조항" 구체화
- 성공 사례가 생기면 즉시 `/stories`에 게시

**적합한 경우**: 가격이 문제가 아니라 신뢰가 문제라고 판단할 때. 측정 환경 확보 후 판단.

**문제**: 01 최저시급 미달 문제는 계속 남는다. 앵커도 약한 상태로 유지된다.

#### B안 — 단순 가격 인상 (시급 기반)

모든 패키지를 목표 시급 15,000~20,000원 기준으로 인상:
- 01: 78,000원 (5.2h × 15,000원), 반올림 79,000원
- 02: 90,000원 (6.0h × 15,000원)
- 03: 168,000원 (11.2h × 15,000원)

**문제**: 03이 15만원을 초과해 과거 원칙("15만원 미만") 위반. 소상공인 결제 저항 증가. 0건 상황에서 첫 주문을 인상된 가격으로 받는 실험은 리스크가 크다.

#### C안 — 소폭 인상 + 앵커 복원 (권장)

최소한의 가격 변경으로 두 문제(시급+앵커)를 동시 해결:
- 01: 49,000 → **59,000원** (5.2h × 11,346원/h → 최저시급 충족)
- 02: 79,000원 **유지** (13,167원/h, 이미 충족)
- 03: 119,000 → **129,000원** (코칭 포함 개별합산 168,000원 대비 23% 할인)
- 코칭 단독: 30,000원 **유지**

앵커 복원 근거: 03 패키지는 01(59,000) + 02(79,000) + 코칭(30,000) = 168,000원을 모두 포함한다. 코칭 30,000원은 실제 별도 상품으로 판매 중이므로 168,000→129,000 비교는 허위 비교가 아니다. 단, 앵커 표시 시 "각각 따로 구매하면 168,000원" 방식으로 명시해야 한다.

## 3. 권장안 — C안 상세 설계

### 3.1 가격표

| 패키지 | 변경 전 | 변경 후 | 변화 | 새 시급 |
|--------|--------|--------|------|--------|
| 01 스마트플레이스 등록 대행 | 49,000원 | **59,000원** | +10,000원 (+20%) | 11,346원/h ✅ |

| 03 종합 풀패키지 | 119,000원 | **129,000원** | +10,000원 (+8%) | 11,518원/h ✅ |
| 코칭 단독 옵션 (60분) | 30,000원 | **30,000원** | 변경 없음 | — |

### 3.2 앵커 문구 설계

03 종합 풀패키지에서 사용할 비교 근거:

```
개별 구매 시: 01(59,000) + 02(79,000) + 코칭(30,000) = 168,000원
종합 패키지: 129,000원 → 39,000원 절감 (23% 할인)
```

**표시 원칙 (허위 비교 방지)**:
- "각각 따로 구매하면" 또는 "개별 합산" 표현 사용 필수
- 코칭 30,000원은 반드시 실제 별도 판매 옵션으로 페이지 내에 노출돼야 한다 (코칭 옵션이 숨겨지면 앵커가 허구가 됨)
- `delivery/page.tsx` 패키지 설명란에 코칭 단독 옵션 섹션 추가 필요

### 3.3 왜 이 안이 "0건 상황"에서도 합리적인가

1. **최저시급 달성**: 01 패키지가 9,423원/h → 11,346원/h으로 개선. 첫 주문부터 합법적·지속가능한 수준 확보.
2. **소상공인 심리 장벽 최소화**: 01 인상(10,000원)은 "커피 한 잔" 수준. 59,000원은 여전히 "5만원대" 심리 구간. 02는 변화 없음.
3. **앵커 복원**: 03의 할인율이 7%(9,000원 절감) → 23%(39,000원 절감)로 개선. 종합 패키지의 가치가 더 명확해짐.
4. **코드 변경 최소**: prices.py 숫자 2개만 바꾸면 백엔드 단일 소스 반영. 프론트엔드는 API에서 가격을 받는 구조 + FALLBACK_PACKAGES 7곳 업데이트.
5. **과거 원칙 준수**: "5만원 미만/15만원 미만" 마지노선 → 59,000원(5만원 초과이지만 6만원 미만, 신규 수정), 129,000원(15만원 미만 유지).

> **수정된 마지노선**: 01은 49,000원에서 59,000원으로 이동하여 과거 "5만원 미만" 기준을 벗어남. 이것이 "1초 결정"에 영향을 주는지는 첫 5건 관찰 후 재검토.

## 5. 측정 계획

### 5.1 기존 인프라 현황

| 계측 도구 | 현재 상태 | 활용 가능 여부 |
|---------|---------|-------------|
| `/admin/growth-funnel` | trial→가입→전환 퍼널 (2026-07-12 신설) | 가입→구독 전환 추적 가능, 배달 페이지는 별도 |
| `delivery_orders` 테이블 | 0건 | 주문 건수·패키지별 분포 추적 가능 |
| `ai_usage_log` 테이블 | 2026-07-12 신설, AI 호출 계측 | 배달 관련 AI 호출(없음)은 해당 없음 |
| GA4 | 홈페이지 라이브 | 페이지 조회수·체류 시간 추적 가능 |

### 5.2 측정해야 할 지표

**1단계 — 첫 주문 5건 달성까지:**

| 지표 | 측정 방법 | 목표 |
|------|---------|------|
| 배달 페이지 조회수 | GA4 `/delivery` 페이지 뷰 | 주 50 이상이면 가격 문제 아님 가능성 높음 |
| 패키지 클릭률 | GA4 "신청하기" 버튼 클릭 이벤트 | 조회 대비 10% 이상 |
| 신청 완료 전환율 | `delivery_orders` 신규 행 / 조회수 | 클릭 대비 30% 이상 |
| 패키지별 주문 비율 | `delivery_orders.package_type` GROUP BY | 01이 지배적이면 가격 올렸어도 OK |

**2단계 — 5건 후 재검토:**

| 상황 | 해석 | 다음 행동 |
|------|------|---------|
| 5건 이내 도달, 패키지 분포 고름 | 가격과 구성 모두 적절 | 유지, 자동화 도구 도입 검토 |
| 5건 이내, 01만 집중 | 01이 유일한 관문 역할 | 01→02 업셀 전략 강화 |
| 조회 있으나 신청 없음 | 신뢰 문제 | 운영자 프로필 추가, 후기 섹션 강화 |
| 조회 자체가 없음 | 발견(discovery) 문제 | 대시보드 DeliveryRecommendCard 노출 강화, 랜딩 섹션 위치 상향 |
| 5건 후 운영자 시간 부족 | 확장성 문제 발생 | Phase 2 자동화 즉시 착수, 가격 재인상 검토 |

**측정 기간**: 최소 3개월(2026-10-15까지). 이 기간 내 주문이 0이면 가격보다 발견·신뢰 문제이므로 랜딩/대시보드 노출 강화 우선.

### 5.3 성장 퍼널 에 배달 섹션 추가 권장

현재 `/admin/growth-funnel`은 trial→가입→구독 전환만 추적한다. 배달 전환도 추가하면:

```
배달 페이지 방문 → 신청 클릭 → 결제 완료 → 작업 진행 → 후기 작성
```

이 퍼널을 `/admin/growth-funnel`에 별도 탭으로 추가하는 것을 권장한다 (구현은 별도 세션).

## 6. 주의사항 및 제약

### 앵커 허위 비교 재발 방지

**반드시 준수:**
- 03 패키지의 "168,000원→129,000원" 비교는 코칭 30,000원 단독 상품이 페이지에 명시된 경우에만 유효하다
- 코칭 옵션 섹션 없이 앵커 표시 금지
- "각 서비스를 따로 이용하면 168,000원" 방식으로 명시 (단순 교차선이 아닌 설명 포함)

### 과거 원칙 중 변경되는 것

| 원칙 | 변경 전 | 변경 후 |
|------|--------|--------|
| 마지노선 가격 | 낱개 5만원 미만 / 종합 15만원 미만 | 낱개 **6만원 미만** / 종합 15만원 미만 |
| 01 시급 | 9,423원/h (최저 미달) | 11,346원/h (최저 충족) |

### Phase 2 자동화 우선순위와의 관계

C안 채택 시에도 Phase 2 자동화(소개글 AI 초안 + 메뉴 엑셀)는 여전히 가치 있다. 자동화 후 시급이 추가로 개선되면 03 패키지를 조정할 여지가 생긴다. 단, 자동화보다 **첫 5건 실주문 확보가 우선**이다.

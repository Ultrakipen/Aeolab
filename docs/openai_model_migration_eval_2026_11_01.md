# gpt-4.1-mini 교체 후보 비교 (2026-11-01)

## 배경
- `gpt-4.1-mini` 종료 예정 2027-01-14 (OpenAI API `/v1/models/gpt-4.1-mini`의 `shutdown_date`, 공식 deprecations 페이지와 일치). 코드 의존 15곳(`chatgpt_scanner.py` 등).
- 공식 권장 대체: `gpt-6-luna`.
- 같은 날 종료되는 모델: `gpt-4.1`, `gpt-4o`, `gpt-4o-mini`. 더 일찍: `gpt-5-mini`·`gpt-5-nano`(2026-12-11), `gpt-4.1-nano`·`o4-mini`(2026-10-23). `gpt-5.4-nano`는 2027-04-01 → 같은 5.4 계열의 `gpt-5.4-mini`도 종료일이 곧 붙을 수 있음(목록에는 아직 없음).

## 시험 1 — 운영 프롬프트, 유명 5개 질의 × 10회 (서버, 운영 프롬프트 그대로)
| 모델(설정) | 일치율 | 출력 토큰 | 속도 |
|---|---|---|---|
| gpt-4.1-mini (현재) | 72% | 56 | 0.92s |
| gpt-6-luna / 5.6-luna / 5.4-mini, `reasoning_effort=none` | 100% | 45~48 | 0.99~1.41s |
| 위 3종, `reasoning_effort=low` | 100% | 204~311 (추론 토큰 156~271) | 2.2~3.3s |
| gpt-5.4-nano | 28% | 120 | 1.36s |
- 새 계열은 `max_tokens`·`temperature`를 못 쓰고 `max_completion_tokens`가 필요. 이 SDK 버전은 `reasoning_effort`를 직접 받지 못해 `extra_body`로 전달. **`none`을 쓰지 않으면 출력 토큰이 5배**.
- 유명 질의만이라 정확도가 포화(100%)되어 모델 간 구분력이 없다.

## 시험 2 — 실제 사업장 A/B (운영 `sample_recommend` 로직 그대로, 표본 60, 질의는 DB 저장값)
| 사업장(질의) | 현재 모델 | gpt-6-luna | gpt-5.6-luna | gpt-5.4-mini |
|---|---|---|---|---|
| 어니언 성수 (성수 카페) | 노출 0.58, 서로 다른 가게명 174개 | **1.00**, 26개 | 1.00, 10개 | 0.92, 63개 |
| 홍뮤직 (창원 편곡) | 0.00, 139개 | 0.00, **0개(빈 목록)** | 0.00, 0개 | 0.00, 29개 |
| 대호흑돼지 (창원 동태탕) | 0.00, 212개 | 0.00, 0개 | 0.00, 0개 | 0.00, 60개 |
| 힐링하우스 (창원 마사지) | 0.00, 217개 | 0.00, 0개 | - | - |
| 법무법인 (부산개인회생) | 0.00, 0개 | 0.00, 0개 | - | - |
- 대조군(존재하지 않는 가게 이름): 현재 0/60, gpt-6-luna 0/60 → 환각 노출 없음.
- 현재 모델의 지역 소규모 질의 결과는 "창원편곡스튜디오", "창원 사운드랩"처럼 **일반명사형 가게명이 대량(139~217종)** — 실존 여부 미확인(상당수가 지어낸 이름으로 보임). 이 목록이 화면의 "AI가 추천한 가게"·경쟁사 노출 대조에 쓰이는지 확인 필요.
- gpt-6/5.6-luna는 "모르면 빈 배열" 지시를 지켜 빈 목록을 반환 → 정직하지만 경쟁사 목록·`top_places`가 비게 됨. 또 거의 결정적(서로 다른 가게명 10~26개)이라 **표본 100회가 사실상 1~2회 분량**: 노출률이 0 또는 1로 쏠리고 신뢰구간이 과대하게 좁아 보임.
- gpt-5.4-mini는 유명 가게 0.92 + 표본 다양성 유지(63개) + 지역 질의에서 여전히 가게명 생성(현재 모델과 비슷한 성격).

## 판단 (미확정 — 사용자 결정 필요)
- 안전한 단기 선택: `gpt-5.4-mini` + `reasoning_effort=none` (측정의 성격이 현재와 가장 비슷, 인기 가게 과소평가 해소, 가장 빠름). 단가 미확인, 종료일이 곧 붙을 위험.
- 장기·정직성 선택: `gpt-6-luna` + `none` (가장 최신, 환각 없음). 단 표본 설계(100회 의미)·경쟁사 목록 빈 상태·점수 변동 방식을 함께 재설계해야 함.
- 어느 쪽이든: 교체 시점을 `score_history`/스캔 결과에 모델 버전으로 기록(노출률 기준선 변경), `max_completion_tokens`·`extra_body` 호출부 4곳 이상 수정, 서버 테스트·변이 검증, 며칠 야간 스캔 확인.

## 미확인
- 모델별 정확한 단가(검색 요약: gpt-6-luna $0.10/$0.50, 현재 $0.40/$1.60 — 공식 가격 페이지 재확인 필요), 소규모 질의에서 현재 모델 가게명의 실존 비율, 화면에서 이 목록의 사용처, 5.4-mini 종료 일정.
- 시험은 실제 사업장 5곳(대부분 창원 소규모 + 어니언 성수 1곳) 한정. 유명 가게 표본이 1곳뿐.

## 시험 3 — 오판 검증 (11-01 밤)
- **중간 인지도 실존 가게 5질의 × 20회**(속초 닭강정·제주 흑돼지·전주 비빔밥·강릉 초당순두부·부산 밀면): 현재 모델 87/100(속초 8/20만 적중), gpt-6-luna 100/100, gpt-5.4-mini 100/100. 서로 다른 가게명 수: 현재 45~69종, luna 8~18종, 5.4-mini 29~40종.
- **`temperature=1.0`을 켜도 luna의 다양성은 회복되지 않음**(11~18종) → 낮은 다양성은 모델 특성. 다양성이 높은 쪽(현재 모델)이 오히려 지어낸 이름이 섞인 결과.
- **실존 확인(네이버 공식 지역검색 API `local.json`, 창원 3개 소규모 질의, 질의당 15표본)**: 현재 모델 서로 다른 이름 201개 중 검사한 60개에서 **확인됨 0**; gpt-5.4-mini 66개 중 60개 검사에서 확인됨 4(그중 하나는 "…빈 배열로 답합니다."라는 **문장이 가게명으로 반환**됨 — 현재 파서(40자 이하)는 통과시킴); gpt-6-luna는 언급 0(빈 목록).
- 한계: 검사 대상은 삽입 순서상 앞쪽(첫 질의 "창원 편곡") 위주라 편향, 지역검색에 없는 실존 가게는 '확인 안 됨'으로 나옴. 그래도 0/60은 현재 모델이 소규모 질의에서 가게명을 지어낸다는 강한 증거.
- 결론 수정: 앞 판단의 "5.4-mini가 현재와 가장 비슷해 연속성 면에서 안전"은 **연속성 = 지어낸 경쟁사 이름 유지**라는 뜻이어서 장점이 아니다. gpt-6-luna(`reasoning_effort=none`)가 권장.

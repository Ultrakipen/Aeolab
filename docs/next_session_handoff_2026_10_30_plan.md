### 병렬 묶음 (독립이라 동시에 돌려도 되는 것)
- **웨이브 A (읽기 전용 점검, 동시 실행 가능)**: #3 `scan-engine` · #5 `Explore` · #6 `scan-engine`(별도 인스턴스) · #13 `scan-engine`+`code-review`. 서로 같은 파일을 쓰지 않는다.
- **웨이브 B (웨이브 A 결과를 메인 세션이 확인한 뒤)**: #5 수정(`backend-dev`) · #6 테스트 추가 · #2 모델 갱신. **같은 파일을 두 에이전트가 동시에 수정하지 않는다**(`scheduler/jobs.py`, `routers/admin.py`는 한 번에 한 에이전트).
- **웨이브 C (순차)**: 구현 → `code-review` → `deploy`(서버에 쓰는 에이전트는 항상 1개).
- **동시 금지**: Playwright 사용 에이전트 2개 이상, 서버에 쓰는 에이전트 2개 이상, 서버에서 네이버를 호출하는 모든 작업.

### 에이전트 공통 지시문 (프롬프트에 항상 포함)
1. 목표와 **이미 배제된 것**(경쟁사 갱신 주기 변경, 서버에서 네이버·구글 직접 접속, 프록시·기능 축소 제안 실행)을 먼저 적는다.
2. 읽을 문서: CLAUDE.md '작업 중요 지침 8~10번' + 이 문서 §2·§6 + 담당 영역 문서.
3. **읽기 전용 작업은 DB·서버에 쓰지 않는다.** 서버 스크립트는 scp 후 실행·삭제.
4. 보고 형식: ①단정 근거 `file:line` ②반증 시도 `file:line` ③실제 명령 출력 일부 ④"확인한 것 / 미확인" 분리. **"완료했다"만 있는 보고는 무효.**
5. 수정 권장은 **방향만** 제시하고 구체 구현은 메인 세션이 결정한다(호출 그래프 grep 결과 첨부).
6. 키·비밀번호·사용자 개인정보를 출력에 남기지 않는다.

### 메인 세션 검증 의무 (에이전트가 끝난 뒤)
- **병렬 에이전트는 전부 끝난 뒤 한 번에 검증한다**(완료마다 중간 보고하지 않는다 — 메모리 `feedback_verify_after_all_parallel_agents_complete`).
- 백엔드 수정: 핵심 변경 라인을 `Read`/`grep`으로 직접 확인. 배포: `ssh ... grep -n <패턴> /var/www/aeolab/<경로>`로 서버 반영 1줄 이상 + md5 비교 + `pm2 logs --lines 60 --nostream` 에러 0건. 프론트: 빌드 성공 로그까지.
- 에이전트의 P0/P1 주장은 **근거+반증 각 1줄**을 메인이 직접 본 뒤에만 채택, 오탐은 기각 사유를 기록.
- 거짓·부실 보고가 나오면 **재위임하지 말고 메인이 직접 수정**한다.
- 모든 최종 보고 끝에 "오판/오탐/누락 재확인" 1~3줄(미확인 명시).

### 새 대화창 시작 시 권장 순서
1. 메인 세션이 §0·§1을 읽고 사용자 결정 변경 여부를 한 번 묻는다(§3).
2. #1을 직접 처리한다.
3. 웨이브 A를 한 메시지에서 병렬 호출 → 전부 끝나면 보고를 종합·검증.
4. 웨이브 B → C 순으로 진행. 결정이 필요한 항목(#9·#12·#16)은 사용자 답을 받기 전에 진행하지 않는다.

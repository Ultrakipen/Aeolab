# §A. 크몽 상세 설명 본문 (복사용)

## 상품명(안)
**내 가게가 네이버·ChatGPT·구글 AI에 나오는지 실측 점검 + 개선 안내 (AEOlab 베이직 전체 기능)**

## 한 줄 소개
손님이 네이버나 AI에게 "근처 맛집(카페·미용실…) 추천해줘"라고 물을 때 **내 가게가 나오는지 실제로 측정**하고, 무엇부터 고칠지 순서대로 알려드립니다.

## 이런 분께 맞습니다
- 네이버 스마트플레이스를 운영 중이거나 운영할 예정인 **소상공인 사장님**
- 광고비를 쓰기 전에, 내 가게가 지금 검색·AI 추천에서 어디쯤인지 알고 싶은 분
- 근처 경쟁 가게와 무엇이 다른지 궁금한 분
- 소개글·리뷰 답글·블로그 글을 어떻게 써야 할지 막막한 분

## 이 상품이 하는 일
AEOlab(AI 검색 노출 점검 서비스)의 **베이직 플랜 기능 전체**를 판매자가 직접 운영하여, 사장님 가게 기준으로 점검하고 결과를 전달해 드립니다. 직접 가입하거나 프로그램을 다루실 필요가 없습니다.
- 가격은 AEOlab 베이직 플랜 정가와 같은 **17,900원**입니다. `【전달방식 확정 후 수정】`
- 아래 「제공 내용」의 **문구·답글·블로그·키워드** 항목(3~7번)은 베이직의 월 한도 안에서 **사장님이 대화창으로 요청하신 만큼** 작성합니다. 요청이 없는 항목은 만들지 않습니다.

## 제공 내용 (베이직 플랜 전체 기능)

### 1. 내 가게 노출 실측 점검
| 항목 | 내용 |
|---|---|
| **네이버 검색 순위** | 사장님이 알려 주신 대표 키워드로 내 가게가 네이버 지도·플레이스 검색에서 몇 번째에 보이는지 측정 |
| **네이버 AI 브리핑·AI탭** | 네이버 AI 답변에 내 가게가 나오는지 확인 (업종에 따라 대상이 다름) |
| **ChatGPT 노출 측정** | "○○동 맛집 추천" 같은 질문을 **100회** 던져, 내 가게가 몇 번 추천 목록에 나오는지 측정 |
| **구글 AI 개요·구글 지도** | 구글 검색의 AI 개요와 지도에 내 가게가 나오는지 확인 |
| **Gemini 참고 측정** | 구글 Gemini에도 같은 방식으로 질문(현재 참고용 지표) |
| **내 가게 성장 단계** | 시작 전 · 보강 단계 · 개선 중 · 양호 중 어디쯤인지 한 줄로 안내 |
| **원할 때 바로 확인(하루 2회 한도)** | 스마트플레이스를 고친 뒤 네이버에서 달라졌는지 다시 확인 |

### 2. 근처 가게 3곳과 비교
- 근처 경쟁 가게 **3곳**과 비교하여 **"저쪽엔 있고 내 가게엔 없는 검색어"**를 알려 드립니다.
- 비교할 가게를 정해 주시면 반영하고, 없으면 같은 지역·업종에서 판매자가 후보를 골라 대화창으로 확인받습니다.
- 부족한 검색어는 복사해서 스마트플레이스에 붙여 넣을 수 있게 정리합니다.

### 3. "이렇게 고치세요" 개선 안내서 (최대 3건)
- 무엇부터 고칠지 **순서대로** 정리한 안내서 최대 3건.

### 4. 바로 붙여 넣는 문구 (소개글·소식·FAQ·톡톡 채팅방 메뉴 합산 최대 10건)
- 스마트플레이스 **소개글**, **소식**, **FAQ**, **톡톡 채팅방 메뉴** 초안
- ⚠️ **사장님이 알려 주신 사실만** 사용합니다. 가격·영업시간·시설·수상 등 확인되지 않은 내용은 넣지 않거나 "직접 확인 후 기재" 표시로 남깁니다.

### 5. 리뷰 답글 초안 (최대 50건)
- 사장님이 대화창으로 보내 주신 **고객 리뷰 내용** 기준으로 답글 초안 작성 (긍정·중립·부정 구분)
- 부정 리뷰 **위기 대응 답글**(최대 20건 한도 내) 포함
- ⚠️ 리뷰 내용은 **전화번호·이름 등 개인정보를 지우고** 보내 주세요.

### 6. 블로그 점검 (최대 5회)
- 홍보 글과 정보 글의 비율을 보고, **더 잘 찾히는 제목·소재**를 제안
- 운영 중인 **네이버 블로그 주소**가 있어야 합니다(없으면 "블로그를 시작할 때의 소재 추천"으로 대체).

### 7. 검색어(키워드) 추천 (최대 5회)
- 업종·지역에 맞는 검색어를 추천하고, 선점할 만한 키워드를 안내

### 8. 스마트플레이스 자동 점검
- 소개글·소식은 자동으로, FAQ는 체크리스트로 **빠진 곳**을 찾아 드립니다.

### 9. 채널 정보 일치 점검 (하루 2회 한도)
- 내 가게 **이름·주소·전화번호**가 카카오맵·네이버·구글 지도에서 같은지 확인

### 10. AI가 가게 정보를 읽기 쉽게 하는 코드(JSON-LD)
- 홈페이지가 있는 경우, 가게 정보를 AI·검색엔진이 읽기 쉬운 형태로 만든 코드를 제공

### 11. 파일 저장
- 점검 결과를 **엑셀(CSV) 파일**로 제공
- 점검 때마다의 결과를 대화창으로 정리해 전달합니다. (주 2회 점검 안내는 아래 「진행 방법」 참조)

## 결과 전달 방식
`【전달방식 선택】 아래 중 확정된 항목만 남기고 삭제`
- **(옵션 A) PDF 보고서**: 점검 결과 전체와 개선 우선순위를 PDF 보고서로 크몽 납품 파일로 전달합니다. 문구 초안·답글·엑셀도 크몽 납품 기능을 통해 전달합니다.
- **(옵션 B) 웹 화면 직접 확인**: 결과 화면을 직접 보실 수 있는 방법을 크몽 대화창으로 안내합니다. (대화창 안내 가능 여부는 크몽 규정 확인 후 확정)
- **(옵션 C) 가입 정보 전달**: 계정 이용 방법을 크몽 대화창으로 안내합니다.

## 진행 방법 (모든 소통은 크몽 대화창)
1. 주문 후 대화창으로 **가게 정보 입력 항목**(아래)을 보내 주세요.
2. 판매자가 가게를 등록하고 전체 점검을 실행합니다.
3. 결과를 위 방식으로 전달합니다. (납기: `영업일 N일` ← 시험 점검 후 확정)
4. 전달 후 **수정·질문은 이 대화창에서 N회**까지 지원합니다. (N ← 확정)

**진행 기간 (결정 2026-11-03 반영)**: 주문일부터 **30일 동안 주 2회(월·목) 점검**하여 결과를 전달합니다. `【기간·이행 방식 확정 전 게시 금지 — B-6】` 가입 안내는 하지 않으며, 60일 변화 기록은 이 상품에 포함되지 않습니다.

## 주문 후 대화창으로 보내 주실 정보
1. 가게 이름 / 업종 / 지역(동네)
2. 네이버 스마트플레이스 주소(링크) — 없으면 "없음"
3. 대표 검색 키워드 3~5개 (예: "창원 성산구 파스타")
4. 비교하고 싶은 근처 가게 2~3곳 (없으면 생략 가능)
5. 대표 메뉴/서비스, **게시해도 되는 영업시간·가격·시설** (소개글·FAQ 작성에 사용)
6. 네이버 블로그 주소(있는 경우), 홈페이지 주소(있는 경우)
7. 답글이 필요한 고객 리뷰(개인정보 삭제 후 붙여넣기)

**보내지 마세요**: 비밀번호, 주민등록번호, 결제 정보, 네이버·구글 로그인 정보, 개인 연락처.
수집한 정보는 점검과 문구 작성에만 사용하며, 점검에 **AI 서비스(Anthropic·OpenAI·Google)** 가 활용됩니다. 주문 시 이에 동의하신 것으로 봅니다. `【확정 필요】 보관·삭제 기간: 구매 확정 후 N일`

## 꼭 읽어 주세요 (한계 안내)
- 결과는 **측정 시점·기기·로그인 상태에 따라 달라질 수 있습니다.**
- ChatGPT 측정은 AI 학습 데이터 기반이며 **실시간 웹 검색 결과와 다를 수 있습니다.** 이번 측정에서 나오지 않았다고 해서 검색을 켠 화면에서도 나오지 않는다는 뜻은 아닙니다.
- **노출·순위·매출 상승을 보장하지 않습니다.** 이 상품은 측정과 개선 안내를 제공합니다.
- 네이버·AI 서비스의 사양 변경이나 접속 제한으로 일부 항목이 **"확인 전"으로 표시될 수 있으며**, 이 경우 추정값 대신 그대로 표시합니다.
- 스마트플레이스에 직접 입력·수정하는 작업은 포함되지 않습니다(사장님이 안내를 보고 직접 적용). `【확정 필요】`
- 프랜차이즈 가맹점은 네이버 AI 브리핑 대상에서 제외될 수 있습니다.
- 사진 촬영, 광고 집행, 블로그 글 대행 작성은 포함되지 않습니다.

## 자주 묻는 질문
**Q. 가입이나 설치가 필요한가요?** 필요 없습니다. 대화창으로 정보만 보내 주세요. `【전달방식 확정 후 수정】`
**Q. 업종 제한이 있나요?** 음식점·카페·미용 등 대부분의 지역 가게를 지원합니다. 일부 업종은 네이버 AI 브리핑 대상이 아니라 해당 항목이 "대상 아님"으로 안내됩니다.
**Q. 스마트플레이스가 아직 없어요.** 점검은 가능하나 네이버 관련 항목은 "확인 전"으로 표시되며, 등록 후 재점검을 권해 드립니다.
**Q. 수정은 되나요?** 입력하신 정보가 잘못된 경우 및 문구 톤 수정은 대화창에서 N회 가능합니다. 측정 결과 자체는 수정 대상이 아닙니다(실측값).

## B-2. 이 상품 고유의 현실 제약 (결정 필요)
1. **주 2회 점검의 이행 방식이 미정이다 → §B-6.** 관리자 소유 사업장은 야간 자동 스캔에서 제외되므로(`jobs.py:584-589`) 운영자 계정에 등록하는 것만으로는 자동 점검이 돌지 않는다. 60일 변화 기록은 상품에서 제외됨.
2. **PDF 보고서**는 Basic 기능이 아님(`pdf: False`). 운영자 권한으로 출력하며, 점수 숫자 비노출 원칙과 면책 문구가 PDF에 있는지 시험 1부로 확인(미확인).
3. **네이버 접속량**: 사업장 1건 = 키워드 4 + 경쟁사 3 + 일치 점검 등 다수 페이지. 하루 신규 주문 처리 상한을 `scripts/naver_load_model.py`로 환산한 뒤 상품 설명의 "납기"를 확정(미실시). 서버에서 연속 점검 금지.
4. **리뷰 답글 50건 + 위기 답글 20건 + 문구 10건**은 한도 상한이며 전부 채워 납품하면 운영 시간이 크다. "최대"로 표기했고, 실제 납품량 기준(구매자가 준 리뷰 수)을 정해야 한다.
5. **알림톡·이메일 안내**(Basic 부가 기능)는 크몽 대화창 전용 조건 때문에 **상품 기능에서 제외**했다. 설명에 넣지 않음.
6. **계정 이전·가입 정보 전달(옵션 C)**: 구매자 이메일을 대화창으로 받는 것이 허용되는지 미확인.

## B-6. 가입 유도 취소 · 60일 변화 기록 제외 · 주 2회 점검 (사용자 결정 2026-11-03)

## B-7. 구매자별 계정 운영 (사용자 결정 2026-11-03: "내가 직접 구매자에게 정보를 받아 가입, 카드 등록 없이 스캔 가능")

**방식**: 크몽 대화창으로 받은 정보로 판매자가 구매자 건마다 **계정 1개 + 사업장 1개**를 만들고, **결제·카드 없이 베이직 구독을 30일간 부여**한다. 이후 점검은 일반 베이직 구독자와 똑같이 야간 스캔(월·목)이 돌고, 판매자는 그 계정으로 로그인해 일반 화면(수동 스캔 하루 2회 등)을 쓴다. 관리자 계정이 아니므로 §B-6의 "관리자 제외" 문제가 없다.

### 카드 없는 구독 부여 — 코드로 확인한 안전한 형태 (구현 전 설계, 서버 적용은 미실시)
`subscriptions` 행: `plan='basic'`, **`status='cancelled'`**, `end_at=오늘+30일(날짜)`, `billing_key=NULL`, `start_at=오늘`.
- 근거 ①: `get_user_plan`은 `cancelled`라도 `end_at`이 미래면 해당 플랜으로 취급(`plan_gate.py:231-259`) → 30일간 Basic 한도, 이후 free로 자동 강등.
- 근거 ②: 야간 스캔 대상도 같은 기준(`scan_scheduling.py:335` `status=="cancelled"` + `end_at` 미래 → 포함, `jobs.py:564-572`) → 월·목 풀스캔 대상, 만료 후 자동 제외.
- 근거 ③: **`status='active'`로 만들면 안 된다.** 갱신 잡은 `active`이고 `end_at ≤ 오늘`인 행을 골라 자동결제를 시도하는데(`jobs.py:1902-1908`, `1967`) 카드가 없으니 실패 → 유예 진입 → 결제 실패 알림톡·고객 이메일·**운영자 알림**이 발생한다. `cancelled`는 이 조회(`.eq("status","active")`/`grace_period`)에 걸리지 않는다.
- 근거 ④: 결제 불일치 감지 잡(`jobs.py:7315`)은 `payment_events`에 성공 결제가 있는 사용자만 대조하므로 결제 없는 부여 행은 대상이 아니다.
- DB `CHECK`상 status 값은 `active/grace_period/suspended/cancelled/expired/inactive`뿐이라(`supabase_schema.sql:230-231`) 새 상태를 만드는 마이그레이션은 하지 않는다.
- 부작용(미확인, 구현 시 확인): 설정 화면이 "해지 예정"으로 보임(판매자만 봄), 관리자 통계/MRR이 `cancelled` 행을 매출로 세는지(`admin.py:117,465,501` 계열) — **매출 집계에 섞이면 숫자가 부풀 수 있으므로 구현 전에 확인**하고, 섞이면 구분 표시(예: `customer_key='kmong:<주문번호>'`)를 둔다.

### 계정 생성
1. 필요한 정보는 전부 크몽 대화창에서 받는다(가게 정보 §5). **이메일은 구매자 실제 주소 대신 판매자 관리용 별칭(예: `kmong+주문번호@…` 형태, 운영 도메인 메일 수신 가능한 것)을 권장**: 서비스가 보내는 이메일(30/60/90일 안내, 주간 다이제스트, 결제 안내 — CLAUDE.md "적용 완료" 목록의 메일들)이 구매자 개인 메일로 직접 나가면 "대화창 외 소통" 조건을 깨고 구매자에게 낯선 메일이 간다. 구매자가 직접 로그인해 볼 필요가 있는 경우(옵션 B/C)만 실제 이메일 사용 — 그때는 해당 메일 발송을 끄는 방법을 먼저 확인.
2. 가입은 Supabase 관리자 API로 `email_confirm=true`, 무작위 비밀번호로 생성(확인 메일 발송 없음). 비밀번호는 판매자가 비밀번호 관리자에 보관, 구매자에게 전달하지 않는다(PDF 전달형).
3. 알림 설정은 **옵트인(NULL=꺼짐)**이라 전화번호를 넣지 않으면 알림톡이 나가지 않는다(`CLAUDE.md` 알림 옵트인 규칙). 전화번호를 받지 않는다.
4. 온보딩으로 사업장 등록 → 첫 측정은 즉시 접수(백그라운드).

### 도구화 (승인 시 구현)
`backend/scripts/kmong_grant.py` — 기존 도구(`subscription_extend_days.py` 등)와 같은 형식: **기본 드라이런**, `--apply --confirm <건수>`로만 실행, `--rollback`(구독 행·계정·Storage 삭제), 출력에 개인정보 마스킹. 입력: 주문번호, 이메일(별칭), 일수(기본 30). 하는 일: 계정 생성 → `profiles` 확인 → 구독 부여 행 1건 삽입. 사업장 등록은 온보딩 화면을 그대로 사용(코드 변경 없음). 서버 배포는 `deploy_backend_files.sh`, DB 쓰기는 사용자 승인 후.

### 용량·운영 제약
- 구매자 계정 1개 = 정식 구독자 1명과 같은 네이버 접속량(월·목 풀스캔 + 경쟁사 크롤)이 30일간 발생한다. CLAUDE.md의 현실 한계는 활성 사업장 약 35~50곳(`naver_load_model.py`). **크몽 동시 진행 건수 상한을 정하고 그 상한 안에서 일반 구독자와 합산**해야 한다(미실시, 상한 수치는 모델 실행 후 확정).
- 점검은 월·목 야간 자동 스캔이라 판매자의 수동 반복 작업이 필요 없다 — §B-6 방식 ①(수동 8~9회)보다 시간 부담이 작다. 판매자는 결과 정리·대화창 전달만 한다.
- 30일 후 자동 free 강등 → 해당 계정·사업장·Storage 파일은 구매자 데이터 삭제 기간(결정 필요)에 따라 삭제.

## B-8. 단발성 상품 확정 + 계정 운영 방식 정정 (사용자 결정 2026-11-03)

- **B-6·B-7의 "30일 주 2회 점검"은 폐기**(단발성 상품). 크몽 상세 설명·이미지(`docs/kmong_assets/`)에서도 제거됨.
- **운영 방식**: 크몽 대화창으로 받은 구매자 정보로 판매자가 AEOlab에 가입하고, **관리자 권한으로 요금제를 조정해 기능을 사용**한다. 코드는 변경하지 않는다.
- **코드 확인 결과 — "관리자 페이지에서 요금제 조정"은 현재 불가능하다.**
  - 관리자 라우터의 쓰기 기능은 `구독 강제 해지/환불`(`admin.py:99`), 관리자 계정 추가·삭제(`admin.py:420,446`), 카카오 공지 발송(`admin.py:801`), 이메일 시험 발송(`admin.py:1431`)뿐이다.
  - 관리자 화면(`frontend/app/admin/AdminDashboard.tsx`)에서 요금제·구독을 부여/변경하는 문구·기능은 검색되지 않았다(요금제 단어는 라벨 한 곳만).
  - `subscriptions`에 플랜을 쓰는 코드는 결제 확정(`webhook.py:223`)과 설정 화면의 카드 변경·해지·재개(`settings.py:257,321`)뿐이다.
  - 따라서 **지금 코드 그대로는 결제 없이 요금제를 올릴 방법이 관리 화면에 없다.** 선택지는 ① Supabase 대시보드(SQL Editor/Table Editor)로 `subscriptions` 행을 직접 만들기(코드 변경 없음, 지금 가능) ② 관리자 구독 부여 기능 개발(코드 변경 필요 — 현재 금지).
- **①을 쓸 때의 안전한 형태(§B-7 근거 그대로)**: `plan='basic'`, **`status='cancelled'`**(절대 `active` 금지 — 만료일에 자동결제 시도→실패 알림·운영자 알림 발생, `jobs.py:1902-1908`), `end_at`=오늘+N일, `billing_key` 비움. **기간은 7일로 확정(사용자 결정 2026-11-03)** — 아래 SQL의 `current_date + 7`. 상세 설명의 납기 N일·수정 N회는 이 7일 안에 끝나도록 정할 것(7일이 지나면 계정이 free가 되어 한도 기능을 쓸 수 없다). 만료되면 자동으로 free가 된다(`plan_gate.py:231-259`).
  ```sql
  -- 실행 전 사용자 id 확인: select id, email from auth.users where email = '<가입 이메일>';
  insert into subscriptions (user_id, plan, status, start_at, end_at)
  values ('<user_id>', 'basic', 'cancelled', now(), (current_date + 7))
  on conflict (user_id) do update
    set plan='basic', status='cancelled', start_at=now(), end_at=(current_date + 7), billing_key=null;
  ```
  (`user_id`는 UNIQUE라 `on conflict` 사용 가능, `supabase_schema.sql:227`. **이 SQL은 이번 작업에서 실행하지 않았고 시험도 하지 않았다** — 첫 사용 전 본인 시험 계정으로 1회 시험할 것.)
- **부작용(미확인 포함)**
  - 이 기간 동안 해당 계정의 사업장은 일반 구독자와 같이 야간 스캔(월·목)에 포함될 수 있어 네이버 접속량이 늘어난다(용량 한계 35~50곳과 합산).
  - 관리자 통계의 구독·매출 집계에 `cancelled` 행이 섞이는지는 확인하지 않았다.
  - 가입 시 인증 메일이 구매자 이메일로 나갈 수 있다 — 구매자 실제 이메일이 아닌 판매자가 받을 수 있는 주소로 가입하는 것을 권장(대화창 외 소통 금지 조건).
  - 알림톡은 전화번호를 넣지 않으면 나가지 않는다(옵트인).
- **확정값(사용자 결정 2026-11-03)**: 납기 영업일 3일, 수정·추가 질문 2회, 구매자 데이터 삭제는 구매 확정 후 30일. 상세 설명(`kmong_assets/kmong_detail.html`)과 `04_process.png`에 반영됨. 남은 미정: 결과 전달 형태.
- **완료 후**: 납품 끝나면 해당 계정·사업장·Storage 파일을 삭제 기간 정책에 따라 삭제(DB 삭제 ≠ Storage 삭제).

- 가격이 바뀌면 크몽 가격도 함께 바꿀 것(단일 소스 `prices.py` 대조).
- **수익 구조 경고(미확인 수수료 가정)**: 크몽 수수료를 기사 기준 20%로 가정하면 실수취 약 14,300원(PG 영세 0.44% 같은 항목은 별도). 베이직의 AI·서버 원가 자체는 월 수백 원 수준(`plan_limits_v1.0.md` 자동 스캔 ~400원)이라 문제가 아니라 **운영자 작업 시간이 수익을 결정**한다. 건당 30분만 써도 시급 약 2.9만원 수준 → 풀 한도(리뷰 답글 50건 등)를 사람이 채우면 적자.
- 따라서 **기본 납품은 자동화 가능한 범위(측정·비교·점검·보고서)로 고정**하고, 문구·답글·블로그 등은 "요청하신 만큼, 한도 내" 방식으로 쓴다(§A 문구 반영). 한도는 베이직 그대로 노출하되 납품 시간 상한(건당 N분)을 운영자가 정해 지킨다.

# 창업 시장 분석 — 지역별 폐업율 데이터 소스 조사 (2026-09-01)

> 목적: "창업 시장 분석" 페이지의 실제 시장 규모(SBIZ)에 더해, 지역·업종별 **폐업율/생존율** 데이터를 추가해 진입 전략의 근거를 강화. **조사·매핑·라이브 검증 전부 완료(2026-09-01). 다음은 구현 단계.**

## 결론 요약

**`행정안전부_식품_일반음식점 조회서비스`(data.go.kr `15154916`) 계열이 "폐업율" 계산이 가능한 유일한 후보.** 2026-01-25 행안부가 지방행정 인허가 데이터(구 `localdata.go.kr`) 195종을 `data.go.kr`로 통합 개방하면서, 기존에 접근 자체가 어려웠던 LOCALDATA가 SBIZ·DataLab과 같은 방식(자동승인, 무료)으로 신청 가능해졌다. **NEIS 학원교습소정보 API(2026-09-01 추가 조사)는 학원/교습소/독서실을 실제로 커버하지만, 폐업 이력 필드 자체가 없는 "현재 운영중 스냅샷"이라 이 문서의 목적(폐업율)엔 쓸 수 없음** — 상세는 하단 "학원/교습소/독서실" 절 참조.

### 실제 라이브 검증 완료 (일반음식점)

- **엔드포인트**: `https://apis.data.go.kr/1741000/general_restaurants/info`
  (⚠️ `/info` 접미사 필수 — 없으면 `NO_OPENAPI_SERVICE_ERROR`. `data.go.kr/en/data/15154916/openapi.do` 영문판 페이지에서 Request URL 확인됨)
- **인증키**: 사용자가 `data.go.kr/data/15154916/openapi.do`에서 이미 자동승인 발급받음(개발 10,000건/일). 이 문서엔 키 값을 기록하지 않음 — 필요 시 사용자에게 재확인.
- **실제 응답 필드** (제주 서귀포시 사례로 실측):
  - `CLSBIZ_YMD` — 폐업일자 (영업중 레코드는 빈 문자열. 실제 폐업 사례는 이후 휴게음식점 검증에서 확보: `CLSBIZ_YMD="2026-08-29"`, 형식 `YYYY-MM-DD` — 아래 매핑표·§"다음 세션 할 일" 참조)
  - `SALS_STTS_NM`/`SALS_STTS_CD` — 영업상태(`"영업/정상"`/`"01"`), `DTL_SALS_STTS_NM`/`CD` — 상세영업상태
  - `LCPMT_YMD` — 인허가일자
  - `OPN_ATMY_GRP_CD` — 개방자치단체코드(예: `6520000`=서귀포시) — **레코드 단위 지역 식별자**
  - `LOTNO_ADDR`/`ROAD_NM_ADDR` — 지번/도로명주소
  - `MNG_NO` — 관리번호(사업자등록번호 아님, LOCALDATA 자체 관리번호)
  - `totalCount: 2,293,940` — 일반음식점만 전국 229만 건

### ✅ 해결 — 지역 필터 파라미터 (2026-09-01 확인)

`opnAtmyGrpCd` 등 캐멀케이스 추측은 전부 틀렸음 — 이 API는 **`cond[FIELD::OPERATOR]=값` 조건절 문법**을 씀(공식 Swagger가 `data.go.kr` 상세 페이지 HTML 안에 `swaggerJson` JS 변수로 정적 임베드돼 있었음, 페이지 렌더링 없이 `curl` raw HTML → 정규식 추출로 확보). 실제 쿼리스트링 파라미터 전체:

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `serviceKey` | ✅ | 인증키 |
| `pageNo` | ✅ | 페이지번호 |
| `numOfRows` | ✅ | **최대 100** (⚠️ 1000 요청해도 서버가 100으로 조용히 캡 — 아래 §"다음 세션 할 일" 배치 규모 재계산 필요) |
| `returnType` | – | 응답 데이터 타입 |
| `cond[LCPMT_YMD::GTE]` / `::LT]` | – | 인허가일자 이상/미만 |
| `cond[SALS_STTS_CD::EQ]` | – | 영업상태코드 일치(`01`=영업/정상, `03`=폐업 — 실측 확인) |
| `cond[BPLC_NM::LIKE]` | – | 사업장명 부분일치 |
| `cond[ROAD_NM_ADDR::LIKE]` | – | 도로명주소 부분일치 |
| `cond[DAT_UPDT_PNT::GTE]` / `::LT]` | – | 데이터갱신시점 이상/미만 |
| **`cond[OPN_ATMY_GRP_CD::EQ]`** | – | **개방자치단체코드 — 이게 지역 필터** |

**⚠️ `CLSBIZ_YMD`(폐업일자) 필터는 파라미터 목록에 없음** — 폐업일자 범위 조회는 불가, `cond[SALS_STTS_CD::EQ]=03`으로 폐업 레코드만 받은 뒤 클라이언트에서 `CLSBIZ_YMD` 값으로 재필터해야 함.

**실측 라이브 검증**(2026-09-01, 동일 서비스키로 `curl` 직접 호출):
- `cond[OPN_ATMY_GRP_CD::EQ]=6520000`(제주 서귀포시) → `totalCount: 10851` (전국 229만 건에서 정확히 좁혀짐, 캐멀케이스 추측과 달리 실제로 작동)
- `cond[OPN_ATMY_GRP_CD::EQ]=3220000`(서울 강남구, 알려진 코드로 검증) → `totalCount: 51269`, 샘플 주소 `서울특별시 강남구 역삼동...` — **자치단체코드 체계가 익숙한 LOCALDATA(구 `localdata.go.kr`) 8자리 코드와 동일함 확인**
- 서귀포시 조합: `SALS_STTS_CD=01`(영업) 4,921건 + `SALS_STTS_CD=03`(폐업) 5,930건 = 10,851건(지역 totalCount와 정확히 일치, 이 지역엔 다른 상태코드 없음)
- 전국 `SALS_STTS_CD=03`(폐업) 단독 조회 → `totalCount: 1,617,998`(전국 누적 70.5% — **주의: 이건 수십 년 누적 폐업 비율이지 "연간 폐업율"이 아님**, §4 설계에서 반드시 구분할 것)

**→ 아키텍처 결론이 바뀜**: 지역 필터가 실제로 작동하므로, "주기적 전체 다운로드 배치" 없이 **SBIZ와 동일하게 실시간 반경/지역조회 방식으로 설계 가능**. 필요한 지역의 `cond[OPN_ATMY_GRP_CD::EQ]=<코드>&cond[SALS_STTS_CD::EQ]=01`과 `...=03` 두 번 호출해 `totalCount`만 비교하면 API 호출 2회로 즉시 폐업율 근사치를 낼 수 있음(개별 레코드 다운로드 불필요, `numOfRows=1`로 카운트만 조회). 단, "최근 N개월 폐업율" 같은 기간 한정 지표를 원하면 `CLSBIZ_YMD` 필터가 없어서 폐업 레코드 전체(예: 서귀포시 5,930건 → `numOfRows=100`로 60페이지)를 받아 클라이언트에서 날짜로 재필터해야 함 — 이 경우만 배치성 호출이 필요.

### ✅ 지역 필터 최종 방식 결정 — LIKE 주소검색 채택(2026-09-01, 사용자 결정)

`OPN_ATMY_GRP_CD` 코드 기반 필터는 정확하지만, 이 코드값(예: `6520000`)과 AEOlab `businesses.region`(한글 지역명 문자열, 예: `"제주 서귀포시"`) 사이를 잇는 공식 매핑표가 없다 — `localdata.go.kr`이 **2026-04-16부로 완전 폐쇄**됐고(검색 확인, 이전 세션이 §6에서 찾았던 엑셀 다운로드 경로는 이제 죽은 링크), `data.go.kr`에도 자치단체코드 전용 데이터셋이 없으며 Swagger 설명도 `"개방자치단체코드"`라는 라벨뿐 코드표 참조가 없다.

**대안 검증**: `cond[LOTNO_ADDR::LIKE]=<지역명>`(지번주소 부분일치)을 지역 필터로 직접 쓸 수 있는지 실측 비교(서귀포시, 2026-09-01):

| 방식 | totalCount | 비고 |
|---|---|---|
| `cond[OPN_ATMY_GRP_CD::EQ]=6520000` | 10,851 | 정답(자치단체코드 기준) |
| `cond[ROAD_NM_ADDR::LIKE]=제주특별자치도 서귀포시` | 8,240 | 도로명주소 미기재 레코드 다수 누락 — **사용 부적합** |
| `cond[LOTNO_ADDR::LIKE]=제주특별자치도 서귀포시` | 10,755 | 정답 대비 약 0.9% 언더카운트(96건) |
| 위 + `cond[SALS_STTS_CD::EQ]=03`(폐업) | 5,875 | 코드 기준 폐업 5,930건 대비 약 0.9% 언더카운트 |

**결정**: `LOTNO_ADDR::LIKE` 방식 채택(사용자 확인). 사유 — 자치단체코드 매핑표(약 229개 시군구) 구축·유지보수 부담이 없고, SBIZ가 이미 쓰는 `businesses.region` 자유텍스트를 그대로 재사용 가능해 아키텍처 일관성이 높음. 약 1% 언더카운트는 "폐업율"처럼 상대 비교용 지표에는 실질적 영향이 없다고 판단(절대 폐업 건수를 정확히 표시하는 용도로는 부적합 — 그 경우에만 코드 기반 방식 재검토).

**구현 시 주의**:
- `businesses.region`이 `"시도 시군구"` 형태(예: `"제주특별자치도 서귀포시"`)와 정확히 일치해야 LIKE가 잘 걸림 — 축약형(`"제주 서귀포시"`)이면 매칭률이 더 떨어질 수 있어, 실제 구현 시 SBIZ의 Kakao 지오코딩 결과(`region_2depth_name` 등 정규화된 행정구역명)를 재사용하는 편이 안전(§`sbiz_api.py:_geocode_region` 참조)
- 지역명이 짧고 흔한 경우(예: "중구"는 서울·부산·대구·인천·대전·울산 6곳에 존재) LIKE 단독으로는 오매칭 위험 — 반드시 시도명까지 포함한 전체 문자열로 LIKE 실행할 것

### ✅ `bar`(주점) 매핑 방향 확정 — `general_restaurants` 재사용, `singing_bars` 불필요

AEOlab의 `bar`는 ACTIVE 업종(네이버 AI 브리핑 대상)으로, 문맥상 호프집·펍·칵테일바 같은 **서양식 주점**을 의미할 가능성이 높다. 그런데 한국 법령상 **"단란주점영업"은 접객원 없이 손님이 노래를 부를 수 있는 룸 형태 주점**(가무·유흥종사자 없는 노래방+주류 결합업소)을 가리키는 좁은 인허가 범주이고, **"유흥주점영업"은 접객원(유흥종사자)을 두는 성인전용 업소**로 더더욱 다른 범주다. 실제 호프집·요리주점·칵테일바는 한국에서 대부분 **"일반음식점"(이미 검증된 `general_restaurants`)으로 등록**되는 경우가 많다(주류+음식 판매).

**결정(2026-09-01, "술집창업" 850건+"호프집창업" 390건 검색량 확인 후)**: `bar` 카테고리는 `singing_bars`(단란주점영업)가 아니라 이미 검증된 `general_restaurants`를 `BZSTAT_SE_NM`(업종세부명)으로 "호프"/"주점"/"바" 필터링하는 방식으로 확정. **`singing_bars` 활용신청 자체가 불필요해짐** — 검색량은 있지만(bar 카테고리 유지) 데이터 소스는 이미 보유 중.

**✅ `BZSTAT_SE_NM` 분포 실측 완료(2026-09-01)** — `cond[BZSTAT_SE_NM::LIKE]`로 확인:

| 검색어 | totalCount | 확인된 BZSTAT_SE_NM 값 |
|---|---|---|
| `호프` | 212,900 | `호프/통닭`(치킨호프 등, 대형 카테고리) |

→ `bar` 매핑은 `cond[BZSTAT_SE_NM::EQ]=호프/통닭` (또는 `::LIKE]=호프`) + `감성주점` 조합으로 확정. 이걸로 `bar` 카테고리 데이터 소스 조사는 **완결**.

## 학원/교습소/독서실 — NEIS Open API (2026-09-01, 사용자 제공 명세서+인증키로 라이브 검증)

> 이전 세션 판정("CSV 파일 다운로드 전용, API 아님")은 **오판이었음** — 그건 `data.go.kr`의 사본(`전국학원및교습소표준데이터`, `15096277`) 얘기였고, 원 출처인 NEIS(나이스 교육정보 개방포털)엔 정식 실시간 API가 별도로 존재함. 사용자가 명세서(`학원교습소정보_오픈API명세서.xls`)와 인증키를 제공해 라이브 검증 완료.

- **요청제한횟수**: 제한없음(명세서 기재) — 단 한 번 호출당 최대 1,000건(`pSize` 상한, 초과 시 에러코드 `336`)

### ✅ 독서실은 이 API로 커버됨 — 이전 세션 "커버 안 됨" 판정 정정

### ❌ 폐업율 계산 불가 — 이 데이터셋의 결정적 한계

**서울 25,493건 전체(26페이지 전수 페이지네이션)를 확인한 결과 `REG_STTUS_NM`이 100% `"개원"`(개원)이었고, "휴원"·"폐원" 등 다른 상태값이 단 한 건도 없었다.** 이는 이 API가 **현재 운영 중인 학원만 담은 스냅샷 레지스트리**이며, 등록 취소(폐원)된 학원은 상태값으로 표시되는 게 아니라 목록에서 아예 사라지는 구조임을 강하게 시사함(행안부 API의 `CLSBIZ_YMD`/`SALS_STTS_CD=03` 같은 폐업 이력 필드 자체가 없음 — 필드 목록에 `CAA_BEGIN_YMD`/`CAA_END_YMD`(휴원 시작/종료)만 있고 이건 "폐업"이 아니라 "일시 휴원"임).

**→ 결론: 학원/교습소/독서실은 이번 "폐업율" 기능의 데이터 소스로 쓸 수 없다.** SBIZ 상가업소 데이터와 동일한 한계(현재 스냅샷, 폐업 이력 없음). 다만 이 데이터 자체는 다른 용도(정원·수강료·개설일자·시설정보 포함, 지역별 학원 밀집도/시장 규모 파악)로는 AEOlab에 유용할 수 있음 — 별도 기능(창업 시장 분석의 "시장 규모" 섹션 등)으로 검토할 가치는 있으나, **이 문서(폐업율 조사)의 범위 밖.**

## 1. 시장 변화 조사 결과

### 1.1 네이버 AI탭 베타 출시 (확인된 사실)

- **출시일**: 2026년 4월 27일
- **현재 대상**: 네이버플러스 멤버십 사용자
- **확대 계획**: 2026년 상반기 내 전체 사용자 + 모바일 메인 검색창 (목표 발표, 지연 가능성 있음)
- **진입 경로**: 네이버 PC 메인 검색창 / AI 브리핑 하단 / 쇼핑·플레이스 통합검색 결과

**AI탭의 핵심 작동 구조 (네이버 공식 발표)**

AI탭은 단순 링크 나열이 아닌 대화형·조건 해석형 검색이다. 핵심은 네이버 생태계 내 데이터를 종합 활용한다는 것이다.

- 통합검색 + 쇼핑 + 플레이스 + 블로그 + 카페를 한 화면에 통합
- 사용자 생성 콘텐츠(UGC: 리뷰·블로그 후기)와 도메인 특화 데이터를 결합
- "화담숲 근처 뷰 예쁜 카페" → 플레이스 정보 + 방문자 리뷰 + 블로그 후기 종합 분석 후 예약 연결
- "광화문 맛집" → 상호명 옆에 예약 버튼 바로 노출

**AEOlab에 대한 직접적 시사점**: 플레이스 + 블로그 + UGC가 AI탭 답변의 원료임이 공식 확인됨.  
즉, AEOlab이 진단해야 할 노출 조건의 범위가 명확해졌다.

### 1.2 네이버 스마트플레이스 노출 조건 (2026년 기준)

> **출처 신뢰도 주의**: 아래 내용은 마케팅 실무자 커뮤니티(아이보스 등)의 경험적 분석이며,  
> 네이버가 공식 발표한 알고리즘이 아님. 실무적으로 일관되게 보고되나, 공식 확인 불가.

#### 핵심 변화: 키워드 중심 → 행동 데이터 중심

**이전 로직 (2024년 이전)**
- 상호명, 소개글, 카테고리의 키워드 밀도가 노출 순위 결정

**현재 로직 (2026년 기준)**
- 노출 이후의 이용자 행동 데이터가 핵심 지표
  - 플레이스 클릭 후 체류 시간
  - 사진·메뉴·가격 정보 확인 여부
  - 전화·길찾기·예약 버튼 클릭률

#### 플레이스 노출에 영향을 주는 주요 요소

| 항목 | 내용 | 비고 |
|------|------|------|
| 정보 완성도 | 상호명, 소개글, 사진, 메뉴, 가격, 영업시간 모두 입력 | 2026년부터 완성도 자체가 랭킹 요소 |
| 사진 최신성 | 월 1회 이상 신규 사진 업로드 필요 | 사진 클릭률 → 신뢰도 점수 상승 |
| 리뷰 구조 | 다양한 키워드, 지역+업종+경험 표현 포함 | 짧은 기간 몰린 동일 패턴 리뷰 → 마이너스 요인 |
| 사장님 답글 | 답글 작성 = 매장 활성도 데이터로 인식 | 단순 응대가 아닌 신호 지표 |
| 행동 데이터 | 검색 → 클릭 → 체류 → 전화/예약 흐름 | "잘 만든 플레이스"보다 "계속 관리되는 플레이스" 우대 |
| 콘텐츠 흐름 | 블로그 → 플레이스 → 재검색 → 방문 연결 구조 | AI가 이 흐름이 연결된 것을 선호 |

#### 마이너스 요인 (반드시 진단 항목에 포함)

- 짧은 기간에 몰린 리뷰
- 비슷한 문장 구조가 반복되는 리뷰
- 사진 미업데이트 (정보 신선도 저하)
- 사장님 답글 없음 (비활성 신호)
- 업데이트가 멈춘 소개글

### 1.3 네이버 블로그 노출 조건 (2026년 기준 AI탭 시대)

> **출처 신뢰도 주의**: 아래의 E-E-A-T 프레임은 구글의 공식 평가 기준이며,  
> 네이버가 E-E-A-T를 공식 채택했다는 발표는 없음. 마케팅 업계가 개념적으로 차용한 것.  
> 네이버의 공식 알고리즘은 **C-Rank + D.I.A.+** 임.

#### 핵심 변화: 키워드 SEO → AI 인용 AEO

**이전 방식**: 키워드 반복, 글 분량, 포스팅 빈도로 순위 결정  
**현재 방식**: AI가 의도를 파악하여 "인용할 만한 글"을 선별

#### 블로그 AI 인용 조건

**C-Rank (네이버 공식 블로그 신뢰도 알고리즘)**
- C-Rank가 낮으면 AI 인용 후보군에 아예 오르지 못함
- C-Rank가 높다고 반드시 선택받는 것은 아님 (필요조건이지 충분조건 아님)
- C-Rank 핵심: 특정 주제에 집중, 꾸준한 포스팅, 사용자 반응(댓글·공감·체류시간)

**AI가 인용하는 블로그의 특징 (실무 기반)**

| 요소 | 내용 |
|------|------|
| 주제 전문성 | 하나의 카테고리에 집중 (잡블로그 < 전문 주제 블로그) |
| 콘텐츠 구조 | H2, H3 소제목, 표, 번호 리스트 활용 → AI가 정보 위계 파악 |
| 초반 명확성 | 글 시작 40~60단어 안에 핵심 정보 배치 |
| 실경험 증거 | 영수증 인증, 직접 촬영 사진, 수치화된 경험 포함 |
| 정보 최신성 | 주기적 업데이트, 출처 링크 명시 |
| 누락 위험 요소 | AI 생성 글 그대로 발행, 키워드 도배, 구조 없는 텍스트 나열 |

#### 2026년 블로그 조회수 하락의 구조적 원인

블로그 조회수 자체의 하락은 AEOlab의 가치를 오히려 강화하는 근거가 된다.

- 원인 1: 웹사이트 통합 노출 확대 → 블로그 단독 점유율 하락
- 원인 2: AI 브리핑·AI탭 등장 → 사용자가 블로그 클릭 없이 정보 획득
- 원인 3: 사용자 체류 시간의 플랫폼 분산 (유튜브·인스타·숏폼)

즉, "블로그를 AI가 대신 소비"하는 구조로 전환 중이므로, "내 블로그가 AI에 인용되느냐"가 핵심 지표가 된다.

| 내용 | 판정 | 근거 |
|------|------|------|

| 플레이스 행동 데이터 중요성 증가 | ✅ 실무 다수 보고 | 네이버 공식 미발표, 실무 일치 |

| C-Rank = AI 인용 필요조건 | ✅ 실무 일치 | 네이버 공식 미확인이나 구조적으로 타당 |
| 블로그 E-E-A-T 기준 적용 | ⚠️ 마케팅 업계 해석 | 구글 기준 개념 차용, 네이버 공식 아님 |
| AI탭 세부 랭킹 로직 | ❌ 미공개 | 베타 3주차, 내부 알고리즘 비공개 |

**결론**: AI탭이 어떤 기준으로 플레이스를 선택하고 블로그를 인용하는지 세부 로직은 현재 미공개 상태다. AEOlab의 개선 가이드는 이 불확실성을 명시하고 "확인된 패턴 기반 권고"임을 사용자에게 안내해야 한다.

## 3. 서비스 개선 방향

### 3.1 전략 포지셔닝 수정

#### 현재 기획서의 문제

기획서 v7.1의 핵심 차별화는 "6개 AI 플랫폼 통합 관리"이다. 그런데 AI탭 출시로 네이버가 플레이스+블로그+UGC 통합 분석을 직접 운영하기 시작했다. 기획서가 리스크로 예상했던 "네이버 AI탭 사업자 기능"이 실제로 발현된 상황이다.

#### 수정 방향

**변경 전**: "6개 AI 플랫폼 통합 관리"  
**변경 후**: "네이버 AI탭 포함 전 AI 플랫폼에서 내 가게 노출 격차를 진단하고 개선하는 서비스"

핵심 구분을 명확히 해야 한다.
- 네이버 AI탭: "네이버 생태계 안에서의 AI 검색" (네이버가 운영)
- AEOlab: "네이버 안팎 전체 AI 검색에서의 노출 격차 진단 + 개선 가이드" (AEOlab이 제공)

이 구분이 없으면 "네이버 AI탭 쓰면 되지 않나?"라는 반론을 막기 어렵다.

#### 메시지 프레임 수정 (랜딩 및 인터뷰용)

"네이버 AI탭에서 내 가게가 나오는지 확인해드립니다. 그리고 ChatGPT, Perplexity에서는 어떻게 보이는지, 그 차이를 한눈에 보여드립니다."

### 3.2 AI Visibility Score 평가 항목 재구성

#### 현재 기획서 (4.1) 문제점

현재 평가 항목 중 "리뷰 수·평점·키워드 다양성 20%"는 2026년 플레이스 알고리즘 현실과 맞지 않는다. 행동 데이터가 더 중요해졌는데 진단 항목에 빠져 있다.

#### 권고: 평가를 2트랙으로 재구성

**트랙 A: AI 노출 점수** (기존 유지)

| 평가 항목 | 가중치 | 측정 방법 |
|----------|--------|----------|
| AI 검색 노출 빈도 | 30% | 6개 AI 플랫폼 100회 샘플링 |
| 경쟁사 대비 상대 순위 | 20% | 동일 업종·지역 비교 |
| 온라인 언급 빈도 | 15% | 블로그·SNS·커뮤니티 외부 언급 |
| 정보 완성도 | 15% | 플레이스·웹사이트 기본 정보 |
| 콘텐츠 최신성 | 10% | 최근 30일 업데이트 여부 |
| 웹 콘텐츠 구조화 | 10% | Schema 적용 여부 (웹사이트 보유 업체 한정) |

**트랙 B: AI 노출 기반 조건 스코어** (신규 추가 권고)

이 트랙은 "왜 AI에 안 나오는지"를 설명하기 위해 필요하다. 트랙 A 점수가 낮을 때 원인 분석 근거가 된다.

| 진단 항목 | 확인 내용 |
|----------|----------|
| 플레이스 정보 완성도 | 사진 수, 사진 최신성, 메뉴 정보, 영업시간, 소개글 구조 |
| 리뷰 구조 품질 | 리뷰 키워드 다양성, 영수증 리뷰 비율, 지역+업종+경험 표현 포함률 |
| 활성도 신호 | 사장님 답글 작성 여부, 소식 탭 업데이트 빈도 |
| 콘텐츠 구조화 | 블로그 포스팅의 소제목·표·이미지 활용 여부 |
| 마이너스 요인 | 단기 집중 리뷰 패턴, 동일 문장 구조 반복 여부 |

트랙 B가 있어야 "점수는 낮은데 왜 낮은지, 뭘 먼저 고쳐야 하는지"를 사장님에게 설명할 수 있다.

### 3.3 개선 가이드 분기 설계

#### 현재 기획서의 구조적 문제

기획서의 핵심 개선 기능: Schema JSON-LD 자동 생성 + Claude Sonnet 한국어 가이드

이 기능은 **웹사이트가 있는 사업자에게만 작동**한다.

음식점·카페 사장님의 현실: 웹사이트 없음, 네이버 플레이스가 유일한 온라인 존재. Schema JSON-LD를 적용할 곳이 없다.

가장 큰 타깃 세그먼트에 핵심 MVP 기능이 작동하지 않는 구조다.

#### 권고: 사업자 유형별 개선 가이드 분기

```
사업자 유형 분기
│
├── 웹사이트 있는 사업자 (병원·법률·학원·쇼핑몰·전문직)
│   ├── Schema JSON-LD 자동 생성 (기존 계획 유지)
│   ├── 콘텐츠 구조화 가이드 (블로그 포스팅 구조 개선)
│   └── 메타데이터 완성도 진단
│
└── 웹사이트 없는 사업자 (음식점·카페·미용실·소매점)
    ├── 플레이스 소개글 개선 초안 자동 생성 (신규)
    ├── 사장님 답글 템플릿 생성 (신규)
    ├── 사진 구성 가이드 (업로드 우선순위 안내)
    └── 리뷰 키워드 갭 분석 (기존 계획 + 분기 적용)
```

플레이스 소개글 자동 생성은 기술적으로 Claude API로 즉시 구현 가능하며, 웹사이트 없는 사장님에게 가장 직관적인 "뭔가 해줬다" 체감을 줄 수 있다.

### 3.4 효과 증명 시스템 강화

#### 기존 레이어 유지 + 보완

기획서의 3단계 레이어 구조(AI 노출 점수 / 간접 신호 / Before·After 시각 증거)는 방향이 맞다.

**레이어 3 강화**: Before/After 스크린샷 대상에 네이버 AI탭 명시 추가

현재: ChatGPT, 네이버 AI 브리핑에서의 Before/After  
추가: 네이버 AI탭에서의 Before/After

AI탭은 "광화문 맛집"을 검색하면 상호명 + 예약 버튼이 바로 표시되는 구조이므로, "AI탭에 내 가게가 나타났다"는 스크린샷이 가장 직관적인 증거가 된다. 사장님이 매일 쓰는 네이버에서 벌어지는 변화이기 때문에 ChatGPT보다 훨씬 강한 체감을 준다.

**레이어 2 강화**: 플레이스 행동 데이터 연동

네이버 플레이스 통계(조회수·저장수·예약 클릭률)의 Before/After를 AEOlab 개선 가이드 적용 시점과 연결해서 보여주는 구조. "AI 점수 올랐고, 네이버 플레이스 조회수도 올랐어요"가 가장 설득력 있는 효과 증명이다.

---

### 3.5 Phase 0 인터뷰 설계 업데이트

#### 체험 도구 추가

현재 Phase 0 인터뷰의 핵심 체험: "ChatGPT에서 함께 검색해서 보여주기"

**추가해야 할 체험**: "네이버 AI탭에서 함께 검색해서 보여주기"

네이버플러스 멤버십 가입자는 지금 AI탭을 사용할 수 있다. 사장님 앞에서 네이버 AI탭에 "○○ 맛집"을 검색했을 때 경쟁 가게는 나오고 내 가게는 안 나오는 장면이 ChatGPT보다 충격이 크다. 이유: 사장님이 평생 써온 네이버에서 벌어지는 일이기 때문이다.

#### 인터뷰 스크립트 수정 권고

**기존 순서 (기획서 12장)**
1. ChatGPT에서 업종 검색해본 적 있나요?
2. 함께 검색 → 경쟁 가게 나오고 내 가게 없음 확인
3. 매출 영향 인식 확인
4. 9,900원 지불 의향 확인

**수정 순서**
1. 네이버에서 검색하실 때 AI탭 써보셨어요? 같이 한번 해볼까요?
2. 네이버 AI탭에서 업종+지역 검색 → 경쟁 가게 나오고 내 가게 없음 확인
3. ChatGPT에서도 동일하게 검색 → 두 결과 비교 (멀티 AI 격차 실감)
4. 매출 영향 인식 확인
5. 9,900원 지불 의향 확인

네이버 AI탭을 먼저 보여주면 "AI 검색은 ChatGPT 얘기"라는 거부감이 사라진다.

---

### 3.6 업종 우선순위 재검토

#### AI탭 출시가 바꾼 상황

AI탭이 데모에서 보여주는 예시가 모두 로컬 음식점·카페다.
- "화담숲 근처 뷰 예쁜 카페"
- "광화문 맛집"
- "강남에서 카공하기 좋은 카페, 콘센트 있고 좌석 넓은 곳"

네이버가 AI탭으로 먼저 장악하려는 영역이 정확히 음식점·카페 업종이다.

#### 기획서 업종 우선순위 재검토 권고

| 업종 | 기존 우선순위 | 재검토 후 |
|------|------------|---------|
| 병원·학원 | 최우선 | 최우선 유지 (인터뷰 타깃) |
| 음식점·카페 | 특수 전략 (설득 난이도 높음) | **인터뷰 병행 타깃으로 격상 권고** |

변화 근거:
1. 음식점·카페 사장님에게 "네이버 AI탭에 내 가게가 안 나온다"는 체험이 가장 즉각적으로 가능
2. "ChatGPT 얘기가 아니라 네이버 얘기"이므로 설득 난이도가 AI탭 출시로 낮아짐
3. AI탭의 로컬 특화 구조가 이 업종의 위기감을 현실화해줌

단, 여전히 메시지 프레임은 기획서의 "리뷰 자산 확장" / "경쟁자 비교" 프레임을 유지해야 한다. "네이버 리뷰를 부정"하는 방향은 여전히 금지.

새로운 프레임 추가 가능: "사장님, 네이버 AI탭에서 강남 맛집 검색해보셨어요? 옆집은 나오는데 우리 가게는 안 나와요."

## 5. Phase별 수정 계획

### Phase 0 (현재 ~ +2주)

**추가**: 네이버 AI탭 체험을 인터뷰 핵심 도구로 활용  
**추가**: 음식점·카페 업종 인터뷰 병행  
**수정**: 랜딩 메시지 업데이트  
**확인**: AI탭 상반기 전체 확대 시점 모니터링

### Phase 1 MVP (착수 후 3~10주)

**추가**: 트랙 B (AI 노출 기반 조건 스코어) 진단 항목 구현  
**수정**: 개선 가이드를 웹사이트 유/무 기준으로 분기  
**추가**: 웹사이트 없는 사업자용 플레이스 소개글 자동 생성  
**추가**: Before/After 스크린샷 대상에 네이버 AI탭 포함  

기술 구현 메모:
- 플레이스 소개글 생성: Claude API로 즉시 구현 가능
- AI탭 스크린샷: Playwright로 AI탭 URL 접근 후 캡처 (네이버 멤버십 세션 필요, 구현 난이도 검토 필요)

### Phase 2 v1.0 (MVP 이후 11~24주)

**강화**: 효과 증명 레이어 2 — 플레이스 행동 데이터(조회수·저장수·예약 클릭률) 연동  
**강화**: 주간 카카오톡 알림에 "AI탭 노출 변화" 유형 추가  
**추가**: AI탭 전체 사용자 확대 이후 시장 반응 데이터 수집  
**검토**: AI탭 세부 랭킹 로직 공개 여부 모니터링 후 진단 정확도 고도화

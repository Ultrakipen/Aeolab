# AI 소모 대비 데이터 효율 조사 (2026-11-05)

> 해석: "AI 도구" = AEOlab이 쓰는 AI API(ChatGPT·Gemini·Claude). 개발용 도구 토큰 절감은 `docs/token_efficiency_guide.md` 참조(이 문서 범위 아님). 구현은 사용자 승인 후 — 이 문서는 조사만.

## 1. 결론 (요약)
1. **측정 호출(ChatGPT·Gemini)은 이미 거의 공짜다.** ChatGPT 50회 ≈ 1.4원(11-05 실측값 기준, 추정 아님이나 ai_usage_log 장기 누적 전), Gemini는 무료 등급. 비용 지배항은 **Sonnet 가이드 1건 약 138원**(출력 토큰이 약 80%).
2. **진짜 병목은 돈이 아니라 한도·신뢰다**: Gemini 무료 일 약 500회(표본 100회/측정 → 하루 약 5회 측정), 네이버 접속 차단 위험, 소규모 지역에서 ChatGPT가 가게를 못 내놓는 비율.
3. **"질문을 다양화하면 같은 호출로 더 많은 정보" 가설은 실험에서 대체로 기각**(§2). 적용하지 말 것.

## 2. 실험: 같은 20호출, 5문 ×4 반복 vs 서로 다른 20문 ×1
조건: ChatGPT `gpt-6-luna`, 비유도 `_recommend_once`, DB 쓰기·네이버·구글 접속 없음, 총 80호출(약 2원). 각 조건 1회 실행(n=1, 비결정성 있음).

| 지역/업종 | 방식 | 응답 있음 | 빈 응답 | 고유 가게 | 쌍별 겹침 |
|---|---|---|---|---|---|
| 서울 성동구 카페 | A 반복 | 20 | 0 | 18 | 0.47 |
| 서울 성동구 카페 | B 다양화 | 20 | 0 | 19 | 0.47 |
| 창원 성산구 한식 | A 반복 | 3 | **17** | 14 | 0.00 |
| 창원 성산구 한식 | B 다양화 | 8 | **12** | 34 | 0.03 |

해석
- 인구 밀집 지역(서울 카페): 차이 없음(18 vs 19). 질문 다양화는 정보를 늘리지 못한다.
- 소규모 지역(창원 한식): 빈 응답이 A 85%, B 60%. **측정 대부분이 '가게를 못 내놓음'** — 비용 문제가 아니라 유효 관측 부족 문제. B의 고유 가게 34곳은 **실존 여부 미검증**(과거 옛 모델은 소규모 지역에서 가게명을 지어냄 — 네이버 대조 0/60). 많다 ≠ 믿을 수 있다.
- 한계: 지역·업종 2쌍, 각 1회. 결론을 일반화하려면 반복 실행과 네이버 지역검색 대조가 필요(미실시).

## 3. 후보 방안 평가
| 방안 | 효과 | 위험·미확인 | 권고 |
|---|---|---|---|
| 질문 다양화 | 실험상 이득 없음/불확실 | 지어낸 가게 증가 가능 | **하지 말 것** |
| 공유 `probe_cache` 켜기(`AI_PROBE_CACHE_TTL_SEC`) | 같은 (지역·업종) 질의 재사용 → 호출·Gemini 한도 절약 | 프로세스 메모리 캐시(재시작 시 소실), TTL 동안 값이 고정되어 "측정 시점" 표기와 정합 확인 필요 | 가장 안전한 1순위, 설정만, 켜기 전 사용자 결정 |
| 정기 스캔의 Gemini 표본 축소 | 무료 한도(일 500) 여유 확대 | 공개 화면은 `GEMINI_MEASUREMENT_LIVE=false`라 점수 반영 범위 확인 필요(미확인) | 점수 영향 코드 확인 후 결정 |
| Batch API(50%) | 이론상 절반 | probe 비용이 극소라 절감액 미미, 가이드는 사용자가 대기 | 비권고 |
| 프롬프트 캐싱(Sonnet) | 입력 약 20%라 총비용 약 10% 이하(추정, 미검증) | 구현 복잡도 대비 작음 | 후순위 |
| 가이드 출력 토큰 축소·Haiku 라우팅 | 출력이 비용 80% → 가장 큰 레버 | 화면 노출 필드(weeklyRoadmap 등)·품질 저하 → A/B 필요 | 사용자 결정 후 A/B |
| 가이드 재생성 상한 | 이미 적용(`GUIDE_MAX_REGEN`=1, `GUIDE_REGEN_BELOW`=60) | — | 완료 |
| 공공·공식 API 활용 | 비용 0 데이터 | 경쟁사 후보 발굴 활용 여부 미확인 | 추가 조사 |

## 4. 하지 말 것
- `MAX_CLAUDE_CALLS_PER_JOB`을 가이드 때문에 줄이기(jobs.py 3곳과 공유).
- 비용 절감을 이유로 측정 못 한 값을 0점·'없음'으로 저장.
- 질문 변형으로 표본을 부풀려 "관측 수"를 늘려 보이기(effective_n은 서로 다른 질문 수 기준).
- 네이버 접속을 늘려 정보량 확보(차단 위험이 최우선 제약).

## 5. 미확인
- 정기 스캔에서 Gemini 표본이 점수·화면에 실제 반영되는 범위.
- 소규모 지역 빈 응답의 원인(모델 거절 vs `is_plausible_place_name` 필터) — 미분해.
- `ai_usage_log` 장기 실측(현재 단가 추정 기반).

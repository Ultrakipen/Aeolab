## 0. 의도 파악 (사용자 요청 재진술)

1. **판매 채널 = 크몽.** 가입자를 기다리지 않고 크몽 검색 유입으로 구매자를 확보한다.
2. **상품 = AEOlab 베이직(플랜) 기능의 운영자 대행 점검.** 구매자는 서비스에 직접 가입·입력하지 않는다.
3. **흐름:** 구매 → 구매자가 가입정보·가게정보를 전달 → **운영자(사용자)가 AEOlab에 입력** → 전체 점검 → 결과를 (a) 보고서로 전달 또는 (b) 사이트 주소를 알려 구매자가 직접 확인.
4. 크몽에는 **하나의 상품(gig)** 으로 등록.

### 과거 크몽 관련 문서·요청의 처리 (사용자 지시 2026-11-02)
**이전의 크몽 관련 요청·서술(`low_cost_volume_delivery_product_v1.0.md` §A.8 "크몽 채널 철회" 등)은 이 계획의 입력에서 제외한다.** 현재 기준은 단 하나: **"이 서비스의 기능을 크몽에 상품으로 등록해 구매자를 찾는다."**

### 소통 제약 (사용자 지시 2026-11-02, 전 설계의 최우선 조건)
**구매자↔판매자 소통은 크몽 대화창만 허용.** 구매자는 필요한 것을 크몽 대화창으로 전달한다. 따라서:
- 입력 양식·질문·보고서 전달·후속 안내가 **전부 크몽 대화창/크몽 납품 기능 안에서** 끝나야 한다.
- AEOlab의 이메일·카카오 알림톡·전화 등 **외부 채널로 구매자에게 연락하지 않는다**(구매자 연락처를 받지도 않는다).
- 구매자를 AEOlab에 가입시키는 흐름은 **크몽 안에서 허용되는 범위인지 미확인** → 기본 설계에서 제외(§3).

## 2. 상품 정의 — "하나의 상품, 3개 패키지"

크몽 gig 하나에 STANDARD/DELUXE/PREMIUM 3패키지를 둘 수 있으므로 "하나의 상품"과 모순 없이 가격 사다리를 쓴다. 기존 29K/79K/119K 설계를 **크몽 수수료 후 실수취** 기준으로 재검토한다.

**상품명(안):** `네이버·ChatGPT·구글 AI에 내 가게가 나오는지 실측 점검 + 개선 보고서 (소상공인)`

| 패키지 | 산출물 | 납기 | 운영자 시간 | 가격(안) |
|--------|--------|------|-----------|---------|
| **A. 진단 보고서** | 네이버 순위·AI 브리핑·ChatGPT 표본·구글 노출 실측, 등급 라벨, 경쟁사 3곳 비교, 먼저 고칠 3가지, 30일 체크리스트(PDF) | 2영업일 | ~0.7h | 29,000 |
| **B. 보고서 + 실행 초안** | A 전체 + 소개글·FAQ 3·톡톡 메뉴 5·리뷰 답글 10·블로그 소재 5(고객 제공 사실만 사용) | 4영업일 | ~3.5h | 79,000 |
| **C. B + 1개월 직접 확인** | B 전체 + 결과 화면을 구매자가 직접 볼 수 있는 계정/링크 1개월 + 30일 뒤 재측정 1회 | 5영업일 | ~5h | 119,000 |

- "베이직"은 **플랜 이름**이므로 gig 제목에는 "AEOlab 베이직"을 쓰지 않는다(구매자 눈에는 의미 없음). 설명에서 "AEOlab 베이직 플랜과 같은 측정 방식"이라고 한 줄 언급.
- 가격은 **제안값**. 크몽 실수수료 확인 후 재계산(§8-3).
- B의 "고객이 준 사실만 사용" — CLAUDE.md 작업지침 7번 사실 지어내기 금지 그대로 적용. 영업시간·메뉴·시설은 구매자 입력 양식에 있을 때만 문장에 넣는다.

## 3. 전달 방식 2가지 설계 (사용자 요청의 (a)/(b))

### (a) 보고서 전달 — A·B 기본
- 기존 PDF(`/api/report/pdf/{biz_id}`)는 **Pro+ 게이트** → 운영자(관리자=biz 취급)로 호출 가능. 한글 폰트(NotoSansCJK) 있음.
- **점수 숫자 비노출 원칙**(CLAUDE.md "점수 표시 원칙") 그대로: 등급 라벨만. 보고서가 Pro 용 PDF 양식이면 숫자 포함 여부를 **샘플 1부로 확인**(미확인).
- 측정 못한 항목은 0점이 아니라 "확인 전"(지침 9). 네이버 측정이 빠진 스캔은 변화·비교 문구 금지(`change_signal_guard`).

### (b) 사이트 주소로 직접 확인 — C
크몽 대화창만 허용이라는 조건 때문에 이전 안(구매자 가입→소유 이전)은 **기본안에서 제외**한다(가입 이메일 교환·계정 이전 안내가 대화창 밖 소통이 될 수 있고, 대화창에 사이트 URL을 적는 것이 허용되는지도 미확인).

선택지 (§8-2에서 결정):
1. **읽기 전용 공유 링크** — 운영자 계정에 사업장을 두고, 추측 불가 토큰 링크를 대화창으로 전달. 구매자 가입·연락처 불필요. 신규 화면 필요(공유 토큰·만료·개인정보 노출 범위 설계). **URL 전달 허용 여부를 크몽 규정에서 먼저 확인.**
2. **C 패키지 제외** — 보고서(PDF)만 납품. 구현 0, 가장 안전.
3. 구매자 계정 정보를 받아 대신 입력 — ❌ 비권장(비밀번호 수령은 보안·정책 위험).

권장: **1차 출시는 A·B(보고서 납품)만.** C는 크몽의 URL 허용 여부 확인 + 첫 주문 수요가 확인된 뒤 1번으로 추가.

## 4. 운영 흐름 (건당)

```
① 크몽 주문 접수 → 크몽 메시지로 "입력 양식" 전달(§5)
② 양식 회수 → 필수값 검증(사업장명·주소·업종·네이버 플레이스 URL 등)
③ 운영자 계정에 사업장 등록 (온보딩과 동일 경로, 서버 확정 place_id)
④ 전체 스캔 1회 (scan_all, 수동) → 결과 화면을 유명 가게 점검과 같은 기준으로 육안 확인
⑤ 산출물 작성(A/B) → 점검표 §6 통과
⑥ 크몽 메시지/납품 파일 업로드 → 구매 확정 요청
⑦ (C를 둘 경우) 공유 링크 대화창 전달 / 30일 뒤 재측정은 운영자 캘린더로 관리하고 결과도 대화창으로 전달
⑧ 구매 확정 후 구매자 개인정보 보관기간 경과 시 삭제(§7)
```
- 크몽 주문 번호 ↔ AEOlab `business_id` 대응표를 `docs`가 아닌 **DB `delivery_orders`** 에 `channel='kmong'`로 기록하는 안과 별도 시트(CSV) 안 중 택일(§8-4). DB 안은 환불 잡·알림톡과의 충돌 확인이 선행조건(§1 마지막 행).
- 한 건당 네이버 페이지 접속: 키워드 4 + 경쟁사 3곳 등. **일일 상한(제안값 600/일)과 차단 위험**(지침 8)을 고려해 **하루 신규 주문 처리 상한 3~5건**, 서버에서 연속 점검 금지. 상한은 `scripts/naver_load_model.py`로 환산 후 확정(미실시).

## 5. 구매자 입력 양식 (크몽 메시지로 회수)

필수: 사업장 상호·업종·지역/주소·네이버 스마트플레이스 URL(없으면 "없음")·대표 키워드 3~5개·경쟁 가게 2~3곳(선택)·대표메뉴/서비스(B 이상)·**영업시간·가격·시설은 "게시해도 되는 사실만" 체크**.
받지 않는 것: **비밀번호, 주민번호, 결제정보, 네이버/구글 로그인 정보, 이메일·전화 등 외부 연락처.**
- **모든 소통은 크몽 대화창만.** 양식은 gig 설명에 "주문 후 대화창으로 아래 항목을 보내 주세요"로 미리 안내하고, 주문 직후 첫 메시지(템플릿)로 다시 보낸다. 구매자는 텍스트로 답하므로 항목은 번호 목록·짧은 답 형태로 설계(스마트플레이스 URL 복사, 키워드 나열).
- 스마트플레이스 URL이 없는 구매자: "가게명 + 동네"만으로 운영자가 네이버 지역검색 API로 찾고, **후보를 대화창으로 되물어 확정**(동명 가게 오등록 방지, 자동 확정 금지).
- 수정 요청·추가 질문도 대화창 안에서 끝나도록 납품 시 "수정은 이 대화창에서 N회"를 명시(N은 패키지별).

## 7. 법·약관·개인정보

- 구매자 개인정보(이메일·사업장 정보)가 **AEOlab 운영 DB와 AI 업체(Anthropic·OpenAI·Google)** 로 흐른다. 개인정보처리방침 5항(11-01 개정)은 **가입자 대상**이므로 크몽 구매자에게 같은 고지가 적용되는지 확인 필요 → gig 설명과 첫 대화창 메시지에 수집·이용·AI 처리 안내 3줄 + 동의 문구 필요(동의도 대화창 답변으로 받음)(**변호사 확인은 보류 중이라 문구는 초안이며 법적 효력 미확인**, 메모리 "리허설·변호사 의뢰 보류" 참고).

## 8. 사용자 결정 필요 사항 (권장안 포함)

1. **패키지 구성**: 위 3패키지(A/B/C) 안 vs 단일 패키지만. 권장: 3패키지.
2. **C의 "직접 확인" 방식**: 1차 출시에서 C 제외 vs 읽기 전용 공유 링크(대화창 URL 허용 확인 후). 권장: 1차는 A·B만.
3. **가격**: 29/79/119K가 맞는지(크몽 수수료 확인 후 재계산).
4. **주문 기록 위치**: DB `delivery_orders(channel='kmong')` vs 별도 CSV. 권장: 환불 잡 충돌 확인 후 DB.
5. **구매자 데이터 삭제 시점**: 구매 확정 후 며칠(예: 30일).

# AEOlab 개발 대응 전략

> 작성일: 2026년 5월 16일  
> 성격: 기획서가 아닌 실행 문서. "무엇을 어떻게 만들어야 하는가"에 집중.  
> 전제: 1인 개발, Next.js + FastAPI + Supabase 스택, Claude Code 사용

---

## 상황 인식 — 지금 무슨 일이 벌어지고 있는가

네이버가 2026년 4월 27일 AI탭 베타를 출시했고, 6월 중 전체 사용자 확대 예정이다.  
**지금이 AEOlab 개발 착수의 골든타임이다.**

이유는 단순하다. 네이버 AI탭이 전체 사용자에 열리는 순간, "내 가게가 AI탭에 안 나와요"라는 문제 인식이 소상공인 사이에서 폭발적으로 생긴다. 그 타이밍에 해결책이 이미 있어야 한다. 지금 만들기 시작하면 6월 전체 사용자 확대 시점에 맞출 수 있다.

### 네이버 AI 검색의 두 레이어 이해

| 구분 | AI 브리핑 | AI탭 |
|------|-----------|------|
| 출시 | 2025년 3월 | 2026년 4월 27일 |
| 위치 | 기존 검색 결과 안에 삽입 | 별도 화면(탭) |
| 인터페이스 | 1회성 요약 박스 | 대화형 연속 질의 |
| 대상 | 전체 사용자 (검색의 20~40%) | 현재 멤버십 → 6월 전체 |
| 연결 | 블로그·플레이스 요약 | 플레이스 + 예약 + 구매까지 |
| 관계 | 먼저 검증한 레이어 | AI 브리핑의 고도화 버전 |

**소상공인에게 임박한 현실**: 6월이 되면 네이버에서 "강남 카페 추천해줘"를 검색하는 모든 사람이 AI탭을 쓴다. 거기 안 나오는 가게는 사실상 검색에서 사라지는 것과 같다.

## 무엇을 만들어야 하는가 — 핵심 기능 정의

AEOlab이 해야 할 일을 가장 단순하게 정의하면 이렇다.

> **"사장님 가게가 네이버 AI(브리핑+탭)와 ChatGPT에서 어떻게 보이는지 진단하고, 안 나오는 이유를 찾아서, 나오게 만드는 방법을 알려준다."**

이것을 구현하는 데 필요한 기능은 세 가지뿐이다.

1. **스캔** — AI가 내 가게를 어떻게 보는지 자동 수집
2. **진단** — 안 나오는 이유가 무엇인지 분석
3. **가이드** — 구체적으로 뭘 고쳐야 하는지 제시

---

## 개발 순서 — 무엇을 먼저 만들어야 하는가

### 원칙: 가장 빠르게 사장님에게 "와, 이거네"를 만들어줄 것

페이즈를 나누는 기준은 기술적 복잡도가 아니다. **사장님이 처음 봤을 때 충격을 받는 순간까지 얼마나 빠르게 도달하느냐**다.

## Phase 0 — 인터뷰 도구 제작 (지금 당장, 1주일)

### 목표: 노트북 하나로 사장님 앞에서 5분 안에 문제를 보여준다

코드를 짜기 전에 만들어야 할 것은 **현장 시연 스크립트와 수동 도구**다.

### 지금 당장 만들 것

**시연용 프롬프트 세트 (파일로 저장)**

```
# 네이버 AI 브리핑 체험용 검색어 템플릿
# 사장님 업종/지역 입력 후 네이버에서 직접 검색

[음식점·카페]
- "{지역} 맛집 추천해줘"
- "{지역} {업종} 분위기 좋은 곳"
- "{지역} {업종} 주차 가능한 곳"

[병원·한의원]
- "{지역} {진료과목} 잘 하는 병원"
- "{진료과목} {지역} 추천"

[미용실]
- "{지역} 헤어컷 잘 하는 미용실"
- "{지역} 펌 잘 하는 곳"

[학원]
- "{지역} {과목} 학원 추천"
- "{지역} 초등 {과목} 잘 가르치는 학원"
```

**수동 진단 체크리스트 (PDF 1장)**

인터뷰 현장에서 사장님과 함께 체크하는 용도.

```
□ 네이버 AI 브리핑에서 업종+지역 검색 → 내 가게 노출 여부
□ 경쟁 가게 1~3위 확인 → 공통점 파악
□ 네이버 플레이스 정보 완성도
   □ 사진 10장 이상
   □ 최근 30일 이내 사진 업데이트
   □ 메뉴/가격 정보 입력
   □ 영업시간 정확히 기입
   □ 소개글 200자 이상
□ 최근 30일 리뷰 수
□ 리뷰 답글 작성 여부
□ 블로그 후기 최근 포스팅 수
```

**인터뷰 순서 (변경 불가)**

```
1. "네이버에서 같이 검색해볼게요" (AI 브리핑 체험)
   → 경쟁 가게 나오고 내 가게 없음 확인

2. (멤버십 있으면) AI탭에서 동일 검색
   → 더 구체적인 조건 검색으로 충격 배가

3. "왜 안 나오는지 같이 볼게요" (플레이스 체크리스트)

4. "이걸 고쳐드리는 서비스입니다. 월 9,900원이면 써보겠어요?"
```

**Phase 0 판정 기준**: 30명 중 10명이 체험 후 "9,900원 낼게요"라고 할 때 Phase 1 착수.

### 기능 1: 네이버 AI 노출 스캔

**무엇을 만드는가**

사용자가 가게 이름 + 지역 + 업종을 입력하면, AEOlab이 자동으로 네이버 AI 브리핑을 스캔해서 "내 가게가 언급됐는가"를 체크한다.

**어떻게 만드는가**

```
기술 스택:
- Playwright (Python) → 네이버 검색 자동화
- Gemini Flash API → 대량 쿼리 처리 (비용 최소화)
- Supabase → 결과 저장

스캔 쿼리 구성:
업종별 질문 패턴 20개 × Gemini Flash로 응답 분석
= 가게명 언급 여부 + 언급된 컨텍스트 추출

예시 쿼리:
- "{지역} {업종} 추천"
- "{지역} {업종} 분위기 좋은 곳"
- "{지역} {업종} 가성비"
- "{지역} {업종} 주차 가능"
- "{지역} 데이트 코스 {업종}"
```

**핵심 출력물**

```
[결과 화면]
업종 내 AI 노출 순위: 12위 / 25개 업체
이번 주 언급 횟수: 3회 / 100회 스캔
경쟁 1위 업체: ○○○ (23회 언급)

[언급된 실제 AI 응답 예시]
"강남에서 분위기 좋은 카페로는 ○○, △△, □□가 추천됩니다..."
→ 내 가게는 이 답변에 없습니다.
```

**개발 시 주의사항**

- 네이버 robots.txt가 Playwright 크롤링을 막을 수 있음 → 실제 테스트 필요
- 막힐 경우 대안: 사용자가 직접 검색 결과를 붙여넣기하면 AI가 분석하는 방식으로 우회
- AI탭은 로그인(멤버십) 필요 → Phase 1에서는 AI 브리핑만 스캔, AI탭은 Phase 2에서 추가

### 기능 2: 플레이스 완성도 진단

**무엇을 만드는가**

네이버 플레이스 URL을 입력받아 "AI가 이 가게를 인용할 만한 조건을 갖췄는가"를 점수로 보여준다.

**어떻게 만드는가**

```
입력: 네이버 플레이스 URL
처리: Playwright로 플레이스 페이지 스크래핑
출력: 항목별 점수 + 개선 우선순위

진단 항목:
1. 사진 수 (기준: 10장 이상)
2. 최근 사진 업데이트 (기준: 30일 이내)
3. 메뉴/서비스 정보 (기준: 5개 이상)
4. 소개글 길이 (기준: 200자 이상)
5. 영업시간 입력 여부
6. 최근 30일 리뷰 수
7. 리뷰 내 키워드 다양성 (단순 반복 vs 다양한 표현)
8. 사장님 답글 비율 (기준: 최근 리뷰의 30% 이상)
9. 블로그 연결 여부
```

**출력 형식 (사장님이 바로 이해 가능하게)**

```
[내 가게 플레이스 점수: 42 / 100]

🔴 지금 당장 해야 할 것 (영향 큼)
1. 사진이 6개입니다. 10개 이상으로 늘리세요.
   → 안쪽 인테리어, 음식, 메뉴판, 외관 사진 추가 권장

2. 마지막 사진 업로드: 45일 전
   → 이번 주 안에 새 사진 1장 이상 업로드 필요

🟡 이번 달 안에 해야 할 것 (영향 중간)
3. 리뷰 답글이 없습니다.
   → 최근 리뷰 5개에 답글 작성 필요

🟢 여유 있을 때 (영향 낮음)
4. 소개글 120자 → 200자 이상으로 확장 권장
```

### 기능 3: 개선 가이드 자동 생성

**무엇을 만드는가**

진단 결과를 바탕으로 "지금 바로 실행할 수 있는 텍스트"를 자동 생성한다.  
사장님이 복사해서 붙여넣기만 하면 되는 수준.

**어떻게 만드는가**

```
Claude Sonnet API 사용
입력: 가게 정보 + 진단 결과
출력: 실행 가능한 텍스트 콘텐츠

생성 항목:
1. 플레이스 소개글 개선 초안
   (현재 소개글 → AI가 인용하기 좋은 구조로 재작성)

2. 리뷰 답글 템플릿 3종
   (감사 답글 / 불만 답글 / 재방문 유도 답글)

3. 리뷰 키워드 가이드
   (이 업종에서 AI가 자주 인용하는 키워드 목록)

4. 사진 촬영 가이드
   (어떤 사진을 찍어야 하는지 구체적 설명)
```

**소개글 생성 예시 (Claude 프롬프트 구조)**

```python
prompt = f"""
가게 정보:
- 이름: {store_name}
- 업종: {category}
- 지역: {location}
- 현재 소개글: {current_description}
- 주요 메뉴: {menu_items}

현재 네이버 AI 브리핑에서 상위 노출되는 경쟁 가게들의 공통 특징:
{competitor_patterns}

위 정보를 바탕으로 네이버 AI가 '{location} {category} 추천' 질문에
이 가게를 인용할 가능성이 높은 소개글을 작성해주세요.

조건:
- 200~300자
- 지역명, 업종 특성, 차별화 포인트 포함
- "~입니다" 문체, 자연스러운 한국어
- 과장 표현 금지
"""
```

### Phase 1 기술 구현 상세

**프로젝트 구조**

```
aeolab/
├── frontend/          # Next.js 14 App Router
│   ├── app/
│   │   ├── dashboard/ # 메인 대시보드
│   │   ├── scan/      # 스캔 결과
│   │   └── guide/     # 개선 가이드
│   └── components/
│
├── backend/           # Python FastAPI
│   ├── api/
│   │   ├── scan.py    # AI 스캔 엔드포인트
│   │   ├── place.py   # 플레이스 진단
│   │   └── guide.py   # 가이드 생성
│   ├── scrapers/
│   │   ├── naver_briefing.py  # AI 브리핑 스크래핑
│   │   └── naver_place.py     # 플레이스 스크래핑
│   └── ai/
│       ├── gemini_scan.py     # 100회 샘플링
│       └── claude_guide.py    # 가이드 생성
│
└── database/          # Supabase
    ├── stores          # 사업장 정보
    ├── scan_results    # 스캔 결과
    ├── scores          # 점수 히스토리
    └── guides          # 생성된 가이드
```

**Supabase 테이블 설계 (핵심만)**

```sql
-- 사업장
stores (
  id uuid,
  user_id uuid,
  name text,
  category text,
  region text,
  place_url text,
  created_at timestamp
)

-- 스캔 결과
scan_results (
  id uuid,
  store_id uuid,
  platform text,  -- 'naver_briefing' | 'chatgpt' | 'naver_ai_tab'
  query text,
  mentioned boolean,
  mention_context text,
  scanned_at timestamp
)

-- 점수 (주별 집계)
weekly_scores (
  id uuid,
  store_id uuid,
  week_start date,
  ai_exposure_score integer,
  place_score integer,
  rank_in_category integer,
  competitor_count integer
)

-- 생성된 가이드
guides (
  id uuid,
  store_id uuid,
  guide_type text,  -- 'description' | 'reply_template' | 'keyword' | 'photo'
  content text,
  applied boolean,
  created_at timestamp
)
```

**API 엔드포인트 (MVP)**

```
POST /api/scan/start        → 스캔 작업 시작 (비동기)
GET  /api/scan/{store_id}/result  → 스캔 결과 조회
POST /api/place/analyze     → 플레이스 URL 진단
POST /api/guide/generate    → 개선 가이드 생성 (Claude API)
GET  /api/dashboard/{store_id}   → 대시보드 데이터
```

**비용 계산 (사용자 1명 기준 월간)**

```
Gemini Flash (스캔 100회/주 × 4주):
- 입력/출력 토큰 합산 → 약 $0.03/월/사용자

Claude Sonnet (가이드 생성 월 4회):
- 약 $0.06/월/사용자

Playwright 서버 (iwinv):
- 고정비 월 약 3~5만원 (전체 서버)

결론: 사용자 1명당 가변비 약 100원/월
9,900원 구독료 기준 마진 99% (서버 고정비 분산 전)
```

## Phase 2 — 구독 서비스 완성 (Phase 1 이후 8주)

Phase 1이 "한 번 보여주는" 서비스라면, Phase 2는 "계속 붙어있게 만드는" 서비스다.

### 추가할 것 3가지

**1. 주간 자동 스캔 + 카카오톡 알림**

매주 월요일 자동 스캔 → 변화가 있으면 카카오 비즈 API로 알림 발송.

```
[AEOlab 주간 리포트]
○○○ 사장님, 이번 주 결과입니다.

📊 AI 노출 순위: 8위 → 5위 ↑3
📝 이번 주 AI 인용: 7회 / 100회 스캔

💬 실제 인용 예시:
"강남 카페 추천하면 ○○○의 분위기가..."

⚠️ 이번 주 할 일:
사진이 30일째 업데이트 안 됐어요.
이번 주 사진 1장만 올려보세요.

[대시보드 보기] →
```

변화 없을 때 이탈 방지 — 경쟁 가게 변화나 시장 뉴스로 대체:

```
이번 주 순위 변화는 없었어요.
그런데 경쟁 가게 ○○이 이번 주 2계단 올랐습니다.
그 가게가 뭘 바꿨는지 확인해볼까요? →
```

**2. Before/After 스크린샷 카드**

가입 시점 AI 노출 스크린샷을 저장해두고, 30일 후 동일 검색의 스크린샷과 나란히 비교.  
카카오톡으로 공유 가능한 카드로 만들면 바이럴이 일어난다.

```
구현 방법:
```

## ChatGPT 스캔 구현

ChatGPT API를 직접 호출. 네이버와 달리 크롤링 이슈 없음.

```python
async def scan_chatgpt(store_name: str, category: str, location: str):
    queries = [
        f"{location} {category} 추천해줘",
        f"{location} 에서 {category} 어디가 좋아?",
        f"{location} 맛있는 {category} 알려줘",
    ]
    results = []
    for query in queries:
        response = openai.chat.completions.create(
            model="gpt-4o-mini",  # 비용 절감
            messages=[{"role": "user", "content": query}],
            max_tokens=500
        )
        content = response.choices[0].message.content
        mentioned = store_name in content
        results.append({
            "query": query,
            "mentioned": mentioned,
            "context": content if mentioned else None
        })
    return results
```

**중요한 사실**: ChatGPT는 네이버 데이터를 크롤링하지 못한다 (robots.txt 차단).  
즉 네이버 블로그·플레이스 기반 사업자는 ChatGPT에서 노출이 구조적으로 어렵다.  
이것을 진단 결과에서 명확히 보여줘야 한다.

```
[ChatGPT 진단 결과]
내 가게의 ChatGPT 노출: 낮음 (3/100회)

이유: ChatGPT는 네이버 블로그와 플레이스 데이터에 접근하지 못합니다.
ChatGPT 노출을 높이려면:
→ 독립 웹사이트 또는 구글 비즈니스 프로필 필요
→ 외부 블로그(티스토리 등) 포스팅 필요
```


## 핵심 리스크와 대응

### 리스크 1: 네이버가 Playwright 크롤링을 막는다

**현실**: 일반 브라우저 자동화는 별도 차단 없음. 단 과도한 요청은 IP 차단 가능.

**대응**:
- 요청 간격 3~5초 랜덤 delay
- 사용자별 스캔은 주 1회 배치로 제한
- 막히면 즉시 수동 붙여넣기 방식으로 전환

### 리스크 2: Phase 0에서 10명 YES를 못 받는다

**대응**:
- 7명 이상 + 인터뷰 품질이 높으면 착수 검토
- 단순 YES가 아닌 "체험 후 YES"만 유효
- 결과에 따라 타깃 업종·메시지 재설정 후 재인터뷰

### 리스크 3: AI 응답 불일관성으로 스캔 신뢰도가 낮다

**대응**:
- 동일 쿼리 20회 반복 → 빈도로 집계
- "○○ 가게가 나왔다"가 아닌 "100번 중 7번 나왔다"로 표현
- 오차 범위 명시

### 리스크 4: 네이버 광고가 오가닉과 섞여서 진단이 어려워진다

**대응**:
- AI 브리핑 스캔 시 "광고" 표시 여부 파싱해서 별도 집계
- 오가닉 노출만 카운트하는 방식 유지

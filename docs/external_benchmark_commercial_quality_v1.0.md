## §1. 점검 절차 (7단계, 순서 고정)

1. **과거 이력 확인** — 메모리(MEMORY.md) + `docs/nine_pages_measurement_inspection_v1.0.md` 등 상속 문서에서 해당 페이지가 이미 감사된 적 있는지 확인. 있으면 "재조사 금지, 회귀 여부만 검증".
2. **코드 레벨 재검증** — 과거 수정 지점이 여전히 살아있는지 `Read`/`Grep`으로 직접 확인(회귀 스캔). 이 단계에서 끝내지 말 것 — 코드만 보고 "이상 없음" 판정한 과거 사례가 실제로는 오판이었던 전례 있음([[project_action_history_measurement_audit_2026_07_06]] 2차 재검증 참조).
3. **라이브 브라우저 직접 접속** — `browse`(gstack) 스킬로 실제 로그인 후 대상 페이지 접속. MCP `playwright` 도구가 프로필 잠금으로 막히면 `browse`가 별도 프로필이라 우회 가능(이번 세션에 실증). 텍스트 덤프(`$B text`) + 스크린샷(PC/모바일 viewport 둘 다) 확보.
4. **외부 기준 조사** — 페이지 유형에 맞는 참조를 **그때그때 판단**해서 WebSearch:
   - 범용: Nielsen Norman Group 10대 사용성 휴리스틱(`nngroup.com/articles/ten-usability-heuristics`) — 모든 페이지에 적용 가능한 기본 축
   - 경쟁사 비교형 페이지: BrightLocal·SEMrush·Ahrefs 등 실제 상업 로컬SEO/경쟁사 툴 관행
   - 이력/추세/감사로그형 페이지: 감사 이력(Audit Trail) UX 관행(절대+상대시간 병기 등), Grafana/Splunk 차트 어노테이션 관행
   - 페이지 유형이 다르면 그때 새로 검색할 것 — 한 번 조사한 자료를 다른 유형 페이지에 억지로 재활용하지 말 것
5. **반증 시도 후 확정** (CLAUDE.md "문제 분류 검증 의무" 그대로 적용) — 라이브에서 이상해 보이는 것도 코드로 즉시 원인 확인, "다른 가능성"을 먼저 검토. 이번 세션 실제 사례:
   - ✅ 확정: 리뷰 0개+평점 4.1 동시노출(스크래핑 독립 실패), dimension_key 영문 원본 노출, TrendLine 마커 차트범위 밖 방치, score_history 행기준→날짜기준 근본원인, 근본수정 직후 발견한 "빈 상태 문구 오분류" 회귀
   - ❌ 오판으로 철회: "도움말 검색 패널 모바일 오노출"(풀페이지 스크린샷 합성 아티팩트였음, 뷰포트 전용 재캡처로 반증), "정보 과밀 위반"(모바일은 이미 탭으로 progressive disclosure 구현 중이었음, 코드 미확인 상태로 단정한 게 원인)
6. **확정된 것만 수정** — CLAUDE.md "코드 수정 요청 시 필수 절차" 그대로: md5 선확인 → 최소 변경 → scp → 서버 grep 확인 → 빌드 → PM2 재시작 → 에러로그 확인 → **라이브 재접속으로 실제 반영 스크린샷/텍스트 확인**(빌드 성공만으론 불충분) → git 커밋
7. **push 전 서버 드리프트 확인** — `ssh ... git status --short`로 서버 미커밋 변경이 방금 배포한 내용과 일치하는지 diff까지 확인 후 push. GitHub Actions가 지연/장애(status.githubstatus.com 확인)면 서버에서 직접 `git fetch && git reset --hard origin/main` + `deploy.yml` 절차 수동 실행으로 우회 가능(안전 조건: 서버 미커밋 diff가 push할 내용과 100% 일치할 때만).

## §2. 반복 실수 방지 — 이번 세션에서 직접 겪은 것

- **근거 없는 정밀도 금지**: "3.9/5 평균", "2.5/5 → 4/5" 같은 소수점 점수는 실제로 그 시점에 채점한 적이 없으면 지어낸 것. 정성적 등급(강함/보통/약함) + 구체적 근거만 제시할 것.
- **근본 수정이 새 회귀를 만들 수 있음**: `score_history` 쿼리를 행기준→날짜기준으로 고친 직후, 스캔이 뜸한 계정에서 "아직 스캔 기록이 없습니다(=첫 스캔)" 문구가 실제로는 "과거엔 스캔했음"인 사용자에게 잘못 뜨는 걸 라이브 검증에서 발견. **근본 수정 직후엔 반드시 엣지케이스(데이터가 뜸한 계정 등)로 라이브 재검증할 것.**
- **외부 검색이 항상 명확한 답을 주진 않음**: "차트 범위 밖 어노테이션" 같은 미시적 UX 문제는 업계 문서에 답이 없을 수 있음 — 이 경우 정직하게 "외부 기준 없음"을 밝히고 프로젝트 내부 원칙(CLAUDE.md의 "실질적 기능 제거 금지" 등)으로 판단.
- **탭/조건부 렌더링을 확인 안 하고 "화면에 다 보인다"고 단정 금지**: 데스크톱 풀페이지 스크린샷만 보고 "정보 과밀"이라 판단했다가, 코드 확인 결과 모바일은 `md:hidden` + tab state로 이미 분리돼 있었음.

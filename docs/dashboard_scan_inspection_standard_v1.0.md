# 대시보드 스캔결과 점검 기준 v1.0

> 작성: 2026-06-12 | 목적: **"매번 점검하면 개선사항이 나오는" 무한 루프를 끝내는 단일 기준**
> 적용 대상: `/dashboard` 스캔결과 화면 (Hero·네이버 섹션·콘텐츠·오늘할일·상세·글로벌AI)

---

## 0. 왜 이 문서가 필요한가 (근본 원인)

같은 질문("스캔결과 화면 점검해줘")으로 10회 이상 점검했고 **매번 개선사항이 나왔다.**
이는 화면이 나빠서가 아니라 **구조적 문제**다:

1. **종료 조건이 없다** — "완료"의 정의가 없으니 끝이 없다
2. **모든 디자인은 트레이드오프** — 한쪽을 누르면 반대쪽이 "문제"로 보인다
   (점수 숫자 제거 → "데이터 약해 보임", 명확화 위해 반복 추가 → "중복")
3. **전문가·AI는 산출물 편향** — "개선할 점 있냐"는 질문에 빈손으로 끝내지 않는다
4. **실사용자 신호 0** — 유료 구독자 BEP 미달. 아무도 안 쓰는 화면을
   추측으로만 다듬는 중 → 그 공백을 끝없는 전문가 추측으로 채운다

증거: `docs/`에 점검 문서가 계속 쌓이는 것 자체가 "끝없는 점검"의 증상이다
(`scan_result_screens_inspection`, `dashboard_scan_ux_diagnosis`, `dashboard_inactive_ux_fix`,
`dashboard_top_redesign` ...).

**결론: 기준을 "전문가 점검"이 아니라 "고정 체크리스트 + 실사용자 행동"에 맞춘다.**

---

## 1. North Star — 이 화면의 단 하나의 임무

> **"사장님이 이번 주에 네이버 액션 1개를 실제로 실행하게 만든다."**

모든 요소는 이 임무를 **돕거나 → 아니면 잘라낸다.**
판정 신호(향후 측정): Hero "실행 →" 클릭률, 오늘할일 완료 체크율.

이 North Star에 기여하지 않는 "더 예쁘게/더 자세히"는 **개선이 아니다.**

---

## 2. 완료 체크리스트 (점검의 유일한 채점표)

각 항목은 **측정 가능 + 이분법(✅/❌)**. 주관 평가 금지.

| # | 기준 | 측정 방법 | 합격선 |
|---|------|----------|--------|
| 1 | 콘솔/네트워크 에러 0건 | `browse console --errors` | 에러 0 |
| 2 | 모바일 첫 화면에 **결론 1 + 행동 1** | 모바일 첫 viewport 캡처 | 둘 다 보임 |
| 3 | 더미·허위 수치 없음 | 화면 수치가 전부 실측/추정배지 | 위반 0 |
| 4 | **같은 정보 표현 ≤ 2회** | 동일 메시지 인스턴스 카운트 | ≤ 2 |
| 5 | **핵심 행동까지 모바일 스크롤 ≤ 2화면** | North Star 액션 위치 | ≤ 2화면 |
| 6 | **읽기 순서 = 결론→행동→상세 (점진적 공개)** | 섹션 텍스트 위치 + 무거운 카드 접힘 여부 | 행동이 상세 앞 · 무거운 참고 카드 기본 접힘 |

> 부가(상세·심화) 섹션의 길이는 **#5 대상이 아니다** — 핵심 행동만 본다.
> 부가 섹션은 "접힘 기본 + 필요시 펼침"이면 길어도 합격.
>
> **#6 보충 (2026-06-12 신설):** "행동을 찾을 수 있나"(#2·#5)와 "전체가 읽히나"(#6)는
> 다른 차원이다. 행동 버튼이 첫 화면에 있어도, 결론(Hero)과 행동(오늘 할 일) 사이에
> 방대한 참고자료(개선방법·순위표)가 펼쳐져 있으면 흐름이 끊겨 안 읽힌다.
> 인지 순서 **결론 → 행동 → 상세**를 따르고, 무거운 참고 카드(순위표·측정조건·how-to)는
> **기본 접힘 + 눌러서 보기**로 점진 공개한다. 단, 가볍고 핵심인 카드(체크리스트)는 펼침 유지.
> 네이버 우선은 Hero가 네이버 현황을 첫 노출하는 것으로 충족 — 네이버 *how-to 참고* 섹션은
> 행동 뒤로 가도 우선순위가 안 깨진다.

### 현재 점수 (2026-06-12 라이브 실측, INACTIVE 계정 홍스튜디오)

| # | 판정 | 근거 |
|---|------|------|
| 1 | ✅ | 콘솔 0건 |
| 2 | ✅ | Hero "네이버 검색·플레이스가 핵심 무기" + "지금 할 일 실행 →" |
| 3 | ✅ | 키워드 채널별 순위·체크리스트·경쟁순위 전부 실측 |
| 4 | ✅ (수정 후) | "네이버 핵심" 메시지 4회→2회 (`IneligibleBusinessNotice` 반복 헤드라인 제거) |
| 5 | ✅ | 핵심 행동이 Hero(첫 화면) 내부에 존재 |
| 6 | ✅ (수정 후) | ④오늘 할 일을 Hero 직후로 이동(결론→행동) + 네이버 순위표·AI탭·브리핑 기본 접힘(점진 공개). 네이버 섹션 3~4화면→체크리스트1+토글3 |

→ **2026-06-12 기준 6개 전부 ✅. 이 화면은 "완료" 상태.**
→ #6은 사장님이 "순서·읽기" 문제를 지적해 발견 — 제 초기 5개 기준의 맹점이었고, 그 지적으로 기준이 6개로 보강됨.

## 3. 점검 프로토콜 (이 순서만 따른다)

```
1. 위 체크리스트 5개로 라이브 화면을 채점한다 (browse로 실측, 코드 추정 금지)
2. ❌ 항목이 있으면 → 그 항목만 수정한다
3. ✅ 항목은 절대 건드리지 않는다 ("더 개선" 금지)
4. 5개 전부 ✅ → "완료" 선언, 점검 중단
5. 완료 후 변경은 §5(실사용자 막힘)에서만 발생
```

**1회 점검 = 채점 1회 + 미달 수정.** 채점 없이 "개선안부터" 만들면 루프 재발.

## 4. 오판 방지 규칙 (가장 중요)

> 지난 점검들의 오판: 색 다이어트(불필요로 판명)·반복 제거를 "P1"로 단정(취향이었음)

1. **모든 제안은 ❌ 항목에 매핑돼야 한다.** 매핑 안 되면 그것은 **취향 → 하지 않는다.**
2. **사실 vs 취향을 명시 분리해 보고한다:**
   - 사실: "메시지가 4회 나온다" (화면으로 셀 수 있음)
   - 취향: "그래서 줄여야 한다" — 합격선(≤2) 위반일 때만 사실이 된다
3. **제거 전 가치 확인** (메모리 `feedback_no_remove_useful`): 중복·일반론처럼 보여도
   대충 읽는 사장님에겐 반복이 도움일 수 있고, 측정조건 설명은 신뢰 근거일 수 있다.
   **합격선을 넘긴 잉여분만** 제거한다.
4. **라이브 우선** — 코드만 보고 "문제다" 단정 금지. `browse`로 실제 렌더 확인 후 판정
   (색 비판 오판이 코드-only 추정에서 나왔음).

---

## 5. 완료 후 — 점검을 멈추고 무엇을 하나

5개 ✅면 **디자인 점검을 중단**하고 신호원을 바꾼다:

1. **실사용자 1~3명**에게 화면을 주고 *말없이 지켜본다.* "어디서 멈추나, 무엇을 누르나."
   → **실사용자 1명의 막힘 > 전문가 점검 10번**
2. 다음 변경은 *AI/전문가 의견*이 아니라 *실사용자가 실제로 막힌 지점*에서만
3. 연관: CLAUDE.md 남은 작업 "베타 후기 1~3개 확보" = 바로 이 단계

---

## 6. 안티패턴 (이러면 루프 재발)

- ❌ 채점 없이 "개선안" 먼저 생성
- ❌ ✅ 항목을 "더 좋게" 만지기
- ❌ 취향(트레이드오프 선택)을 P0/P1으로 단정
- ❌ 이전에 추가한 것을 이번에 "중복"이라며 제거 → 다음에 다시 추가 (진동)
- ❌ 코드만 보고 색·레이아웃 "문제다" 단정 (라이브 미확인)
- ❌ 한 번에 4~5개 변경 (1개만 검증하고 나머지는 추측)

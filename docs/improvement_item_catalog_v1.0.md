# 개선 항목 카탈로그 v1.0 (2026-10-27)

> **목적**: "점수" 대신 "가게의 부족한 점과 개선하면 좋을 점"을 화면의 중심에 두기 위한 기준 문서. 항목마다 **무엇을 관찰하는지, 어떤 코드로 측정하는지, 얼마나 믿을 수 있는지, 사장님이 직접 확인하는 방법**을 근거와 함께 정리한다. **조사만 했고 코드는 바꾸지 않았다.**
> 상위 문서: `docs/popular_shop_trust_cases_2026_10_27.md`, `docs/keyword_gap_display_inventory_2026_10_27.md`

## 0. 항목 채택 기준과 신뢰 등급

개선 항목으로 화면에 올리려면 **네 가지를 모두** 만족해야 한다.
1. **직접 관찰한 사실**이다(추정·기본값이 아니다).
2. 사장님이 **네이버에서 직접 확인할 수 있다**(링크 제공).
3. 사장님이 **직접 고칠 수 있다**.
4. 화면 문구에 **효과 약속("노출이 늘어납니다", "+20점")이 없다**.

| 등급 | 뜻 | 화면 처리 |
|---|---|---|
| **A** | 측정값이 사실과 일치함을 확인 | "부족/없음"을 사실로 말해도 됨 |
| **B** | 측정은 되나 실제 페이지와 대조가 일부뿐이거나 조건부 | "확인된 개선 여지"로 올리되 직접 확인 링크 필수 |
| **C** | 추정·휴리스틱 | 단정 금지, "직접 확인해 보세요"로만 |
| **X** | 현재 측정 불가 또는 측정이 틀림 | **항목으로 쓰지 않음**(결함 수정 후 재평가) |

## 1. 측정 파이프라인 (확인된 사실)

스마트플레이스 상태를 읽는 함수가 **두 개**다.

| 함수 | 사용처 | 비고 |
|---|---|---|
| `naver_place_stats.check_smart_place_completeness` | 사용자 스캔의 `smart_place_completeness_result`, 사용자 "스마트플레이스 자동 점검"(`POST /api/report/smartplace-check`) | 메뉴·영업시간·소개글·소식·예약·사진 |
| `smart_place_auto_check.auto_check_smart_place` | **체험(trial)** (`scan.py:923`) | 소식 판정 코드가 위와 거의 동일 |

- 스마트플레이스 점검 결과가 있는 스캔은 **플레이스 ID가 있는 6곳 중 3곳**뿐이다(어니언 1/2, 하라식당 2/6, 홍스튜디오 11/12, 나머지 0).
- 스캔 결과의 `photo_count`는 **전 가게 None**, `ai_info_tab_status`는 **전 가게 unknown**.

## 2. 확인된 결함 (근거 + 반증 시도)

### D1. 소식 판정 오탐 — **글이 있는데 "최근 소식 없음"** (P1)
- **재현**: 홍스튜디오(`1752528839`)의 소식 탭에는 2026.10.20·09.22·09.11·07.26·…·06.28 글이 실제로 있다(Playwright 직접 확인). 현재 서버 코드 두 함수 모두 `has_recent_post=False`, `recent_post_measured=True`를 반환.
- **원인(확정)**: 소식 탭 본문 14,216자에 날짜 패턴이 34개 있는데, 본문 중 한 글에 "서울에는 아직 장미 **소식이 없어** 창원까지…"라는 문장이 있어 `소식이\s*없` 정규식이 **글 본문까지** 훑고 날짜 검사 전에 `False`를 반환한다(`naver_place_stats._detect_recent_post_stats`, `smart_place_auto_check._detect_recent_post`).
- **반증 시도**: 어니언·하라식당 모바일 플레이스에는 소식 탭 자체가 없어서 "없음"이 맞다(익명 접속 확인). 즉 측정된 3곳 중 2곳은 정답, 1곳은 오탐.
- **정정**: 앞서 "네이버 날짜가 두 자리 연도라 정규식이 못 읽는다"고 했으나 **소식 탭의 날짜는 `2026.10.20` 4자리**라 이 탭에는 해당하지 않는다(두 자리는 홈의 리뷰 날짜). 철회.
- 영향: 체험 결과, 사용자 스캔, 점검 화면 3경로. 오탐률은 표본 3곳이라 알 수 없다.

### D2. 사진 — **미측정이 "0장 등록됨 / 미통과"로 표시됨**
- `naver_place_stats`: "photo tab not rendered (loading state)"로 `photo_count=None`(전 가게). `smart_place_auto_check`: 정규식 `전체\s*([\d,]+)`가 쉼표만 있어도 매칭 → `int('')` 오류로 건너뜀.
- `report.py:~5222`: `(photo_count or 0) >= 5` → **None이 "사진 5장 이상 미통과"**, 상세는 `"{photo_count}장 등록됨"`(None이면 "None장"이 아니라 `get(...,0)`=0장) — 사실이 아닌 값을 표시.

### D3. 메뉴·서비스 판정이 사실상 항상 True
- `has_menu = re.search(r"메뉴|서비스\s*가격|…", body)` — 홈 본문 어디든 "메뉴"가 있으면 True(탭 이름·리뷰 문구 포함). 메뉴 탭이 없는 홍스튜디오도 True. 구별력 없음.

### D4. 휴면 체크리스트(`GET /api/report/smartplace/{biz_id}`)는 **5곳 전부 동일 결과**
- 서버에서 같은 로직을 8개 가게에 재현: 플레이스 ID가 있는 5곳 모두 `✓✓✗✓✓✗✗ = 4/7(57%) → C등급`. 리뷰 2,283건 가게와 18건 가게가 같다.
- ✗(사진·리뷰 답변·웹사이트)는 미측정/해당 없음 기본값 실패, ✓(기본정보·소개글 Q&A·소식)는 기본값 통과(`done = has_hours or bool(place_id)`, `has_intro`만 있으면 "Q&A 5개 이상" 완료, 소식은 상수 `content_freshness>=50`).
- 효과 약속 포함("정보 완성도 +20~30점", "글로벌 AI 서비스 노출 +15~20점"). **현재 프론트에서 쓰이지 않음(휴면)** — 활성화 금지, 재설계 대상.

### D5. 리뷰 답변율은 측정 코드가 없다
- `naver_result.response_rate`를 기록하는 곳이 없고(모델 필드뿐) 체크리스트는 `or 0`으로 읽는다 → 항상 "미달".

### D6. AI 정보 탭 상태는 자동 측정이 아니다
- `businesses.ai_info_tab_status`는 사용자 설정 컬럼이고 전 가게 `unknown`.

### D7(미확인). 소개글 글자 수가 정확히 500
- 어니언·홍스튜디오 `intro_char_count=500`(하라식당 375) — 상한 절단 의심이나 `_detect_intro_stats` 로직을 읽지 못했다.

## 4. 화면 규칙 (이 카탈로그를 쓰는 방법)

- **개선 여지 구역에는 A·B 등급만** 올린다. C는 "직접 확인해 보세요" 체크 안내, X는 올리지 않는다.
- 항목마다 **관찰 사실 + 측정일 + 직접 확인 링크 + 하는 방법**을 보여 주고 점수·효과 약속은 쓰지 않는다.
- **N/A 규칙**: 해당 없는 항목(예약은 업종별, JSON-LD는 홈페이지 없을 때)은 "부족"이 아니라 숨긴다.
- C04처럼 **"탭이 없다"와 "글이 없다"를 구분**한다(어니언·하라식당은 소식 탭 자체가 없음 → "소식 기능을 쓰고 있지 않습니다").

### 현재 데이터로 적용했을 때 (예상)
- 어니언 성수: 확인된 개선 여지 = C04(소식 기능 미사용, B 가정). C08 예약은 카페라 N/A 가정. 이전의 "키워드 8개 보강", "사진 10장 미완료"는 모두 사라짐.
- 홍스튜디오: D1 때문에 현재 값으로는 C04가 **틀린 개선점**이 된다 — 결함 수정이 선행되어야 한다.

## 7. 선행 수정 1단계 결과 (2026-10-27)

### 수정·배포한 것
- **D1 소식 오탐 수정**: `services/feed_post_parser.py` 신설 — 게시 시각을 **단독 줄**(`2026.10.20.` / `3일 전` / `방금`)에서만 읽는다. 본문 문장 속 "소식이 없어"·"1시간 전부터"는 읽지 않는다. 상태 5종(recent/old/none/no_tab/unmeasured), 읽지 못하면 `has_recent_post=None`(측정 불가)로 두어 "없음"으로 단정하지 않는다. `naver_place_stats`(사용자 스캔·점검)와 `smart_place_auto_check`(체험)가 같은 파서를 쓴다.
- **수정 전 코드는 양방향 오탐**임을 같은 입력으로 확인: 글이 있는 가게 → `False`(정답 True), 오래된 글만 있는 가게 → `True`(정답 False).
- **검증**: 홍스튜디오 서버 실행 — 수정 전 `has_recent_post=False` → **수정 후 사용자 스캔·체험 모두 `True / recent / 2026-10-20`**. 테스트 `tests/test_feed_post_parser.py`(10개), 전체 218개 통과.
- **D8(신규) 차단 화면 감지 결함 수정**: 네이버 차단 화면은 `플레이스` / `서비스 이용이 제한되었습니다.` 두 줄로 나뉘는데 기존 감지는 한 줄 문자열 비교라 **매칭되지 않았다** → 차단 화면이 정상 내용으로 읽혀 차단 중 측정값이 "측정됨"으로 기록될 수 있었음. `services/naver_block.py`(`is_naver_block_page`)로 통일, 두 파일 7곳 교체. 테스트 `tests/test_naver_block.py`(5개).

### 사고: 서버 IP가 네이버에 일시 차단됨
- 검증 중 서버에서 플레이스 페이지를 연속 호출(점검 함수 6회 + 직접 Playwright 5회 이상)하자 응답이 "과도한 접근 요청으로 서비스 이용이 제한되었습니다. IP: 115.68.231.57"로 바뀜(2026-10-27 19:03 KST). 이후 서버에서는 추가 요청을 하지 않았다.
- 서버는 10-25부터 프록시 없이 직접 접속 중이라 IP 단위 제한에 노출되어 있다. 정기 스캔·순위 측정·카나리에 영향이 갈 수 있으므로 해제 여부를 확인해야 한다.
- 교훈: **페이지 구조 확인은 로컬 Playwright로**(차단 없이 동작), 서버에서는 최소 횟수만.

### 아직 검증하지 못한 것
- **소식 탭이 없는 가게(어니언·하라식당)의 서버 측 결과**: 차단 때문에 확인 불가. 서버의 `/feed`가 홈으로 이동하는지(`no_tab`) 아니면 빈 화면인지(`unmeasured`)는 미확인. 로컬 브라우저에서는 `/place/{id}/feed`가 `/home`으로 이동함. 이 가게들의 소식 항목은 지금 `unmeasured`로 남을 수 있다.

## 8. 선행 수정 2단계 결과 — 사진·메뉴 (2026-10-27)

### 수정·배포한 것
- **D2 사진**: ① 점검 화면 항목에 `measured`를 도입(`services/smartplace_items.py`) — 사진을 못 읽으면 `passed=None`으로 내려 화면이 빨간 "개선 필요" 대신 회색 **"확인 전 · 직접 확인하기"**로 보여주고, 사실이 아닌 "0장 등록됨" 문구가 사라짐. 점수(`total_score/max_score`)는 측정된 항목만 계산. ② 쉼표만 매칭돼 `int('')` 오류로 사진 측정이 건너뛰어지던 정규식 수정(`naver_place_stats`, `smart_place_auto_check`, 공용 `place_page_signals.parse_photo_total`).
- **D3 메뉴**: 본문 어디든 "메뉴"가 있으면 통과하던 판정을 **단독 줄 근거**(`메뉴`·`메뉴16`·`가격표`)로 교체. 2026-10-27 로컬 브라우저 실측 — 어니언 `메뉴`·`메뉴16`, 홍스튜디오·힐링하우스 `가격표`(메뉴 탭 없음), 작곡교습소 근거 없음. **근거를 못 찾으면 "없음"이 아니라 "확인 안 됨"(`menu_measured=False`)** — 업종마다 라벨이 달라 못 본 것일 수 있다. `/menu` 탭이 홈으로 이동하는 경우(메뉴 탭 없는 가게)도 주소로 구분.

## 2. 확인된 결함과 수정 (모두 실행·실호출로 확인)
1. **잘못 묶인 업종 팁** — 세무·회계·부동산·건축이 변호사 체크리스트("승소 결과 게시"), 피부관리실·안경원이 의원 체크리스트("건강보험·비급여"), 네일·마사지·스파·찜질방이 미용실 팁("염색·펌·두피"), 어린이집·스터디카페가 학원 "합격·성과 사례" 팁을 받음 → `routers/schema_gen.py TIPS_ALIAS`(모듈 상수로 승격) 분리, 새 그룹 8개(`beauty_care`·`relax`·`professional_service`·`childcare`·`study`·`bakery`·`laundry`·`optics`), `music_studio` 팁 없음 해소. 데이터는 `services/category_tips_data.py`로 분리·재작성.
2. **플랫폼 효과 단정 25건** — "노출 조건입니다/우선 노출됩니다/노출됩니다" 등(네이버·AI가 공개하지 않은 기준) → 확인 가능한 이유("고객이 확인하는 정보")로 교체, 금지 문구 테스트.
3. **업종 규칙 조회 결함** — 기타·미등록 업종이 음식점 규칙을 받음(`normalize_category("other")=="restaurant"`), education·tutoring·music_studio 전용 규칙과 bar 전용 규칙이 도달 불가였음 → `get_industry_rules` 수정(기존 업종 결과 불변을 테스트로 고정).
4. **의료·법률 광고 규정 가드** (`services/regulated_industry.py`) — 해당 업종이면 생성 프롬프트에 금지 표현 지침, 결과에서 확실한 금지 유형 문장 제거(Q&A는 쌍으로, 다 지워지면 표시·대체). **다른 업종은 입출력이 한 글자도 바뀌지 않음**(테스트). 적용 경로: 소개글·블로그 초안·FAQ·네이버 소개글·글로벌 소개글·톡톡 메뉴·개선 가이드 시스템 프롬프트·리뷰 답글·위기 대응·주간 소식 초안.
5. **블로그 초안 3번째(리뷰_모음)** — 서버 실호출에서 치과·법률사무소 모두 업체가 직접 쓴 "방문 후기" 글을 생성 → 의료·법률은 "방문 전 안내" 형식으로 전환(템플릿 키는 프론트 탭 키라 유지), LLM 실패 대체 템플릿도 동일. 응답에 `regulated_industry` 플래그(생성 시점 판정)를 실어 프론트가 탭 라벨·경고 문구를 바꿈(드롭다운 값은 생성 후 바뀔 수 있어 사용하지 않음).
6. **금지 유형 키워드·문구 제거** — "승소율 높음"(사용자가 고르는 추천 태그·키워드 사전), "승소 사례"(비위치 키워드·체크리스트·DualTrackCard·채널 가이드), "치료 사례" 사진, 의료 FAQ 예시의 "대부분의 진료에 건강보험이 적용됩니다"(지어낸 사실), 의료 리뷰 요청 문구의 "치료 효과".
7. **리뷰 답글·위기 대응(의료·법률)** — 진료·상담·사건 내용(시술 종류·사건 유형 포함)을 공개 답글에서 되풀이하지 않게 하는 지침(기존 "리뷰 내용을 반드시 반영" 조건보다 우선). **법적 근거는 확인하지 못한 보수적 제품 선택**이다. 서버 실호출: 첫 지침은 법률 답글이 "이혼 소송 상담"을 되풀이 → 예시를 명시해 보강, 재호출에서 해소.
8. **주간 소식 초안** — 업종 변환표가 8개뿐이라 나머지 업종은 `massage`·`dental` 같은 영문 코드가 프롬프트에 들어가던 것을 전 업종 한글명으로.

3. **`DUAL_TRACK_RATIO`에 bakery·nail이 없어 기본 60/40 사용**(cleaning·fashion은 의도적이라고 주석에 있음, bakery·nail은 사유 없음). 점수 변화가 생기므로 별도 결정.

## 7. 교훈 (같은 실수 방지)
- **변이 검증 도구가 같은 크기로 바꾸면 `.pyc`가 낡은 채 쓰인다**(`"optics"`→`"clinic"`처럼 글자 수가 같고 같은 초에 되돌리면 캐시가 안 바뀜) — 변이 실행마다 `__pycache__`를 지울 것. 실패를 제품 결함으로 오판할 뻔했다.
- **통과한 테스트도 변이로 확인**: 구조 테스트가 "문자열이 한 번이라도 있으면 통과"여서 두 사용처 중 하나를 되돌려도 못 잡는 경우가 3번 나왔다(`result?.regulated_industry` 2곳, `cat_ko` 대입문, Q→A 쌍 방향) — 개수·대입문 전체를 요구하도록 강화.
- **실호출이 새 문제를 보여줬다**: 프롬프트를 고쳤는데도 "방문 후기" 글(템플릿 자체가 후기 형식을 지시)과 법률 답글의 "이혼 소송 상담" 되풀이는 실제 LLM 출력으로만 드러났다. 프롬프트 변경은 실출력으로 확인하고, 지침은 모호하면 지켜지지 않으니 예시를 넣는다.
- 배포 스크립트는 **커밋 전에** 서버 기준선(md5)을 확인해야 한다 — 커밋 후엔 `HEAD`가 새 버전이 되어 "서버만 다름"으로 중단되고 `--force`가 필요해진다(이번에 커밋 전 md5 일치를 확인한 뒤 사용).

# 키워드 "누락" 표시 전수 조사 (2026-10-27)

> 목적: 업종 표준 키워드 "누락/없음/부족" 목록을 사실처럼 보여 주는 모든 화면·메일·공유 문구를 찾아 출처별로 분류한다. **조사만 했고 코드는 바꾸지 않았다.** 상위 문서: `docs/popular_shop_trust_cases_2026_10_27.md` §5.

## 2. 출처 4종

- **S1 스캔 표준 목록 갭** (`scan_results.top_missing_keywords`): 거의 모든 가게가 "누락". 가장 약한 근거.
- **S2 경쟁사 비교 갭** (`gap_analyzer` competitor_only): 경쟁사 쪽은 실측 텍스트, "내 가게에 없음" 쪽은 S1과 같은 빈약한 텍스트.
- **S3 블로그 진단** (`blog_analyzer`): 내 블로그 실제 글 본문 기준 — 근거 충분, 의미가 다름("블로그 글에서 확인 안 됨").
- **S4 체험 갭** (`trial_scan`): 입력 키워드+블로그 제목 기준. 결과는 0 또는 8뿐.

## 4. 제안 원칙 (일괄 적용용)
- **R1** 상태·미션·카드 제목·알림·이메일 제목·공유 문구에는 쓰지 않는다. "없다/누락/미적용/미등록/경쟁 가게가 쓰는" 같은 단정 금지.
- **R2** 쓸 때는 "참고: 업종에서 자주 쓰는 키워드 — 우리 가게에 해당하는 것만 고르세요" 선택 도구 형태로만(✕ 제외 UI 유지).
- **R3** 빈 목록·0을 긍정("이미 갖춰져 있습니다", "노출 양호")으로 쓰지 않는다 — 계산 안 됨과 구분 불가.
- **R4** S2·S3는 출처를 문구에 명시("경쟁 가게 글에는 나오지만 내 블로그 글에서는 확인되지 않음"), 내 쪽 텍스트 근거가 비면 숨긴다.

## 5. 결정이 필요한 것
1. 점수 입력(`kw_gap*0.3`)도 같은 약한 근거다 — 점수에서 빼거나 가중치를 낮출지(인기 가게 감점 요인, 어니언 기준 소폭).
2. 체험 이메일 제목 변경은 이미 발송되는 문구라 영향 확인 필요.
3. H4의 `keyword_gap_score` 할 일을 어떤 문구로 대체할지(또는 삭제).

## 6. 확인하지 못한 것
- M3 온보딩 문구가 실데이터인지, L2 예시 표기 여부, `MissingKeywordBadges` 제목 문구.
- 체험의 0개 204건이 "계산 실패"인지 "해당 업종 표준 없음"인지(구분 불가).
- 이메일·알림톡 본문 전체(제목만 확인).

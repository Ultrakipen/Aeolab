## 0. 먼저 읽을 것 (결론)

1. **"이 기능이 최적의 상업 서비스 계획이다"를 입증하지 못했다.** 사장님 수요를 직접 보여주는 자료를 찾지 못했고(§1-2), 문구 생성만으로는 차별성이 약하다(§3). 따라서 본 문서의 판정은 **"조건부 — 수요 입증 없이 만들어 보는 소규모 실험이며, 개발은 네이버 차단 신호가 나타난 뒤(§10-1)에 시작하고 폐기 기준(§8-3)을 둔다"**이다. (11-04 지시로 인터뷰 조건은 삭제됨)
2. **개발 전에 먼저 처리해야 할 기존 결함 의심 1건**을 발견했다. 기존 소식 초안 코드가 사장님 입력 없이 "네이버 예약으로 원하는 시간 직접 선택 가능" 등을 고정 문구로 넣는다(§2). 지침 7번(사실 지어내기 금지) 위반 의심이며, 신규 기능보다 먼저 판단할 사항이다.
3. 신규 기능의 최소 형태는 **"사장님이 입력한 이번 주 사실 → 채널별(스마트플레이스·카카오 채널·당근) 복사용 초안"**이다. 자동 발송·자동 게시는 하지 않는다(§4-2, §6).
4. 가입 유도 효과는 **약하다**. 이 기능은 가입 후 가치(유지)에 가깝고, 신규 가입 유인으로는 근거가 없다(§5).

## 2. 선행 발견 — 기존 소식 초안의 사실 지어내기 의심

**근거(직접 확인):** `briefing_engine.py`의 소식·카페글 템플릿이 사업장 입력 없이 다음 문구를 고정 삽입한다.
- `:968` "📌 네이버 예약으로 원하는 시간 직접 선택 가능"
- `:969` "📞 전화·카카오톡 문의도 언제든지 환영합니다"
- `:1001` "방문 전 네이버 예약으로 원하는 시간에 편하게 오실 수 있습니다."
- `:1157-1161` "· 네이버 예약으로 원하는 시간 직접 선택 가능 / · 방문 전 전화·카카오톡 문의 환영 / … 네이버 예약으로 간편하게 방문 예약하세요."
- `:1490` "네이버 예약으로 간편하게 방문하실 수 있습니다."

**반증 시도:** ① `briefing_engine.py` 안에 예약 보유 여부로 문구를 거르는 조건이 없다(`booking` 검색에 이 파일 결과 없음). ② 다른 모듈(`smart_place_auto_check.py:436`, `naver_place_stats.py:373`)이 예약 버튼을 감지하지만 이 템플릿이 그 값을 쓰는 코드는 찾지 못했다.

**판정(11-04 갱신): 게이팅 부재 확인 + 화면 도달 경로 코드로 확인.** 경로: `:1254`→`:1266 ready_content`→`report.py:2165 copy_text`(`post_global` 팁, ChatGPT·구글 미노출일 때 생성)→`ConversionGuideSection.tsx:177` 복사용 텍스트. Basic 이상(`report.py:1924 is_paid`)은 전문이 보이고 무료는 흐림 처리(`:2168 locked`). 예약 기능이 없는 가게가 게시하면 허위 안내가 된다.
- **여전히 미확인:** 라이브 화면에서 실제로 뜨는 빈도, 해당 팁이 `tips[:4]` 절단(`:2172`)에 걸려 빠지는 경우의 비율. 따라서 P0/P1 등급은 단정하지 않고 "지침 7번 위반 경로 확인됨"까지만 말한다.

**권고:** 이 고정 문구를 "예약 확인된 경우만" 또는 플레이스홀더로 바꾸는 소규모 수정(D-1). 11-04 개발 보류 지시로 미착수.

## 3. 차별성 평가 (솔직한 판단)

| 대체재 | 겹치는 부분 | 판단 |
|---|---|---|
| 카카오 비즈센터 AI 문구 생성 | 카카오 채널 메시지 문구 | 무료·공식 기능이 있어 **문구 생성만으로는 차별 불가** [2차] |
| ChatGPT·Gemini 직접 사용 | 모든 채널 문구 | 무료. 크몽 프롬프트 묶음까지 판매 중 |
| 네이버 AI 후기 관리 | 리뷰 답변(이 기능 범위 아님) | 소식과 직접 겹치지 않음 |

따라서 가치가 있다면 **문구 품질이 아니라 아래 3가지**여야 한다. 모두 가설이다.
1. **사실 고정(fact-lock):** 사장님이 확인한 사실만 쓰고 지어내기를 기계적으로 막는다. 범용 AI와 다른 점.
2. **한 번 입력 → 채널별 변환:** 스마트플레이스·카카오·당근 형식 차이(길이, 어조, 해시태그)를 한 번에 맞춘다.
3. **무엇을 언제 올릴지 알려주는 주기 안내:** 사장님이 가장 막히는 "오늘 뭘 올리지?"에 대한 답.

이 3가지가 실제로 사장님에게 의미 있는지는 외부 자료로 확인할 수 없고, 구현 후 제품 내 행동 로그(§8-3)로만 방향을 볼 수 있다.

## 4. 기능 설계 (독립 기능, MVP 한정)

### 4-1. 사용자 흐름
1. 사장님이 **이번 주 알릴 사실**을 고른다: 신메뉴·휴무·이벤트·시즌 인사·자유 입력(최대 3개). 각 항목은 사장님이 직접 쓴 값이다.
2. (선택) **고정 정보**: 영업시간, 예약 방식(네이버 예약/전화/카카오톡/없음) 중 사장님이 확인한 것만 체크. 체크하지 않은 항목은 초안에 쓰지 않는다.
3. AI가 **채널별 초안**을 만든다: **MVP는 스마트플레이스 소식 / 카카오 채널 메시지 2채널**(D-3 판단). 당근 소식·인스타 캡션은 후순위(당근은 공개 API·정책 미확인이라 복사용 초안만 가능).
4. 각 초안에 **복사 버튼**. 게시와 발송은 사장님이 직접 한다.
5. 확인되지 않은 정보가 필요한 자리는 `[ ]` 플레이스홀더와 경고로 남긴다.

### 4-2. 하지 않는 것 (설계상 제외)
- **자동 발송·자동 게시:** 카카오 브랜드 메시지 조건(친구 수 등)과 딜러사 계약이 필요하고 [2차], 당근은 공개 API를 찾지 못했다 [미확인]. 고객 연락처를 AEOlab이 받지 않는다(개인정보 부담 회피).
- **쿠폰·할인·혜택 문구 생성:** 사장님 입력이 없으면 만들지 않는다. 기존 리뷰 답변 프롬프트가 이미 쿠폰·혜택을 금지한다(`guide.py:388`). 리뷰 대가 제공과 엮이지 않도록 분리한다.
- **점수 연결·효과 단정:** 이 기능은 AI Visibility 점수에 반영하지 않는다. "소식을 올리면 노출이 늘어난다"는 문구 금지(E9 미확인).

### 4-3. 사실 지어내기 방지 (필수 요건)
- 프롬프트: 입력에 없는 가격·시간·혜택·시설·예약 수단·수상·운영 기간을 쓰지 않도록 지시.
- **코드 후처리 검사:** 출력의 숫자·금액·"예약"·"무료"·"할인" 등이 입력 사실에 없으면 해당 초안을 차단하거나 플레이스홀더로 치환. 프롬프트 지시만 믿지 않는다(이 서비스에서 3회 재발한 패턴).
- 테스트: 빈 입력·모순 입력·예약 없음 입력으로 변이 검증(후처리를 빼면 실패하는지).

### 4-4. 광고 관련 안내 (법적 확인 전제)
카카오 채널 메시지 초안 옆에 **체크리스트**를 둔다: "(광고) 표기", "무료 수신거부 방법", "야간(21~08시) 발송 주의". 이는 안내이며 법률 자문이 아니다. 조문 원문과 친구톡 적용 범위는 확인 전(E1~E2)이라 **문구 확정 전에 법률 확인이 필요**하다.

### 4-5. AI·비용
- 모델: 기존 패턴대로 Claude Haiku 4.5(`claude-haiku-4-5-20251001`, 단가 $1/1M in·$5/1M out — CLAUDE.md 표 기준).
- 1회(3채널 초안) 추정: 입력 약 1,500토큰·출력 약 1,000토큰 → 약 $0.0065. 환율 1,450원 가정 시 약 10원. **[추정 — 실측 전, 환율은 가정]**
- 사용 로그는 기존 `ai_usage_logger`로 계측한다.

## 8. 수요 검증 — 인터뷰 제외 방식 (2026-11-04 사용자 지시: 인터뷰 없이 외부 조사·판단으로 진행)

### 8-1. 추가 외부 조사 결과 (11-04)
- 소상공인 실태조사(2024, 중기부·소진공 보도): 디지털 기술 활용 18.0→27.2%, 온라인 판로 7.6→13.3%, 72.8%는 미활용 (datasom.co.kr 보도 인용, 원문 보고서 미열람). → 디지털 도구 사용 자체가 아직 소수. 도구 수요보다 **사용 장벽**이 핵심 위험.
- "온라인 마케팅 이용 67.3%·성과 체감 28.4%"는 마케팅 업체 블로그의 2차 인용이라 **채택하지 않음**(미확인).
- "신규 확보비는 유지비의 5배"는 출처 불명 속설(범위 5~25배로 제각각). Bain은 유지 시 수익성 5~7배라 하나 이는 다른 주장. **근거로 쓰지 않음**.
- 국내 소상공인 단골 매출 비중·재방문 통계, 사장님의 SNS 소식 작성 시간 부족을 직접 보인 공식 조사: **찾지 못함** (표준 검색 2회 + 확장 검색 1회).
- 법령: 제50조 사전 동의·수신거부 후 전송 금지는 2차 해설에서 재확인. **야간(21~08시) 조항은 이번에도 원문 미확인.** 이 기능은 자동 발송이 없으므로 MVP에는 직접 적용되지 않으나, 사장님이 보낼 문구에 "(광고)" 안내를 붙이는 체크리스트는 유지.

### 8-2. 결론: 외부 자료만으로 수요는 입증되지 않는다
인터뷰를 뺀 이상 "필요하다"는 단정은 불가능하다. 따라서 판단 방식을 **수요를 먼저 증명**하는 구조에서 **싸게 만들어 보고 제품 내 행동 로그로 폐기 여부를 정하는 구조**로 바꾼다. 근거: 초안 1건 비용 약 10원(추정), 신규 인프라·네이버 접속·알림톡 없음, 기존 `post_draft` 저장소 재사용 → 실패해도 손실이 작고 되돌리기 쉽다.

### 8-3. 폐기 기준 (제안값 — 근거 데이터 없음, 첫 4주 뒤 재조정)
측정은 사장님 입력이 아니라 **제품이 기록하는 사실**만 쓴다: ①초안 생성 횟수 ②복사 버튼 클릭 수 ③생성 후 편집 여부 ④"사실 확인 필요" 경고 발생 수.
- 유료 사업장 중 월 1회 이상 생성: 활성 유료 사업장의 30% 미만이면 노출 위치 변경 1회 후 재측정, 그래도 미만이면 폐기.
- 복사율(생성 대비 복사 클릭): 20% 미만이면 문구 품질 문제로 보고 프롬프트 재설계, 개선 없으면 폐기.
- 모수가 작다(유료 4곳 내외): **판정은 숫자 임계가 아니라 방향 확인**으로만 사용. 통계적 결론 금지.
- 한계: ①복사·편집 이벤트 기록은 **새로 구현해야 하는 로깅**이라 구현 전에는 데이터가 없다. ②"복사"는 실제 게시를 뜻하지 않는다(복사 후 미게시 가능). ③차단이 길어져 구독자 구성이 바뀌면 비교 기준이 흔들린다. ④개인 식별 정보 없이 사업장 단위 집계만 쓴다.

- **주의(논리 점검)**: 차단은 *측정* 기능을 막고, 이 기능은 *게시 초안*이라 차단 상황에서 새로 가치를 만드는 것은 아니다. 차단 시 이탈을 줄이는 **대체 가치**로 쓰는 것이며, 차단 자체의 해결책이 아니다. 이 한계를 구현 판단 시 전제로 둔다.

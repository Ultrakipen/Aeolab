## §2. 점검 관점 (전문가 분야별)

### §2.1 정보 설계 전문가 (Information Architecture)
- 각 페이지의 섹션 순서가 사용자 의사결정 흐름에 맞는지
- 중복 정보가 여러 섹션에 반복되지 않는지
- 핵심 정보가 스크롤 없이 화면에 보이는지 (above the fold)
- 각 페이지의 목적이 1개로 명확한지 (페이지 = 1 goal)

### §2.2 UX 디자이너 (User Experience)
- 전환 깔때기: 방문 → 체험 → 가입 → 구독 흐름이 자연스러운지
- CTA(행동 유도 버튼)가 몇 개인지, 위치는 적절한지
- 빈 상태(empty state) 처리: 데이터 없을 때 안내 문구 존재 여부
- 오류 상태(error state) 처리: API 실패 시 사용자에게 적절한 피드백
- 로딩 상태: 스캔 중 진행 표시가 명확한지
- 폼 유효성 검증: 필수 입력 누락 시 적절한 안내

### §2.3 UI 디자이너 (Visual Design)
- **색상 일관성**: 같은 역할의 요소에 같은 색상 사용 여부
  - 주 CTA: blue-600 일관 사용 여부
  - 성공/긍정: green-500~600 계열 일관 여부
  - 경고: amber/yellow 계열 일관 여부
  - 위험/부재: red-500 계열 일관 여부
  - 비활성/잠금: slate/gray 계열 일관 여부
- **카드 테두리**: border-gray-200 / border-slate-200 / border-blue-200 혼재 여부
- **배경색 리듬**: 연속 섹션의 배경색 단조로움 또는 과도한 혼재
- **그림자 일관성**: shadow-sm / shadow-md 사용 기준이 있는지
- **아이콘 크기**: w-4(소) / w-5(중) / w-6(대) 사용 기준이 있는지
- **간격 일관성**: mb-4 / mb-6 / space-y-3 혼재 패턴

### §2.4 타이포그래피 전문가 (Typography)
- **텍스트 계층 구조**:
  - 페이지 제목: text-2xl md:text-3xl font-black 이상
  - 섹션 제목: text-xl md:text-2xl font-bold 이상
  - 카드 제목: text-base md:text-lg font-bold
  - 본문: text-sm md:text-base
  - 보조 설명: text-sm text-gray-500
  - 최소 크기: text-xs 사용 금지 (중요 정보)
- **줄 간격**: leading-relaxed / leading-snug 적절 사용 여부
- **한국어 줄바꿈**: break-keep 누락 여부 (단어 중간에서 줄바꿈 발생)
- **가독성**: 배경색 대비 텍스트 색상 (WCAG AA 기준 4.5:1 이상)
- **폰트 굵기**: font-semibold와 font-bold 구분 기준

### §2.5 반응형 디자인 전문가 (Responsive Design)
- **모바일(375px)** 기준 점검:
  - 텍스트가 잘리거나 overflow 발생 여부
  - 버튼 터치 영역 최소 44px 이상 여부
  - 그리드가 1열로 자연스럽게 변환되는지 (grid-cols-2 → 1)
  - 고정 요소(sticky/fixed)가 콘텐츠를 가리지 않는지
  - safe-area-inset-bottom 적용 여부 (iOS 홈바 영역)
- **태블릿(768px)** 기준 점검:
  - 2열 레이아웃이 자연스럽게 전환되는지
- **PC(1280px+)** 기준 점검:
  - max-w 제한이 없어 과도하게 늘어나는 요소 없는지
  - 양쪽 패딩이 화면 크기에 맞게 조정되는지

### §2.6 전환율 최적화 전문가 (CRO)
- **각 페이지의 CTA 버튼 개수**: 1페이지 = 1 primary CTA 원칙 준수 여부
- **사회적 증거**: 후기·사용자 수·통계 데이터가 적절히 배치됐는지
- **긴급성/희소성 요소**: 할인 만료, 제한 수량 등 존재 여부
- **가격 앵커링**: 요금제 페이지에서 비교 기준이 명확한지
- **손실 회피 문구**: 체험 결과 저장 유도, 7일 후 삭제 등
- **신뢰 신호**: 보안 배지, 해지 보장, 데이터 삭제 정책 명시 여부

### §2.7 접근성 전문가 (Accessibility)
- **alt 텍스트**: 모든 이미지에 적절한 alt 속성
- **aria-label**: 아이콘만 있는 버튼에 aria-label 존재 여부
- **키보드 네비게이션**: Tab 키로 모든 인터랙티브 요소 접근 가능한지
- **색상 대비**: 텍스트 색상과 배경색 대비 WCAG AA 기준 충족
- **포커스 표시**: 포커스 시 시각적 표시(ring) 존재 여부
- **폼 레이블**: 모든 입력 필드에 연결된 레이블 존재 여부

### §2.8 콘텐츠 전문가 (Content Strategy)
- **헤드카피 설득력**: 각 페이지 첫 문장이 사용자 문제를 정확히 표현하는지
- **마이크로카피**: 버튼 텍스트, 플레이스홀더, 에러 메시지가 자연스러운지
- **면책 문구 일관성**: AI 측정 한계, 추정값 표시 등 모든 곳에 적용됐는지
- **용어 일관성**: "소개글 Q&A", "톡톡 채팅방 메뉴", "AI 브리핑" 등 전 페이지 통일
- **금지 표현 점검**: "직접 인용" 등 단정 표현 사용 여부
- **정보 사실성**: 임의 더미 수치, 계산 근거 없는 추정 점수 없는지

### §2.9 소상공인 언어 전문가 (Plain Language for Small Business Owners)

> AEOlab의 핵심 사용자는 디지털 마케팅에 익숙하지 않은 40~60대 소상공인입니다.  
> IT·AI 용어를 그대로 노출하면 이탈합니다. 이 관점에서 전 페이지를 점검합니다.

**기술 용어 → 생활 언어 변환 여부**

| 기술 용어 (점검 대상) | 소상공인이 이해하는 표현 (권장) |
|---------------------|-------------------------------|
| AI 노출 점수 | "AI가 내 가게를 얼마나 알고 있는지" |
| 트랙1 (네이버) / 트랙2 (글로벌) | "네이버에서 찾히는 정도" / "ChatGPT에서 찾히는 정도" |
| 듀얼트랙 모델 | 사용자에게 노출 금지 — 내부 용어 |
| 키워드 갭 분석 | "경쟁 가게가 쓰는 단어 중 내 가게에 없는 것" |
| AI 브리핑 인용 후보 | "AI 답변에 내 가게가 나올 수 있는 상태" |
| 스마트플레이스 완성도 | "네이버 지도 내 가게 정보 완성 정도" |
| 노출 확률 (%) | "100번 물어보면 몇 번 내 가게가 나오는지" |
| exposure_freq | 절대 노출 금지 — 내부 변수명 |
| Track1 / Track2 | 절대 노출 금지 — 내부 용어 |
| Gemini 50회 샘플링 | "ChatGPT·AI에 50번 물어봐서 확인" |
| C-rank 알고리즘 | "네이버가 가게를 평가하는 방식 (비공개)" |
| JSON-LD 스키마 | 사용자에게 노출 금지 |
| SSE 진행률 | 사용자에게 노출 금지 |

**점검 항목**

- [ ] **영어 약어 단독 사용 금지**: "AI", "SEO", "CTA", "API" 등이 한국어 설명 없이 단독 노출되는지
- [ ] **숫자 단위 설명**: 점수 "72점"이 무엇을 의미하는지 한 줄 설명이 붙어 있는지
- [ ] **행동 지침의 구체성**: "개선하세요"가 아니라 "스마트플레이스 → 업체정보 → 소개글에서 수정하세요"처럼 경로가 명시됐는지
- [ ] **결과 해석 도움**: 점수가 높으면/낮으면 실제로 어떤 상황인지 생활 언어로 설명됐는지
- [ ] **업종별 언어**: 음식점엔 "메뉴", 학원엔 "수업", 헬스장엔 "프로그램" 등 업종 맞춤 단어 사용 여부
- [ ] **공포 자극 vs 희망 제시 균형**: 낮은 점수를 보여줄 때 두려움만 주지 않고 "이렇게 하면 됩니다" 해결책이 함께 있는지
- [ ] **전문 용어 툴팁**: 불가피하게 전문 용어 사용 시 물음표 아이콘이나 괄호 설명이 있는지
- [ ] **가격 표현**: "9,900원/월"이 부담스럽지 않도록 "하루 330원" 등 단위 환산 표현이 있는지
- [ ] **성공 사례 언어**: "AI 노출 확률 23% 증가"보다 "매주 평균 3명 더 찾아왔습니다" 형태가 더 설득적인지 검토
- [ ] **버튼 텍스트 명확성**: "확인", "제출" → "내 가게 AI 점수 확인하기", "결과 저장하기" 처럼 행동 결과가 명시됐는지
- [ ] **에러 메시지 친절성**: 기술적 오류 메시지("500 Internal Server Error" 등)가 사용자에게 노출되지 않는지
- [ ] **빈 상태 안내**: 데이터 없을 때 "데이터 없음" 대신 "아직 스캔을 하지 않으셨네요. 지금 시작해보세요" 형태인지

## §3. 페이지별 세부 점검 항목

### §3.1 홈(랜딩) 페이지 `/`
점검 파일: `app/page.tsx` + `components/landing/` 전체

- [ ] 헤드라인이 소상공인 관점에서 즉시 이해되는지
- [ ] 히어로 섹션 CTA가 1개로 명확한지 (무료 체험 시작)
- [ ] 업종 타일(HeroIndustryTiles)이 모바일에서 잘리지 않는지
- [ ] 서비스 동작 원리 섹션 링크(/how-it-works) 연결 여부
- [ ] 요금제 프리뷰 가격이 `lib/plans.ts` 단일 소스와 일치하는지
- [ ] FAQ 섹션의 질문이 실제 사용자 의문을 해소하는지
- [ ] 베타 후기가 실데이터인지 placeholder인지 명확히 표시됐는지
- [ ] 모바일 floating CTA가 /trial 이외 페이지에서만 노출되는지
- [ ] 헤더 네비게이션 메뉴가 모바일에서 햄버거로 잘 접히는지

### §3.2 무료 체험 페이지 `/trial`
점검 파일: `app/(public)/trial/` 전체 + `components/trial/` 전체

**입력 단계 (TrialInputStep)**
- [ ] 필수 입력 필드가 명확히 표시되는지
- [ ] 업종 선택 UX가 직관적인지
- [ ] 가게 이름 입력 후 네이버 검색 결과가 잘 연동되는지
- [ ] 모바일에서 키보드 올라올 때 버튼이 가려지지 않는지

**스캔 단계 (TrialScanningStep)**
- [ ] 진행 표시가 사용자에게 충분한 피드백을 주는지
- [ ] 예상 소요 시간이 표시되는지
- [ ] 스캔 실패 시 에러 안내가 명확한지

**결과 단계 (TrialResultStep)**
- [ ] 섹션 순서가 진단→행동→전환 흐름인지
- [ ] 총점 카드 가독성 (숫자 크기, 색상 대비)
- [ ] 성장단계 배지 + 이번 주 액션이 표시되는지
- [ ] AI 브리핑 대상 배지(BriefingBadgeChip)가 배경 대비 잘 보이는지
- [ ] TodayOneAction 액션 카드가 모바일에서 overflow 없이 출력되는지
- [ ] ClaimGate가 아코디언(근거 확인) 이후에 위치하는지
- [ ] SubscriptionScreenshotPreview 블러 카드 2개가 정렬되는지
- [ ] SubscriptionValueCompare CTA 버튼이 1개인지
- [ ] 공유 버튼(카카오/텍스트)이 모바일에서 정상 동작하는지
- [ ] 재진단 버튼과 공유 섹션 사이 구분이 명확한지
- [ ] Sticky 배너가 콘텐츠를 가리지 않는지 (padding-bottom 보정)
- [ ] 면책 문구(ChatGPT 측정 한계) 표시 여부

### §3.3 데모 페이지 `/demo`
점검 파일: `app/(public)/demo/page.tsx`

- [ ] 업종/지역 선택 후 데이터가 즉시 업데이트되는지
- [ ] "이 결과는 데모 샘플입니다" 안내가 명확한지
- [ ] AI 측정 기준 "구독 기준(각 50회)" 레이블이 표시되는지
- [ ] aiExcerptFail 케이스(photo, music)에서 구독 기준 안내가 표시되는지
- [ ] 성장단계(growthStage) 카드의 focus_message + this_week_action이 출력되는지
- [ ] 잠금(locked) 섹션들이 블러/잠금 UI로 적절히 처리되는지
- [ ] 2컬럼 레이아웃이 모바일에서 1열로 자연스럽게 전환되는지
- [ ] 사이드바 고정(sticky)이 모바일에서 해제되는지
- [ ] 하단 CTA "내 가게 무료 진단하기" 버튼이 /trial로 연결되는지
- [ ] 이모지 아이콘 사용 여부 점검 (lockedTips에 이모지 다수 사용 중)
- [ ] 스마트플레이스 체크리스트 8개 항목의 근거 표시 여부

### §3.4 요금제 페이지 `/pricing`
점검 파일: `app/(public)/pricing/page.tsx`

- [ ] 요금 4가지(Basic/창업/Pro/Biz)가 `lib/plans.ts` 값과 일치하는지

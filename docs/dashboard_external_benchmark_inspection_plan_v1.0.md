## §1. 필수 참고 — 소상공인 사용자의 네이버 신뢰·민감도와 3대 우선순위 (2026-07-09 사용자 지시, 점검 진행 전 반드시 읽을 것)

> **이 절은 점검 방법론이 아니라 판정 기준 자체를 좌우하는 비즈니스 배경이다. §2~§5의 어떤 절차보다 먼저 읽어야 한다.**

### 1.1 배경 — 왜 네이버가 다른 채널과 다른 우선순위를 가지는가

- 이 서비스의 사용자는 **소상공인**이다.
- 소상공인은 **네이버를 거의 100% 신뢰**한다. "내 가게가 네이버에 어떻게 나오는가"는 소상공인에게 매우 민감하고 중요한 문제다 — 매출과 직결된다고 체감하기 때문.
- 이 신뢰·민감도가 실제로 얼마나 큰지 보여주는 방증: 많은 소상공인이 **블로그 포스팅·블로그 노출·스마트플레이스 개선**을 위해 실제 비용을 들여 **전문 대행업체에 의뢰**한다(`docs/agency_service_and_iboss_improvements_v1.0.md`의 대행 서비스 기획 배경과도 일치). 이는 AI 노출(ChatGPT·Gemini 등)보다 네이버 관련 개선을 훨씬 더 절실하게 여긴다는 실증적 근거다.

### 1.2 이로부터 도출되는 3대 원칙 — 대시보드 점검 시 반드시 검증할 것

1. **스캔 결과 화면에서 네이버 관련 정보가 최우선으로(가장 먼저) 나타나야 한다.**
   - 과거 이미 확인됨(§2-③ `project_dashboard_scan_ux_v1`): "네이버 최상단·글로벌 하단(접힘)"이 옳은 배치라고 결론남.
   - **이번 점검에서 재확인할 것**: 이 배치가 그 사이 코드 변경으로 흐트러지지 않았는지 라이브 화면에서 위→아래 순서를 직접 스크롤하며 재확인. "과거에 확인됐으니 됐다"고 문서만 보고 넘기지 말 것 — 이것이 §1.2의 항목 중 가장 회귀 위험이 큰 부분.

2. **"이 서비스가 제공하는 AI 노출 개선 방안이 네이버 SEO 검색 상위 노출로 이어진다"는 것을 화면에서 확실히 안내해야 한다.**
   - **이것이 허위 주장이 아닌 근거**: `score_engine.py`의 Track1 가중치(`NAVER_TRACK_WEIGHTS_V3_1`) 중 `keyword_search_rank`(ACTIVE 25%·LIKELY 30%·INACTIVE 35%, 가장 비중 큰 단일 항목)는 애초에 "AI 인용 여부"가 아니라 **Playwright로 실측한 네이버 검색 순위 그 자체**다. 즉 이 서비스의 개선 가이드를 따라 Track1 점수를 올리는 것은 논리적으로 곧 "네이버 일반 검색 순위 개선"과 상당 부분 같은 행위다 — 지어낸 인과관계가 아니라 점수 모델 설계 자체가 그렇게 돼 있다.
   - 관련 기존 포지셔닝 문구(이미 조사됨, `docs/ai_exposure_standard_and_naver_seo_v1.0.md` §6.3): "네이버 검색 기반이 강할수록 AI 브리핑·AI탭 노출도 함께 올라갑니다" — 이건 **반대 방향**(일반검색→AI노출) 프레이밍이다. 사용자가 이번에 요구한 것은 **정방향**(이 서비스의 AI노출 개선방안→네이버 SEO 상위노출 가능)이 대시보드 화면에 명확히 있는지다. **이 정방향 문구가 현재 대시보드에 실제로 존재하는지는 확인된 바 없음 — 이번 점검에서 처음 확인할 신규 항목.**
   - 반증 시도 필수: "이미 있을 것 같다"고 짐작하지 말고, 라이브 대시보드 텍스트를 실제로 덤프해서 이런 취지의 문구가 있는지 없는지 직접 확인할 것. 없다면 §5 종료 기준의 "확정된 문제"로 취급해 문구 추가를 검토.

3. **AI 도구별로 개선 후 노출 가능한 기간을 사실적으로 안내해야 한다.**
   - 이미 CLAUDE.md에 공식 확정된 채널별 기간 존재: 네이버 AI 브리핑·AI탭 2~4주(추정) / Gemini(Google Search grounding) 2~4주 내 반영 시작·안정적 인용까지 수개월 / ChatGPT 수개월~1년(학습데이터 기반, knowledge cutoff 공식 확인).
   - **이번 점검에서 확인할 것**: 이 기간 안내가 대시보드 화면(또는 대시보드에서 바로 연결되는 위치)에 실제로 노출되는지, 노출된다면 위 공식 수치와 정확히 일치하는지(오래된 수치로 박제돼 있지 않은지) 재확인. Gemini와 ChatGPT를 뭉뚱그려 표시하는 반복 버그 패턴(과거 여러 번 발생)이 재발하지 않았는지 특히 주의.

### 1.3 이 원칙과 §2(닫힌 이슈)의 관계 — 헷갈리지 말 것

- §1.2-①(네이버 최상단 배치)은 **과거에 검증된 것의 회귀 확인**이다 — §2-③에 이미 등재된 이슈이므로 새로 논쟁하지 말고 "여전히 맞는지"만 본다.
- §1.2-②(정방향 SEO 상위노출 인과관계 문구)와 §1.2-③(AI별 노출기간 안내)은 **이번에 처음 명시적으로 요구된 신규 확인 항목**이다 — §2의 "닫힌 이슈"에 해당하지 않으므로 재점검 금지 원칙이 적용되지 않는다. 즉 이 둘은 §3(외부벤치마크 4축)과 별개로 **반드시 확인**해야 하는 항목이며, "없다"고 판단되면 §5 종료 기준상 미해결 항목으로 남는다.
- **오판 방지**: "이미 조사된 문서(`ai_exposure_standard_and_naver_seo_v1.0.md`)에 비슷한 문구가 있다"는 이유로 "이미 다 되어있다"고 순환참조하지 말 것(CLAUDE.md "외부 사실 주장 검증" 원칙과 동일 — 문서 존재와 실제 화면 반영은 다른 문제). 라이브 화면 텍스트 덤프로 직접 확인해야 진짜 검증이다.

## §2. 대시보드가 다른 6개 페이지와 다른 점 — 왜 별도 계획이 필요한가

1. **압도적 규모** — 다른 6개 페이지는 대부분 단일 목적 페이지(폼 1개+결과 1종)였다. 대시보드는 2026-07-02 전수 점검 기준 **27개 이상의 컴포넌트**로 구성된 복합 화면(Hero, DualTrackCard, ChannelScoreCards, CompetitorTimeline, BriefingTimeline, GuidanceZone, InsightZone, AiTabPreviewCard 등). 한 번에 몰아서 점검하면 놓치는 부분이 생기기 쉽다 — **§5에서 구역별 분할 진행을 제안**.
2. **압도적으로 많은 과거 점검 이력** — 이 프로젝트에서 대시보드만큼 반복 점검당한 페이지가 없다. §3에서 전부 정리한다. **새 세션은 §3을 먼저 읽지 않고 점검을 시작하면 안 된다** — 이미 끝난 축을 재점검하거나(중복 작업), 이미 닫힌 논쟁을 다시 여는(무한 루프) 두 가지 함정이 모두 실제로 발생한 전례가 있다.
3. **편집 지뢰(landmine) 존재** — `frontend/app/(dashboard)/dashboard/DualTrackCard.tsx`는 **고아 파일**이고, 실제 렌더링되는 파일은 `frontend/components/dashboard/DualTrackCard.tsx`다. 두 파일 내용이 이미 갈라져 있다. **대시보드 관련 어떤 파일이든 수정 전에 반드시 `grep -rn "import.*DualTrackCard\|from.*<컴포넌트명>"`으로 실제 import 경로를 먼저 확인할 것** — 잘못된 파일을 고치고 "반영 안 됨" 사고가 날 수 있다.

## §4. 이번에 실제로 새로 할 것 — 외부벤치마크 4축 + 네이버 메시징 2건 (§3과 안 겹침)

`external_benchmark_commercial_quality_v1.0.md`의 §2-B 4축:

1. **성능(TTFB)** — 자체 기준선 역할이었던 페이지라(다른 6개 페이지 점검 때 항상 "vs `/dashboard`"로 비교) 이번엔 대시보드 자체를 다른 페이지와 비교할 대상이 마땅치 않음. 그냥 절대값 기록 + "vCPU2/RAM4GB 서버 전역 특성" 감안해서 판단.
2. **WCAG 2.1 AA** — 대비율(canvas 2D `fillStyle`+`getImageData`로 sRGB 강제 변환 후 계산, `text-gray-400`=2.60:1 실패/`text-gray-500`=4.83:1 통과 기준값 재사용) + `aria-expanded`(InsightZone의 네이버 순위표·AI탭·브리핑 카드가 이미 기본 접힘 상태로 구현돼 있음 — `feedback_dashboard_inspection_standard` §6 참조. 이 토글들에 `aria-expanded` 있는지 직접 확인 필요, 아이콘 스왑+회전 패턴 둘 다 체크)
3. **시각 위계** — 27개 컴포넌트가 한 화면에 있는 만큼 특히 중요한 축. 단, §3-①에서 이미 "결론→행동→상세" 순서가 검증된 상태이므로 완전히 새로 판단하기보다 **WCAG 관점에서만**(예: CTA 대비, 배지 색상 일관성) 추가로 볼 것 — 정보구조 관점은 §3-①과 중복이므로 재논쟁 금지.
4. **카피 톤** — 다른 6개 페이지와 톤이 일관되는지.

**신규 축(§1에서 도출, 6개 페이지 점검엔 없던 이 페이지만의 필수 항목)**:

5. **네이버 최상단 배치 회귀 확인** (§1.2-①, §3-③ 연동) — 라이브 스크롤로 위→아래 순서 직접 재확인.
6. **"AI 노출 개선→네이버 SEO 상위노출 가능" 정방향 메시징 존재 여부** (§1.2-②) — 라이브 텍스트 덤프로 직접 확인, 없으면 확정 문제로 기록.
7. **AI 채널별 노출기간 안내의 정확성** (§1.2-③) — 화면에 노출되는 기간 수치가 CLAUDE.md 공식 수치(네이버 2~4주·Gemini 2~4주/수개월·ChatGPT 수개월~1년)와 일치하는지, Gemini/ChatGPT 뭉뚱그림 재발 여부.

**사이트 전역 백로그 2건도 대시보드에서 마주칠 가능성 높음** — `HelpFAQFloat` 위젯(모든 페이지 공통)과 화살표/체크 불릿 아이콘 저대비 패턴. 대시보드에서 새로 발견해도 "이 페이지의 결함"으로 기록하지 말고 기존 사이트 전역 백로그에 합산할 것(`external_benchmark_commercial_quality_v1.0.md` §4).

## §5. 실행 순서 제안 — 구역별 분할

27개 컴포넌트를 한 번에 훑으면 놓치는 게 나온다. 다음 4개 구역으로 나눠 순서대로 진행할 것을 권장(각 구역 종료 시 §4의 4축+3항목 적용):

1. **Hero/점수 구역** — `DashboardHeroCard.tsx`, `components/dashboard/DualTrackCard.tsx`(⚠️ 고아 파일 아님, 이 경로가 진짜), `ChannelScoreCards` 계열, `DashboardEvidencePreview.tsx`. **§4-5(네이버 최상단 배치)·§4-6(SEO 상위노출 메시징)을 이 구역에서 우선 확인** — Hero가 화면 최상단이므로 이 두 항목이 실제로 걸리는 곳일 가능성이 가장 높음.
2. **InsightZone 구역** — 네이버 채널별 카드, AI탭(`AiTabPreviewCard.tsx`), 브리핑, 기본 접힘 토글들 — `aria-expanded` 집중 확인 구역. **§4-7(AI 채널별 노출기간 안내)도 이 구역에서 확인** — 채널별 카드가 모여있는 곳이라 기간 안내 문구가 있다면 여기 있을 가능성이 높음.
3. **GuidanceZone/오늘의 행동 구역** — "오늘 할 일" 카드, CTA 앵커(`#section-action`) 연결부
4. **하단 부가 구역** — 경쟁사·트렌드·기타 카드 (다른 페이지에서 이미 전용 페이지로 분리된 기능의 요약 위젯이 있다면 중복 여부만 가볍게 확인 — 새 기능 제안 금지, `feedback_improvement_proposal_verification` 원칙)

각 구역 종료 시 `docs/external_benchmark_commercial_quality_v1.0.md` §3에 결과 추가. 대시보드는 페이지가 1개뿐이므로 4개 구역 전부 끝나야 §3에 최종 1행으로 등재하고 §4(미점검 후보)에서 제거.

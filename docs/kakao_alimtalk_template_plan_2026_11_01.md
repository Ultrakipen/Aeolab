# 알림톡 템플릿 정리안 (2026-11-01)

목적: ①승인 템플릿을 원래 목적과 다른 알림에 쓰고 있는 곳의 위험을 정리하고 ②자유 문구라 지금 발송되지 않는 알림 9종을 "새 템플릿 등록 / 기존 템플릿 연결 / 알림톡에서 제외" 중 하나로 분류한다.
등록은 사용자가 비즈센터에서 한다. 규칙은 `docs/kakao_alimtalk_sending_rules_2026_10_31.md` 참조(변수는 이름만, 값 14자 이하, 승인 본문 변수를 모두 채움).

## 0. 현재 상태 (11-01 실측)
- 정기 잡의 알림톡이 처음으로 성공했다: 11-01 09:00 월간 리포트, 09:10 점수 변화·경쟁사 알림이 관리자 번호로 전달, `notifications`에 `sent`(수신자는 모두 관리자 번호 — **일반 사용자 발송은 아직 한 번도 확인되지 않음**).
- 성공률 점검 잡(10:00)은 "성공 22·실패 17 → 정상" 판정(시험 발송의 실패 기록 포함, 50% 미만).

## 1. 승인 템플릿을 다른 목적에 쓰고 있는 곳 (발신 프로필 제재 위험)
카카오는 승인된 목적과 다른 내용의 발송을 문제 삼을 수 있다. 전달은 되지만 **제재 가능성은 미확인**(실제 사례를 확인하지 못함). 아래는 위험이 큰 순서.

| 현재 코드 | 쓰는 템플릿 | 실제 내용 | 목적과의 거리 | 권장 |
|---|---|---|---|---|
| `send_post_remind` (소식 14일 미작성, `inactive_post_alert_job`) | `AEOLAB_ACTION_01` ("이달 할 일/정기 분석 결과") | "소식이 N일 올라오지 않았습니다" | 큼 | **끔(§1-1)** |
| 가입 7일차 안내 (`send_action_items(["추천 행동 확인"])`) | `AEOLAB_ACTION_01` | 가입 유도성 환기 | 큼 + 광고성 소지 | **발송 제거(§1-1)** |
| `send_first_exposure` (처음 AI에 노출) | `AEOLAB_CITE_01` ("AI 인용 실증") | 네이버 AI 브리핑 첫 노출 | 작음(AI 노출 확인이라는 점은 같음) | 유지 가능, 새 템플릿 **B**가 승인되면 이동 |
| `check_briefing_alert_job` 신규 등장/이탈 | `AEOLAB_SCAN_01` 코드로 자유 문구 | 노출 상태 변화 | 큼 (그리고 지금은 발송 안 됨) | 새 템플릿 **B** |
| `_detect_competitor_score_spike` | `AEOLAB_COMP_01` 코드로 자유 문구 | 경쟁사 AI 노출 상승 | 작음(경쟁사 변화) | 기존 `COMP_01` 변수 발송으로 연결(§3-①) |

미확인: ACTION_01·CITE_01의 **승인 본문 원문**. 위 "목적"은 CLAUDE.md의 기재(이달 할 일 / AI 인용 실증)에서 가져왔으므로 비즈센터에서 본문을 보고 대조할 것.

## 1-1. 결정·조치 (11-01, 사용자 승인)
소식 14일 미작성과 가입 7일차 안내는 사용자에게 꼭 필요한 정보성 알림이 아니라고 판단해 **알림톡에서 제외했다.**
- 소식 미작성: `last_post_at`이 측정값이 아니라 사용자 입력이고 활성 사업장 8곳 중 2곳만 값이 있다(서버 DB 실측). 값이 없으면 "14일 이상 미작성"으로 취급해 소식을 올리는 가게에도 "올라오지 않았습니다"가 나갈 수 있었다. `inactive_post_alert_job`은 `INACTIVE_POST_ALERT_ENABLED=true`일 때만 등록(기본 꺼짐). **새 템플릿 A는 등록하지 않는다.**
- 가입 7일차: `new_user_day7_rescan_job`의 카카오 발송만 제거. 재스캔과 앱 내 알림 기록(`day7_action`)은 유지.
- 테스트: `tests/test_non_essential_alerts_off.py`(변이 2종 검증).

## 1-2. 경쟁사 알림 정리 (11-01, 사용자 승인)
경쟁사 급등·신규 경쟁사를 COMP_01에 **연결하지 않고**, 이미 나가던 COMP_01의 결함을 고쳤다.
- 발견: 매일 보내는 경쟁사 변화 알림이 ①점수가 5점만 달라져도 발송 ②`순위변화`에 순위가 아니라 점수 증감 숫자를 넣음(점수 숫자 노출 금지 위반) ③값이 None이면 0으로 바꿔 "하락"으로 알림 ④주간 경로는 `순위변화`에 항상 0.
- 수정: `services/competitor_alert.py` — 같은 측정 방식·값이 있는 두 점수·등급 구간이 바뀌고 변화폭 10 이상일 때만, 폭이 가장 큰 1건을 **"AI 노출 상승/하락" 텍스트**로, 사업장당 7일에 1회, **전달 성공일 때만** 기록(`notifications.type=competitor_alert`). 주간 경로의 카카오 발송은 제거(앱 내 알림 유지). 서버 실데이터 기준 현재 발송 대상 0건.
- 급등 알림: `COMPETITOR_SPIKE_ALERT_ENABLED=true`일 때만 실행(기본 꺼짐). 신규 경쟁사: `NEW_COMPETITOR_ALERT_ENABLED=true`일 때만 등록(기본 꺼짐) — "새 사업장"이 아니라 검색 상위 15곳 중 미등록 업체였다.
- 변화폭 10·주 1회는 내 판단으로 정한 값(실사용자 데이터가 쌓이면 조정). COMP_01 승인 본문 원문과 대조는 미확인.
- 테스트: `tests/test_competitor_alert_rules.py`(변이 8종 검증, 처음엔 변화폭 기준 변이가 살아남아 등급 경계 근처 케이스를 추가).

## 3. 연결·등록 안

### ① 기존 COMP_01로 연결 (등록 불필요, 내가 구현 가능)
- 변수: 사업장명·경쟁사명·순위변화·확인일시. 모두 14자 이내로 맞춘다(`_short`). 관리자 번호 1건 시험 발송 후 연결.
- 급등: `순위변화`="AI 노출 상승"(구체 점수 숫자는 표시 금지 원칙). 신규 경쟁사: `순위변화`="신규 후보 N곳".
- 지침 8·9번 준수: 경쟁사 급등은 두 시점 모두 측정이 성공했을 때만, 신규 경쟁사는 발송 실패 시 이력을 남기지 않는다(이미 적용).

### ② 새 템플릿 등록 (사용자 몫) — 입력값은 `AEOLAB_CANCEL_02`와 동일 방식: 기본형 / 강조 없음 / 버튼 없음 / 보안 템플릿 미설정

**A. `AEOLAB_POSTREMIND_01` — 스마트플레이스 소식 업데이트 안내**
```
[AEOlab]
#{사업장명}의 스마트플레이스 소식이 #{경과일} 동안 올라오지 않았습니다.
새 소식이 있으시면 등록해 보세요.
```
- 변수: 사업장명, 경과일(예 "14일 이상", 14자 이내). 본문에 "노출이 늘어난다" 같은 효과 표현을 넣지 않는다.
- 검수 설명: "고객 사업장의 스마트플레이스 소식 등록 현황을 확인해 알려드리는 정보성 안내입니다. 서비스에 가입한 고객에게 14일에 1회 이하로 발송됩니다."

**B. `AEOLAB_BRIEFING_01` — 네이버 AI 브리핑 노출 상태 변경 안내**
```
[AEOlab]
#{사업장명}의 네이버 AI 브리핑 노출 상태가 바뀌었습니다.

변경 내용: #{변경내용}
확인일시: #{확인일시}
자세한 내용은 대시보드에서 확인하실 수 있습니다.
```
- 변수: 사업장명, 변경내용("새로 노출 확인" / "이번 측정에서 미확인"), 확인일시.
- 지침 9번: 이탈은 "빠졌습니다"가 아니라 **"이번 측정에서 확인되지 않았습니다"**로 표현하고, 측정 실패(네이버 차단·쿨다운)일 때는 보내지 않는다. 11-01 점검에서 현재 코드가 오늘·어제의 `mentioned` 값만 비교하고 측정 실패를 보지 않는 것을 발견해(차단된 날이 "이탈"로 나갈 수 있었음) `check_briefing_alert_job`에 `naver_result_unmeasured` 가드를 추가했다(`tests/test_briefing_alert_unmeasured_guard.py`, 변이 검증). 발송 경로가 막혀 있어 실제 오발송은 없었다.
- 검수 설명: "고객이 가입한 서비스에서 측정한 네이버 AI 브리핑 노출 상태가 이전과 달라졌을 때 알리는 정보성 안내입니다. 상태가 바뀐 경우에만 발송됩니다."

**C. `AEOLAB_POSTDRAFT_01` — 주간 소식 초안 준비 안내 (선택)**
```
[AEOlab]
#{사업장명}의 이번 주 소식 초안이 준비되었습니다.
대시보드의 개선 가이드에서 확인하실 수 있습니다.
```
- 변수: 사업장명. 초안은 사실을 지어내지 않도록 이미 가드되어 있다.

등록 후 코드 연결 순서: `TEMPLATES`에 코드 추가 → 승인 본문 변수 대조 → 관리자 번호 시험 발송 1건 → 호출부 교체 → 서버 테스트 → 배포 → 해당 잡 실제 로그 확인.

## 4. 긴 값이 필요한 알림 (정보량)
변수 값 14자 제한 때문에 인용 내용·시장 동향·이번 주 추천·할 일 목록은 짧은 대체 문구나 건수로 나간다. 정보량을 늘리려면 **본문에 문장을 고정으로 넣고 변수는 짧은 값만** 쓰는 템플릿을 새로 신청해야 한다. 우선 후보: GROWTH_01의 `이번주추천`, NEWS_01의 `시장동향`. 현재 사용자에게 보이는 효과와 신청 부담을 따져 사용자가 결정.

## 5. 남은 확인 사항
- 일반 사용자 번호로의 정기 발송 성공(관리자 번호만 확인됨).
- ACTION_01·CITE_01 승인 본문 원문 대조.
- 카카오가 템플릿 목적 불일치를 실제로 제재하는지(확인 못함).
- 환불 해지 `AEOLAB_CANCEL_02` 승인(약 11-02) 후 `KAKAO_TEMPLATE_CANCEL_REFUND` 설정.

## 한 줄 결론
- **① 네이버 차단 대응:** 예방·감지·후퇴·관측 장치는 대부분 구현·배포됐고 구멍 4곳을 추가로 막았다. **그러나 실제 차단 상황에서의 동작은 아직 한 번도 검증되지 않았고**, 프록시는 준비만 했으며, 사용자 300~500명 규모는 구조 변경 없이는 불가능하다는 것이 모델로 확인됐다.
- **② 인기 가게 신뢰 문제:** 잘못된 가게 매칭·부풀린 수치·과장된 이름·측정 못 한 항목의 0점 처리 같은 **신뢰를 깎는 요인은 여럿 제거**했다. **그러나 핵심 문제 — 인기 가게가 체험 결과에서 낮은 평가를 받는 구조 자체 — 는 부분 개선에 그쳤고, 사용자가 실제로 보는 체험 결과 화면을 인기 가게로 직접 확인하지 못했다.**

### 아직 안 풀린 것 (핵심)
1. **인기 가게도 체험에서 낮게 나오는 구조.** 체험 기록 254건이 전부 D(최고 22.7)였고, 네이버 검색 1위인 가게(홍대 육지, 니재빵집)도 통합 약 19점으로 저장돼 있었다(6월 기록). 위 수정으로 체험 통합 점수는 약 27점으로 올랐지만 **여전히 40 미만**이다. 원인의 대부분은 리뷰·구글 0점이 아니라 체험이 측정하는 범위가 좁은 것(ChatGPT 50회, 홈페이지 없으면 스키마 0점, AI 브리핑·AI탭·제미나이·구글 AI는 가입 후)이다. "전부 D의 주원인이 리뷰 0점"이라는 초기 진단은 과장이었고 정정했다(영향 약 8점).
2. **사용자가 실제로 보는 체험 결과 화면을 인기 가게로 직접 확인하지 못했다.** 30 미만이면 라벨이 "AI 검색 준비도 · 시작 전"인데, 네이버 1위 가게가 이것을 보고 어떻게 느낄지는 미검증이다(체험 실행에 API 비용·네이버 접속이 들어 보류).
3. **비인기 가게 관점**은 체험 기록에 리뷰 수가 없어(체험 기록 중 리뷰 수 저장 80건 미만) 분석하지 못했다.
4. 성장 단계가 `score_engine`과 `gap_analyzer` 두 곳에서 **따로 계산**된다(이름만 통일, 판정 규칙은 그대로).
5. 외부 자료가 권하는 **분모·신뢰구간 표시**(예: "50회 중 3회, 신뢰구간 …")는 제안만 했고 구현하지 않았다.

## 이 대화에서 바로잡은 내 오판 (신뢰성 기록)
- 체험 "전부 D"의 주원인이 리뷰 0점이라는 단정 → 약 8점 영향뿐.
- 접속 보호 현황표를 **파일 단위**로 세서 같은 파일의 다른 함수 구멍을 놓침 → 함수 단위 감사로 4곳 발견.
- "카나리를 프록시로 7일 시험" 제안 → 프록시 설정이 전역이고 순위 모듈은 프록시를 쓰지 않아 구조상 불가능, 철회.
- 용량 "약 40~50곳 한계" → 키워드 평균이 3이 아니라 4라 30~40곳.
- 성장 단계 이름 첫 추천 → 이미 라이브인 준비도 어휘를 무시한 것이라 철회, 조사 후 통일.
- 테스트 중 무의미한 것(예외 삼킴, 짝수 로테이션)을 변이 검증으로 발견·수정.

## 다음 우선순위(제안)
1. **인기 가게로 체험을 실제 실행해 사용자가 보는 화면을 점검**(어니언 성수·하라식당 등) — ②의 핵심 미확인 해소. 차단 해제와 회로 회복 동작을 먼저 확인한 뒤.
2. 체험 결과 상단에 **측정으로 확인된 강점**(검색 순위, 리뷰 수 등)을 먼저 보여 주고, 총점 라벨은 "측정된 범위 기준"임을 명시.
3. 차단이 실제로 났을 때 회로의 열림·회복 동작 확인(사건 기록 데이터 축적), 프록시는 사건 기록 기준 충족 시에만 구매.
4. push(커밋 23개)와 사용자 결정 항목(프록시 구매, 알림톡 템플릿 본문 확인).

- "마진 85.7%"는 문서 값, 실제 한도 사용 시 약 80% 추정(가정: 수동 스캔 540원 등) — 마진 작업은 보류 상태.

- 가이드 페이지에서 로드맵이 없다고 한 것은 "이번 주" 탭 때문이었다.
- 로그인 계정을 잘못 말한 사고: 기존 브라우저 쿠키가 다른 계정이었음 → 쿠키 `sub`로 확인.
- "'소수정예'는 등록 키워드"는 오류(등록: 작곡·편곡·연습실·녹음·우쿨렐레).
- **죽은 컴포넌트**: 체험 단계 ①②를 고쳤으나 `MergedScanInfoBox`는 어디서도 렌더되지 않았음 → 사용처 grep + 라이브 DOM으로 먼저 확인할 것.
- "언급 1회"가 가짜 인용이라는 의심은 기각: 원본 `naver_result.in_briefing=True`(실제 신호). 문제는 날짜 없이 최신처럼 보인 표시였다.
- "블로그 후기 템플릿의 지어낸 문장"은 화면에 렌더되지 않아 제외. "'스타일' 문구는 템플릿 결함"은 beauty/nail 분기의 카테고리 불일치 증상. "조건 검색이 제외를 무시"는 이미 `resolve_effective_keywords`로 반영.
- 검증 스크립트 입력이 실제 경로와 달라 "아로마마사지가 부족으로 나온다"는 거짓 결과가 나옴(`custom_keywords` 빈 목록 vs 실제 `or None`).
- 설정 화면의 "모든 분석에서 빠집니다"는 사실이 아니었다(경로별 누락) → 코드 수정 후 문구를 확인된 범위로 정정.

## 6. 절차·도구 메모
- **안전 배포**: `bash scripts/deploy_backend_files.sh <파일들>` (문법→서버 상태→백업→업로드→서버 테스트→재시작→/health). 서버 테스트가 `frontend/`를 읽으므로 **프론트를 먼저** 배포. 프론트는 md5 선확인 → `scp` → `npm run build` → `pm2 restart aeolab-frontend`.
- 이번 대화에서 자동 승인 분류기가 배포·운영 DB 쓰기를 거부한 적이 있다("Production Deploy", "Modify Shared Resources"). 우회하지 않고 사용자 허용을 받은 뒤 같은 스크립트로 진행했다.
- **라이브 로그인 검증**: 서버에서 서비스 키로 매직링크 생성(메일 발송 없음) → 브라우저로 링크 방문 → URL 해시의 토큰으로 `sb-<ref>-auth-token` 쿠키(`base64-`+토큰 JSON)를 직접 설정 → 쿠키 JWT `sub`로 계정 확인. 앱은 URL 해시 토큰을 세션으로 바꾸지 않는다. 검증 후 쿠키·스토리지를 지운다.
- 서버 DB 읽기 전용 스크립트: 로컬에서 작성 → `ast.parse` → `scp` → 서버 venv로 실행 → `rm`. 한글이 든 파이썬은 heredoc(`python - <<EOF`) 대신 파일로(cp949 문제). DB 클라이언트는 `from db.supabase_client import get_client`.
- **제외 키워드 구조 감사**: 업종 키워드 풀을 쓰는 새 모듈은 `keyword_taxonomy.drop_excluded`를 거치거나 `tests/test_excluded_keywords_coverage_audit.py`의 허용 목록에 **사유와 함께** 추가.
- 가이드 생성 라우트(`routers/guide.py` `_generate_and_save`)는 네이버에 접속하지 않는다(DB 읽기+Claude). 체험·가이드 점검 중 네이버 접속은 공식 검색 API뿐이었고 `/api/status/naver`는 매번 정상이었다.

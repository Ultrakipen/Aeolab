## 0. 한 줄 요약

유료 AI 노출 스캔이 **짧은 키워드형 쿼리**만 측정하는데, 시장은 **긴 자연어 질의**로 이동 중(네이버 공식: 롱테일 질의 전년比 2.5배). 메인 스캔 쿼리 구성에 **긴 자연어 다중조건 변형을 단일 소스로 추가**해 측정 범위를 현실에 맞춘다. DB 변경 없음, API 비용 동일.

## 3. 사실 vs 추론 경계 (정직성 원칙)

- **사실(문제)**: 긴 질의 2.5배 증가 + 코드상 짧은 쿼리 측정 → 둘 다 검증됨.
- **추론(해결책)**: "그러므로 긴 자연어 질의를 측정에 추가한다"는 엔지니어링 판단. 최신 자료가 "이렇게 고치라"고 적시한 것은 아님.
- **사실 경계**: 2.5배는 **네이버 검색 행동** 수치. ChatGPT·Gemini(Track2)에 적용하는 근거는 "대화형 AI는 자연어로 질문받는다"는 방향성 추론(공식 통계 아님).

## 4. P1 — 구현 범위 (NOW)

### 4-A. 단일 소스 쿼리 빌더 (핵심)
- `keyword_taxonomy.py`에 `build_ai_scan_queries(region, keyword) -> list[str]` 신규.
- 반환: **짧은 변형 3개(첫 요소 = naver/playwright용 짧은 쿼리 유지) + 긴 자연어 다중조건 변형 2개**.
- 긴 변형 예(지역 有): `"{지역}에서 {kw} 잘하는 곳 추천해줘"`, `"{지역} {kw} 중에 어디가 제일 괜찮아?"`
- **사실 안전 가드**: 사업장이 보유하지 않은 속성(조용함·주차 등)을 쿼리에 날조하지 않음. 일반 의도 표현만.

### 4-B. 유료 스캔 경로 배선
- `scan.py:2624` 인라인 3변형 → 헬퍼 호출로 교체.
- `jobs.py:339` 단일 쿼리 → 헬퍼 리스트로 교체.
- `_scan_queries[0]`(naver·google 단일쿼리)는 **짧은 쿼리 유지** → 네이버 측정 회귀 없음.

### 4-C. 점수 안정성 가드레일
- `sample_n`은 이미 쿼리 리스트를 N회에 균등 분산(`gemini_scanner.py:25-32`). 쿼리 수만 늘 뿐 **총 샘플 수·API 호출 수 불변** → 비용 동일.
- 집계 `exposure_rate`는 전체 N 기준이므로 점수 산식 변경 없음. 측정 입력의 다양성만 증가.
- `_check` JSON 측정 경로 그대로 사용(자연어 답변 측정 미도입) → 점수 의미 일관성 유지.

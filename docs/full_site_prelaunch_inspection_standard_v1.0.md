## §0.1 현재 검증 상태 (2026-06-17 — 새 대화창은 여기서 시작)

- **§5 노출기간표 = 코드 검증 완료.** 우리 ChatGPT·Gemini 점수는 **학습데이터 측정**(`chatgpt_scanner.py:25-30` 웹검색 도구 없음 / `gemini_scanner.py:16` 그라운딩 기본 false). → "수개월~1년" 정확.
- **CLAUDE.md "ChatGPT·Gemini 스캐너 점수 수개월~1년" = 진실 확인(수정 불요).** 코드와 일치.
- **정정된 오판 1건(기록):** v1.0 초안이 위 기간을 "웹검색 경로 누락 = 과소 안내"로 분류했으나 **방향 오판**. 우리 점수는 웹검색 경로(ChatGPT Search 24~72h)를 측정하지 않으므로, 그 빠른 기간을 점수 안내에 끌어오면 오히려 **과대 약속**. → §5에서 "우리 점수=학습데이터 ✅측정 / 웹검색·그라운딩=별도 참고채널 ❌미반영" 분리 완료.

## §1. 점검 대원칙 (먼저 읽을 것)

이 서비스의 사용자는 **소상공인**이며, 이들은 **네이버를 100% 신뢰**한다. 자기 가게가 네이버에 어떻게 나오는지에 매우 민감하고, 블로그·스마트플레이스 개선을 전문 업체에 대행할 만큼 중요하게 여긴다. 따라서 일반 점검 원칙 위에 **도메인 2대 원칙**이 추가된다.

### 1.1 도메인 2대 원칙 (이 서비스 고유 — 위반 시 무조건 P0)

- **원칙 N — 네이버 우선 (Naver-First).** 스캔 결과·대시보드·가이드·체험·미리보기 등 **결과를 보여주는 모든 화면에서 네이버 관련 정보가 시각적·구조적으로 먼저** 나와야 한다. 글로벌 AI(ChatGPT·Gemini·Google)는 그 다음. 서비스가 제공하는 개선 방안은 **"네이버 SEO 검색 상위 노출 가능성을 높일 수 있다 / 개선 가치가 있다"는 점을 명확히** 안내해야 한다(전 업종 공통 가치). ⚠️ **단정 금지** — "상위권 노출이 **가능하다**"는 확정 표현은 축 E·게이트 T의 "노출 보장 단정 0"과 충돌하므로, **확률·가능성 표현**으로만 쓴다("반드시"·"보장" 금지).
- **원칙 T — AI 노출기간 사실성 (공식 출처 기준).** "개선하면 며칠/몇 주/몇 달 뒤 노출"이라는 모든 기간 안내는 **§5 공식 출처 단일표**를 따른다. 네이버가 공식 미공개한 기간은 **반드시 `(추정)` 배지 + 근거 1줄**. 채널별로 다른 기간을 뭉뚱그리지 말 것(특히 ChatGPT 웹검색≠학습데이터).

### 1.2 일반 원칙 (six_pages §1 계승)

1. **루브릭 고정 + 페이지별 분할** — "다 봐줘" 금지. §3 7기준 0~10 채점, ❌만 수정.
2. **근거 + 반증 동시** — "P0/P1이다" 보고 직전 **단정 근거 `file:line` 1줄 + 반증 시도 1줄**을 본 적이 있어야 함(CLAUDE.md §"문제 분류 검증 의무").
3. **실증 우선** — 더미숫자·`text-xs`는 grep 카운트로, 레이아웃·동작은 라이브 `https://aeolab.co.kr` PC+모바일 스크린샷으로 실증. 추측 보고 금지.
4. **종료 기준** — 기준 전부 ✅면 즉시 중단. 취향 제안 금지(반드시 ❌항목 매핑). CLAUDE.md `feedback_dashboard_inspection_standard`.
5. **서버 우선 배포** — `md5 선확인 → scp → npm run build → pm2 restart → 라이브 검증 → git 커밋` 순서.
6. **솔직함(정직 보고)** — 있는 그대로. 거짓 "완료" 금지, 자화자찬 금지, 모르면 "미확인", 자기 작업도 비판적으로, 테스트 실패는 즉시 그대로 보고.
7. **CLAUDE.md·문서 = 스냅샷** — 수치·패턴은 항상 실제 코드/라이브/공식출처로 검증 우선. 거짓 발견 시 §10 절차로 CLAUDE.md 수정.

## §2.1 효율 실행 전략 (토큰·시간 절감 — Max 5x 한도 고려, 필수)

> 75페이지 × 7기준 × 2-pass × PC/모바일 라이브 × 5인 패널을 **페이지마다 전부** 돌리면 한도를 빠르게 소진한다. 같은 커버리지를 훨씬 싸게 얻는 4원칙:

1. **전역 기준은 페이지별이 아니라 1회 일괄 grep으로.** 축 D 교차 일관성·축 A 정적 항목은 75번 반복하지 말고 **레포 전체 1회 패스**로 끝낸다 — ① 가격 4곳 일치 ② `text-xs` 잔존 카운트 ③ 점수 더미숫자(`[0-9]+점`) ④ 영문 업종 라벨 폴백 ⑤ 노출기간 문구(게이트 T). **가장 큰 절감 요인.**
2. **라이브 브라우저는 P★+P1에만.** P2~P4는 코드+grep으로 점검하고 §9 "라이브 미확인·코드상 정상" 구분 보고를 활용. 스크린샷 2장/발견 규칙도 전환 핵심 화면(P★·P1·게이트 N)에만 적용.
3. **패널 교차검증(§8)은 후보가 있을 때만.** 1단계 grep으로 P0 후보표를 먼저 만든 뒤, **후보가 있는 페이지에만** `frontend-dev`·`scan-engine`·`code-review` 병렬 투입. 0건이면 패널 스킵.
4. **세션 분할 = 1세션 1그룹, 사이사이 `/clear`.** 권장 순서:
   - 세션1 — **전역 grep 패스**(위 1번) → P0 후보표 산출(가장 싸고 많이 잡힘)
   - 세션2 — **P★ 4페이지 라이브**(전환 직결, ROI 최고)
   - 세션3 — **P1 대시보드·가이드 라이브**
   - 이후 — P2~P4는 grep 기반, 필요 페이지만 라이브

## §3. 7기준 점검 루브릭 (각 페이지 0~10 채점, 만점 70)

> 축 A~E는 six_pages 5축 계승. **게이트 N·T는 이 서비스 고유 도메인 기준**으로, 결과/안내 화면에서 ❌면 무조건 P0(상업 부적합).

### 축 A — 사실적·실질적 구현 (실측)
- 더미/임의 추정 숫자 노출 **0건**. 점수는 **텍스트 레이블**(양호/보통/주의 필요)만, 숫자(`72점`) 금지 — 티저 더미숫자도 금지(`feedback_score_display_text_only`).
- API 실패 시 `0`/`N·A` 폴백, 허위 수치 생성 금지.
- 버튼·생성기·필터가 실제 백엔드에 연결돼 동작.
- 빈 상태 "아직 데이터 없음 — 첫 스캔 후 표시" 안내.
- 업종 라벨 영문 폴백(restaurant→음식점 누락) 0건(`reference_category_label_leaf_fix`).

### 축 B — PC/모바일 텍스트·구조·폭
- 본문 `text-xs` 잔존 카운트(권장 `text-sm`+).
- **PC/모바일 별도 레이아웃**으로 알맞게 분기(한 화면 강제축소 아님).
- **PC 가로폭이 작지 않은가** — 본문이 좁은 컬럼에 갇혀 좌우 여백만 큰 화면 금지. 정적 본문은 `max-w-3xl`(정책/정보)·대시보드는 넓은 그리드 활용.
- 모바일 가로 스크롤·텍스트 잘림·버튼 겹침 0건. 페이지 패딩 `p-4 md:p-8`.

### 축 C — 이해도·업종별 적합성
- 비전문가(소상공인)가 용어 설명 없이 이해 가능. 전문용어엔 1줄 풀이.
- **ACTIVE/LIKELY/INACTIVE 업종 분기** 정확. INACTIVE에 네이버 AI 브리핑 **단정 노출 금지**. 프랜차이즈 제외(`getBriefingEligibility`).
- AI탭 vs AI 브리핑 **용어 혼동 0**(`ai_briefing_vs_ai_tab_clarification`).

### 축 D — 스크롤·정보 구조·중복 제거
- 위→아래 **중요 정보 먼저**. 첫 화면이 부정 평결·빈 상태로 시작하지 않음.
- 섹션 앵커/아코디언/탭 점프 끊김 0.
- **중복 콘텐츠 0** — 같은 정보가 같은 페이지/인접 섹션에 반복 노출되지 않는가(예: 네이버 채널 Hero↔InsightZone 중복).
- **교차 페이지 일관성** — 페이지 **사이**에 같은 값이 일치하는가: 가격(4곳)·점수 레이블(대시보드↔`/demo`↔`/trial`의 `scoreLabels`)·업종 라벨·용어. 페이지별 점검만으론 못 잡음(`demo_trial_dashboard_alignment` 실사고).

### 축 E — 상업 서비스 적합성 (출시 게이트)
- **플랜 게이트** 정확(`PlanGate.tsx`) — 무료가 유료 기능 보거나 유료가 막히는 오작동 0.
- **결제·전환 동선** — 잠금→업그레이드 CTA가 실제 결제/플랜으로 연결.
- **면책 문구** — 변동 데이터에 "측정 시점·기기·로그인 상태에 따라 달라질 수 있음" 일관. ChatGPT 측정 면책 노출.
- **법적·정책 표현** — 과장/허위 보장 0("반드시 노출"·"100% 보장" 금지). 네이버/ChatGPT 정책 위반 표현 0.
- **상거래법 필수 고지(유료 결제 출시 게이트)** — `/terms`·`/privacy`·결제 화면에 **사업자등록번호·통신판매업 신고번호·대표자·연락처·환불/청약철회 규정** 표시. 전자상거래법·정기결제(자동갱신) 고지 의무 충족. 누락 시 **P0(법적 리스크)**.
- **신뢰성** — 베타 후기 placeholder 실데이터 교체, 미검증 기능 "완료" 노출 금지.

### 게이트 N — 네이버 우선 (결과/안내 화면 한정, ❌=P0)
- 결과 화면에서 **네이버 정보가 글로벌 AI보다 먼저**(위/좌측/우선 탭) 나오는가.
- 개선 방안에 **"네이버 SEO 검색 상위 노출 가능성↑·개선 가치 있음"**이 명확히 안내되는가(전 업종 공통 개선가치, `project_static_pages_standard`). 단, **"반드시 상위 노출"·"노출 보장" 단정은 축 E 위반** — 확률 표현으로만.
- 네이버 채널(AI 브리핑·AI탭·스마트플레이스·블로그) 안내가 글로벌 AI에 묻히지 않는가.
- INACTIVE 업종도 **네이버 일반검색/SEO 개선 가치**는 안내(네이버 자체를 배제하지 않음).

### 게이트 T — AI 노출기간 사실성 (기간 안내 화면 한정, ❌=P0)
- 기간 숫자가 **§5 공식 출처 표와 일치**하는가.
- 채널별로 **분리 안내**(네이버 2~4주 추정 / ChatGPT 웹검색 수일~수주 vs 학습데이터 수개월~1년 / Google·Gemini 2~4주)되는가. 뭉뚱그림 0.
- 네이버 등 **공식 미공개 기간**에 `(추정)` 배지 + 근거 1줄 있는가.
- "노출 보장" 단정 0. "개선 시 ~기간 내 노출 가능성" 식 확률 표현인가.

## §7. 심층 점검 + 오판 최소화 2-pass (six_pages §6 계승 — 필수)

> 모든 발견은 **2-pass(발견 → 반증 재점검)** 통과해야 보고 가능. 옛 주석·부분 grep만으로 단정 금지(2026-05~06 오판 사고).

- **6.1 3계층 실증** — 코드(`Read` 직접) → 호출처(`grep -rn` 전체 카운트) → 라이브(PC+모바일 실화면). 셋 일치해야 확정.
- **6.2 단정 직전 반증 1회 의무** — 아래 표에서 최소 1개 실행·기록. 반증 라인 없는 P0/P1 보고는 **무효**.

| 단정 유형 | 흔한 오판 원인 | 필수 반증 |
|----------|--------------|----------|
| 기능 미연결/미동작 | 다른 파일서 import·호출됨 | 호출처 `grep -rn` 카운트 |
| 더미/허위 수치 | 실측을 더미로 오인 | prop·API 응답 역추적 |
| 텍스트 너무 작음 | 모바일 분기를 PC로 오인 | 반응형 `md:`·별도 모바일 컴포넌트 확인 |
| 업종 분기 오류 | 단일 소스 안 봄 | `score_engine.py:30`/`userGroup.ts` 대조 |
| 점수 숫자 노출(회귀) | 진행률 바를 숫자로 오인 | 렌더 문자열이 `scoreLabels` 경유인지 Read |
| 문구 과장/허위 | 사실 문구를 과장으로 오인 | 계층 구분 — 봇차단(사실) vs 콘텐츠영향(별개) `reference_naver_bot_block_vs_content_effect` |
| **게이트 N 위반(네이버 후순위)** | 탭/접힘으로 실제론 우선일 수 있음 | 라이브 렌더 순서·기본 활성탭 확인 |
| **게이트 T 위반(기간 오기재)** | 스캐너 맥락 표현을 사용자 노출로 오인 | §5 표 + 해당 문구의 대상(스캐너 점수 vs 노출 안내) 구분 |

- **6.3 수정 후 2차 패스** — ① 재현 재점검(❌→✅) ② 부작용 재점검(인접·타 페이지 회귀 0) ③ 서버 반영 재점검(ssh grep 1줄 + 빌드 성공 + pm2 에러 0) ④ 드리프트 재점검(scp 후 git 커밋, md5 일치).

## §10. CLAUDE.md·문서 진위 검증 의무 (NEW — 사용자 요구 반영)

> CLAUDE.md·docs·메모리는 **스냅샷이며 거짓일 수 있다.** 특히 **AI 도구별 노출기간은 공식 웹사이트가 진실의 기준.** 점검 중 수치·정책·기간 관련 기재가 의심되면 아래 절차로 검증·정정한다.

1. **의심 트리거** — 노출기간·업종분류·가중치·정책(네이버/ChatGPT/Google)·가격 등 수치/정책 기재를 사용자 노출 화면 근거로 쓰기 직전.
2. **공식 출처 확인** — `WebSearch`/`WebFetch`로 1차/공식 자료 확인(노출기간은 §5 표가 1차 캐시, 의심 시 재조회). 네이버는 공식 미공개면 "미공개"로 확정.
3. **코드 대조** — 가중치·업종분류·가격은 **실제 코드 단일 소스** 직접 확인(`backend/services/score_engine.py`·`backend/config/prices.py`·`frontend/lib/userGroup.ts`). CLAUDE.md 숫자만 신뢰 금지.
   - ⚠️ **점수 가중치 점검 시 라이브 버전 함정(필수)** — `score_engine.py:24` 코드 기본값은 `SCORE_MODEL_VERSION="v3_0"`이지만, **서버 .env에 `v3_1`(그룹별 가중치)이 라이브**다. 가중치 수치를 점검·기재하기 전 **반드시 서버 .env 버전을 먼저 확인**: `ssh root@115.68.231.57 "grep SCORE_MODEL_VERSION /var/www/aeolab/backend/.env"`. 코드 기본값(`v3_0`)만 보고 가중치 단정 금지(`reference_live_score_model_v3_1` — 2026-06-12 오판 2회 함정).
4. **정정 분류** —
   - **거짓(현재 코드/공식과 불일치)** → CLAUDE.md 즉시 수정 + 변경 라인 메인 세션 직접 확인.
   - **맥락 한정 표현(틀리진 않으나 오해 소지)** → 삭제 아닌 **정밀화 주석** 추가(예: §5의 ChatGPT 기간).
   - **미공개를 단정** → `(추정)`·"공식 미공개" 명시로 교정.
5. **기록** — 정정 시 CLAUDE.md 해당 섹션 + 본 문서 §5/변경이력에 근거 `file:line`/URL 남김.

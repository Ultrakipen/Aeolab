# 전체 사이트 사용자 관점 UX 점검 v1.0 (2026-09-03)

> 목적: 소상공인 사용자가 실제로 사이트를 처음부터 끝까지 쓴다고 가정하고, **편의성·정보구조·스크롤 흐름·설명 가독성** 4가지 기준으로 전체 페이지를 라이브 실측 점검. 코드 버그 사냥이 아니라 UX 관점 점검으로 시작했으나, 과정에서 실제 정합성 버그 1건도 함께 발견됨.

## 1. 범위와 방법론

- **점검 대상**: 관리자(`/admin/*`, 이미 전수 점검 완료 — 제외) 제외 전체 페이지 **66개** (동적 라우트는 대표 슬러그/카테고리 스팟체크)
- **도구**: `mcp__playwright__browser_*`로 실계정(hoozdev@gmail.com, 사업장 2개 — 홍스튜디오·하라식당) PC(1400px)+모바일(375px) 라이브 실측
- **배치 구성**: ① 공개 마케팅/정보 페이지(18개) → ② 인증 플로우(3개) → ③ 대시보드 기능 페이지(13개) → ④ 설정·고객센터(7개) → ⑤ 대행서비스·결제(8개) → ⑥ 인벤토리 대조로 발견한 누락분 보완(6개)
- **핵심 절차 (CLAUDE.md "개선 과제·누락 제안 검증 의무" 적용)**:
  1. 1차 핵심 여정(10페이지) 점검 후 사용자가 "오판과 누락은?" 질의 → 반증 절차 적용, **최초 보고 6건 중 5건이 오판으로 기각**됨(생존 1건, 심각도도 P1→P2 하향)
  2. 이후 배치부터는 "발견 즉시 자체반증" 규칙을 프롬프트에 내장해 왕복 최소화
  3. 최종 5개 배치 완료 후 사용자가 재차 "오판과 누락은?" 질의 → **메인 세션이 직접 코드(Read)로 상위 2건을 재검증**(오판 아님 확정) + **전체 페이지 인벤토리(Glob) 대조로 6개 페이지 누락 발견**, 배치 ⑥으로 보완

## 2. 오판으로 기각된 최초 발견 (기록용 — 반증 근거)

1인 개발 프로젝트 특성상 "그럴듯해 보이는 인상"이 실제로는 근거 부족인 경우가 많았다. 향후 유사 점검 시 같은 실수를 피하기 위해 기록:

## 4. 스코프에서 의도적으로 제외한 항목 (수정 안 함, 판단 근거)

- **`/help` 페이지**: 재확인 결과 이미 `AuthNavControlClient`+`SiteFooter`+정직한 빈 상태 처리("아직 공개 FAQ가 없습니다")가 되어 있음 — 최초 배치 보고("고아+빈 페이지")가 과했던 항목, 조치 불필요
- **문의 티켓(`/support/tickets`) 삭제 기능 부재**: 감사이력 보존 의도된 설계로 판단(관리자단도 "종료"만 가능), 스코프 아님
- **`/notices`, `/preview` 고아 라우트**: 콘텐츠 자체는 정상이나 진입 링크가 없음. 어디에 새 네비게이션을 추가하는 게 적절한지 불확실하고 전체 사이트 네비 구조 변경은 blast radius가 커서 이번 스코프에서 제외 — 필요 시 별도 논의
- **`(auth)/page.tsx`**: 조사 결과 어떤 URL에도 매핑되지 않는 완전한 죽은 코드(루트 `/`는 `app/page.tsx`가 서빙) — 조치 불요

## 2. 측정 사실 (서버 실측·스크린샷 눈 대조)
- 검색 첫 화면의 가게 카드는 **PC 3~13곳, 모바일 5~14곳**뿐이다. 따라서 "20위 이내"가 아니라 "검색 첫 화면" 기준이며,
  None은 "20위 밖"이 아니라 "첫 화면에 없음"이다(카드 문구 정정 완료).
- 순위는 **광고 제외** 순서다. 화면에서는 위에 광고가 몇 칸 있어 더 아래로 보일 수 있다.
- 처음 만든 "정답(카드 순서)" 비교는 측정 코드와 같은 추출 방식이라 순환이었다 — 스크린샷을 눈으로 대조해 방향이 맞음을 따로 확인.
- 가끔 네이버가 가게 목록 없이 파워링크 광고만 내려준다(목록 0개) → 새로고침 재확인으로 처리.
- 등록 ID가 있는 사업장은 ID 기준 순위와 이름 기준 순위가 모든 사례에서 일치(ID 불일치로 인한 거짓 미노출 없음, 8개 사업장 29개 키워드).

## 3. 점수 연결 시뮬레이션 (현재 등록 사업장 8곳, 읽기 전용)
순위 포함 시 순위 제외 대비: 어니언 성수 51.9→34.6, 대호흑돼지 9.8→7.3, 힐링하우스마사지 31.2→21.9(**stability→survival**),
홍스튜디오 43.4→32.4, 하라식당 70.5→71.6, 홍뮤직 39.6→39.7.
- 유명한 가게(어니언 성수)도 "성수 카페" 같은 넓은 키워드에서는 첫 화면에 없어 0점 → 약한 가게뿐 아니라 인기 가게도 깎인다.
- 구체 메뉴·세부 키워드(규동·초밥·편곡)는 1위로 잡힘. 즉 키워드 선택에 점수가 좌우된다.
- 결론: **현재 방식(키워드 평균)으로 연결하면 이탈 위험이 크다.** 연결한다면 "가장 잘 노출되는 키워드" 중심 등 산식 재설계 후 별도 승인.

## 5. 점수 연결 산식 재설계안 (승인 대기 — 코드 미변경)
### 변형 시뮬레이션(등록 사업장 8곳 중 6곳, 순위 제외 기준 대비 변화, 순위 점수 = 키워드별 100/80/60/40/0의 집계)
| 방식 | 평균 변화 | 최저 | 최고 | 비고 |
|---|---|---|---|---|
| 키워드 평균 100% 가중(현재안) | −6.6 | −17.3(어니언 성수) | +1.1 | 인기 가게 감점 |
| 키워드 평균 가중 40% | −3.3 | −8.6 | +0.5 | 절반만 감점 |
| 최고 키워드 1개 | +0.4 | −17.3 | +18.1 | 가중 35% 업종은 ±18점 출렁임 |
| 최고 키워드 + 가중 40% | +0.1 | −8.6 | +8.8 | 감점 여전 |
| **보너스 전용: max(기준, 최고키워드 가중 40% 반영)** | +2.5(3.5+8.8+2.9÷6곳, 처음 +2.2로 잘못 적음) | 0.0 | +8.8 | 감점 없음 — max()의 구조적 결과이지 실측 발견이 아님 |
- 어떤 집계 방식이든 "노출 0"인 가게는 기준(순위 제외, 재정규화로 올라간 점수)보다 내려간다 — 집계 방식으로는 해결 불가.
- **권장: 보너스 전용** — 순위는 점수를 올리기만 하고 내리지 않는다. 노출 못 한 상태는 순위 카드의 안내로 전달.
### 구현 지점 (B안: 점수 계산 시 최근 keyword_ranks 재사용, 에이전트 조사 + 메인 검증)
- calculate_score 호출처: scan.py:974(trial, 제외), 2186, 2966, 3228; jobs.py:585, 5938(대행 30일 재스캔); shadow scan.py:2385, jobs.py:900;
  **report.py:4654·4671·4807(what-if 시뮬레이션)** — 에이전트가 놓침, 같은 입력을 안 주면 "현재 점수"가 저장값과 어긋남.
- 에이전트의 "PLAYWRIGHT_SEMAPHORE 중첩 데드락" 주장은 오판: `naver_keyword_rank.py`는 자체 `_semaphore`(50행)를 쓰고 전역 세마포어를 쓰지 않음.
  다만 방식 A(스캔 중 측정)는 전역 세마포어 밖에서 Playwright가 동시에 돌아 RAM 위험(동시 2개 금지) — B안은 측정 없이 DB 조회만.
- 공개 페이지 `score-guide`(248행)·`how-it-works`(407행)가 키워드 순위 가중치를 25/30/35%로 안내 중 — 현재 점수 계산과 불일치. 재설계 시 함께 정정.

## 6. 재설계안 검토 결과 (오판·오탐·논리 모순) — 보너스 전용안은 보류 권고
외부 자료: SEO 가시성 지표는 순위×검색량×위치별 클릭률로 계산하고(Sistrix·Semrush 등, 공식 산식은 비공개),
브랜드(상호) 키워드와 비브랜드 키워드는 분리해 추적하는 것이 실무 관행(Moz 포럼·SEO 용어집 등 2차 자료).
네이버 플레이스 순위는 유사도·인기도·거리·충실성을 종합(네이버 스마트플레이스 고객센터 안내를 인용한 2차 자료, 원문 미열람, 세부 가중치 비공개).
- 논리 모순 1: max(기준, 블렌드)는 "순위 점수 > 다른 항목 평균(기준)"일 때만 오른다 — 기준이 높은 가게는 순위가 좋아도 가점 0. 설명 불가·비단조.
- 논리 모순 2: 이름 검색은 거의 모두 1위(§이전 17건)임을 확인해 놓고, "최고 키워드" 집계는 가게 이름을 키워드로 등록하면 누구나 100점이 되는 구조 — `routers/business.py:361` 허용 목록에서 keywords는 사용자 편집 가능, 상호 키워드 제외 로직 없음.
- 오탐: 경쟁이 작은 키워드(홍뮤직 '창원 편곡', 카드 3개 중 1위)도 100점 → 검색량·경쟁 무시. 외부 관행은 검색량 가중.
- 오판 1: 시뮬레이션 평균 +2.2는 계산 오류(정확히 +2.5), 그리고 "아무도 내려가지 않음"은 max()의 정의상 당연한 결과.
- 오판 2: 40%·14일은 근거 없는 임의값. 표본은 내부 사업장 6곳.
- 한계: 측정은 서울 서버 IP·비로그인 — 네이버 순위에 거리 요소가 있어 고객 위치별 순위와 다를 수 있음(카드 안내에 위치는 있으나 점수 근거로는 약함).
- 리뷰 수 안내 줄: `review_count`·`avg_rating`도 사용자 편집 가능(`business.py:361`) — 실측값이 아닐 수 있음.
- 결론: 점수 연결은 (a) 상호 키워드 분리·제외 (b) 검색량 가중 또는 최소 경쟁 기준 (c) 실사용자 데이터가 갖춰진 뒤 재검토. 그때까지 순위는 점수와 분리된 비브랜드 노출 지표로 유지.

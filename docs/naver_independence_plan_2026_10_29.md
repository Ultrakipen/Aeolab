- **AI탭 질의 수 `NAVER_AI_TAB_MAX_QUERIES`(1~4, 기본 4=현재와 동일)**: 서버 `.env` 한 줄 + 백엔드 재시작으로 적용. 활성 35곳 알림(70%) 때 2로 낮추는 용도(모델상 100곳 하루 최대 886→680). **플랜별 차등은 만들지 않음** — 스캔 함수가 플랜을 모른다. 질의를 줄이면 AI탭 측정 항목의 표본이 줄어드는 영향은 아직 검토 전이라 낮추기 전에 확인할 것.

- **수동 새로고침 보호 보강 (한 사용자가 전체 속도 기준을 혼자 쓰는 것 방지)**: 사용자별 한도에 **10분 3회** 추가(`_MANUAL_SYNC_BURST_CAP`, 3회=18페이지로 10분 전역 기준 30의 60%, **제안값**·1시간 15회는 그대로). 네이버 쪽 거절(`naver_rate_limited`·`naver_place_cooldown`·`quota_exceeded`·`ip_blocked`)은 500이 아니라 **503**("지금 네이버 확인 요청이 몰려 있어요. 저장된 값은 그대로"), 접속하지 못한 앞의 셋은 사용자 한도를 환급(`manual_sync_refund`), `ip_blocked`는 접속이 있었으므로 환급 안 함. 프론트는 429(너무 자주)와 503(몰려 있음)을 다른 문구로 구분하고 일괄 동기화는 둘 다에서 중단. 변이 4종 검증. 한도는 서버 메모리라 재시작 시 초기화.

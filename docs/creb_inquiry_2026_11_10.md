# 크렙(Creb) 문의 — 발송용 (2026-11-10)

> 사용자가 크렙 고객센터·담당자에게 보내는 문의다. 아래 "발송 문안"만 복사해서 쓰면 된다. 답변이 오면 §3 표대로 코드·방침에 반영한다.
> 기존 §12-3(재가입 방어 설계 문서)의 4개 항목에 **2026-11-10 실제 결제 시험에서 확인한 사실**을 더해 6개로 정리했다.

## 1. 발송 문안

제목: [빌링(자동결제) API 문의] 카드 식별값·거래 조회·환불 정산 관련 6가지

안녕하세요, 빌링(자동결제) API를 연동해 사용 중인 (주)온프(서비스명 AEOlab)입니다. 연동 중 확인이 필요한 사항이 있어 문의드립니다.

**[카드 식별]**
1. 빌링키 발급 응답에 **카드 고유 식별값**(카드 지문, 토큰, 해시 등 같은 카드를 알아볼 수 있는 값)이 포함되는지, 포함된다면 필드명과 **보관·이용 가능 범위**(예: 부정 이용 방지를 위한 해시 보관이 허용되는지)를 알려 주세요.
2. 같은 카드를 다시 등록하면 `billKey`가 **동일하게 발급**되는지, 매번 다르게 발급되는지 알려 주세요.
3. 현재 발급 응답의 `cardNumber`는 **앞 8자리 + `****` + 끝 4자리** 형식으로 내려옵니다. 이 값이 마스킹 규정상 서비스 DB에 저장해도 되는 범위인지, 그리고 앞 8자리가 발급사(BIN) 구분 정보인지 확인 부탁드립니다.

**[결제 안정성]**
4. 결제 요청이 **타임아웃**으로 끝났을 때 승인 여부를 확인할 수 있는 **거래 조회 API**(주문번호 기준)가 있는지 알려 주세요.
5. 같은 `order_id`로 결제를 재요청하면 **중복 결제가 거부**되는지(멱등 처리 여부) 알려 주세요.

**[환불·정산]**
6. 전액 취소(환불) 시 **PG 수수료가 환급되는지**, 그리고 취소 건이 정산 내역에 어떻게 반영되는지(취소 반영 시점·수수료 처리 방식) 알려 주세요.

바쁘신 중에 감사합니다. 확인되는 대로 회신 부탁드립니다.

## 2. 왜 묻는가 (발송하지 않는 내부 설명)

| # | 질문 | 현재 상태 | 답에 따라 달라지는 것 |
|---|------|-----------|----------------------|
| 1 | 카드 고유 식별값 | 코드는 `cardNumber`(마스킹)·카드사 코드만 저장 (`webhook.py:229-230`). 마스킹 값은 **앞 8자리+끝 4자리라 서로 다른 카드가 같을 수 있다** | 고유 식별값이 있으면 카드 기반 재가입 방어 가능(오탐 해결). 없으면 카드 키는 구현하지 않는다 |
| 2 | 같은 카드의 `billKey` 동일 여부 | 미확인 | 동일하면 빌링키 해시 자체를 카드 식별에 쓸 수 있다 |
| 3 | 마스킹 값 저장 범위 | 구독 행에 저장 중(`card_number_masked`), **해지 시 지운다**(`settings.py`) | 허용 범위 밖이면 저장 자체를 줄이고, 방침에 카드 항목을 쓸지 정한다 |
| 4 | 거래 조회 API | 없음 (`creb_client.py`에 조회 함수 없음). 타임아웃이면 "결과 불명"을 구분할 수 없다 | 있으면 타임아웃 시 재청구 전에 조회해 이중 청구를 막는다 |
| 5 | 멱등 처리 | 미확인 (우리 쪽은 갱신 이중청구 가드 36시간 창만 있음) | 거부되면 재요청이 안전, 아니면 우리 쪽 가드가 유일한 방어 |
| 6 | 환불 수수료 환급 | 마진 계산은 환불 시 수수료 미환급을 가정하지 않았다 | 미환급이면 7일 환불 정책의 건당 비용이 생긴다(마진 문서 보정) |

## 3. 답변 받은 뒤 할 일

- **1·2 긍정**: 카드 키(`KEY_CARD`) 추가 — 결제 시점에 해시 보관(해지 때 지워지기 전), 방침 항목·약관·공지·탈퇴 화면 문구와 시험 동기화, 변호사 확인 대상.
- **1·2 부정**: 카드 기준은 구현하지 않고, 현재 키(이메일·플레이스 번호·카카오 ID·사업자번호·연락처)만 유지.
- **3**: 허용 범위에 맞게 저장 정책 정리 (방침 갱신 필요 여부 판단).
- **4·5**: 거래 조회·멱등 지원이 있으면 `creb_client.py`에 조회 호출을 추가하고, 타임아웃 후 "결과 불명" 상태 처리를 설계 (결제 코드는 변경 전 호출 그래프 전체 확인).
- **6**: `docs/plan_limits_v1.0.md`·`docs/business_viability_audit_v1.0.md` 마진 수치에 환불 시 수수료 처리를 반영.

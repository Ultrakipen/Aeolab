# AEOlab 상업 서비스 총괄 점검 계획 v1.0

> 작성일 2026-07-11. 기존 점검(75개 페이지 7기준 · 마스터 점검 4-레이어 · 관리자 화면 · 구독 생애주기 · 대행 서비스 등)은 **사용자 가치/UX/데이터 정확성** 축에 집중돼 있었고 전부 완료됨(§1 참조). 이번 요청("사업성·보안 등 처음부터")은 그 축에서 **다뤄진 적 없거나 3개월 이상 재점검이 없는 4개 신규 축**을 세우는 것이 핵심.

## 0. 원칙

- **재점검 금지 축**: 사용자 UX·데이터 정확성·측정 파이프라인 무결성은 이미 20회 이상 라운드로 점검 완료(§1). 여기 다시 들어가지 않는다.
- **전문가 렌즈 + 사용자 렌즈 이중 적용**: 보안=침투테스터 관점, 사업성=투자자/재무 관점, 법적=변호사 관점, 인프라=SRE 관점 / 모든 축에 "소상공인 사장님이 이걸 알면 안심할까·불안할까" 사용자 렌즈를 덧씌운다.
- **단정 전 반증** (CLAUDE.md 표준 적용): 아래 각 항목은 실제 코드 확인 없이 "안 되어 있을 것"으로 추정 금지. 실행 단계에서 코드 우선 확인 후 결함으로 분류.
- **실사용자 0명이라는 현실 전제** ([[project_next_steps_handoff_execution_2026_07_11]] 참조): 사업성 점검은 "완벽한 재무모델"이 아니라 "가설 검증 가능한 최소 지표 체계"를 목표로 한다.

## 2. 신규 축 — 이번 점검의 본론

### A. 보안 (Security) — 최대 공백

**현재 상태(확인됨)**: 2026-04-13 `186248a` 커밋에서 1회 보안 점검 실시(Toss 웹훅 Basic Auth 검증 `_verify_toss_auth` 추가 등). **그 이후 3개월간 대행서비스·관리자 총괄 대시보드·팀/API키·구독 생애주기 등 대규모 신규 표면이 추가됐는데 보안 관점 재점검이 없었음** — 이것이 실제 공백.

| 점검 항목 | 확인 방법 |
|---|---|
| IDOR (소유권 검증 누락) — 사업장/스캔결과/대행의뢰/문의 등 전 리소스 | 각 라우터에서 `business.user_id == current_user.id` 류 검증이 모든 CRUD 엔드포인트에 있는지 grep 전수 |
| 관리자 권한 상승 — support가 owner 전용 액션 접근 가능한지 | `require_owner` 실제 적용 라우트 24곳(현재 `admin.py` 확인) 대비 금전 이동 액션 커버리지 |
| 웹훅 재검증 — Toss 서명/Basic Auth가 모든 webhook 엔드포인트에 적용됐는지 | `webhook.py` 전체 엔드포인트 대조 (issue_billing 외 confirm 등) |
| Rate limiting 커버리지 | 확인된 9개 파일 외 로그인/회원가입/문의작성 등 어뷰징 취약 엔드포인트 누락 여부 |
| Secrets 관리 | `.env` gitignore 확인됨(양호) — 서버 파일 권한(600)·API 키 로테이션 이력 여부 |
| XSS | `dangerouslySetInnerHTML` 4곳(FAQ, HeroSampleCard, layout.tsx) — 사용자 입력값 삽입 여부 확인 |
| SSRF | Playwright 크롤러(경쟁사 URL 등)가 사용자 입력 URL을 그대로 fetch하는지 |
| 의존성 취약점 | `npm audit` / `pip-audit` 실행 이력 없음 — 1회 스캔 필요 |
| 로그 내 PII 노출 | error.log에 이메일·전화번호 평문 기록 여부 |

**실행 방법**: `/cso` skill(comprehensive 모드, OWASP+STRIDE+시크릿 스캔) 우선 실행 → 발견 항목은 CLAUDE.md 표준대로 근거+반증 검증 후 P0/P1 분류.

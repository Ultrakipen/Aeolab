## 확인되지 않은 것 (미확인 — 시작해도 되지만 알고 있어야 함)
1. **30일 뒤 정기 재결제(`renewal`)** — `payment_events`에 첫 결제 성공(`billing_issue`)은 4건(09-02 ×2, 09-29, 10-27 실결제 8,950원)이 있지만 `renewal` 기록은 0건이다. 재결제 호출(`retry_billing`)은 첫 결제와 같은 `billpay`(빌링키)라 API 자체의 위험은 낮으나, 잡 로직(`subscription_lifecycle_job`)은 동작 시험(테스트)이 없다 — 아래 "추가 개선 후보" 참조. (이전 문서의 "카드창 이후 결제 완료 미확인"은 과장이었다: 첫 결제 완료는 10-27 서버 기록으로 확인됨.)
2. **제3자 번호로 알림이 실제 도착하는지**(운영자 폰만 확인), 비밀번호 재설정 메일, 신규 계정의 온보딩→첫 스캔 결과 화면(07-20 이후 변경 많음).
3. **용량** — 활성 사업장 약 35~50곳이 모델 추정 한계. 10곳 이내는 여유로 보이나 실측 아님.
4. **법적 회색지대** — 네이버 접속 방식은 변호사 의뢰 보류 중(사용자 위험 수용). 방침 시행일은 기존 가입자 11-08.
5. **장애 보상 문안·약관 정합성**(제5조·제8조)과 3일 연장의 실제 청구일 이동 동작.
6. 베타 후기(`testimonials.ts`)는 모두 자리표시자지만 **모두 자리표시자면 후기 섹션 자체가 렌더링되지 않는다**(`Testimonials.tsx:14`) — 가짜 후기가 노출되는 문제는 없고, 실제 후기 확보는 성장 과제다.
7. 현재 DB의 계정은 **모두 개발자 계정**(사용자 확인 11-02) — 실제 결제 고객 0명, 방침·약관 시행일을 가르던 기존 가입자 6명도 제3자가 아니다.

**결정 사항 처리(11-02 밤, "오판·오탐·누락 확인 후 진행")** — 추천 결정을 하나씩 반증한 뒤 반영했다. 추천을 **뒤집은 것 1건**, **보완한 것 1건**:

- ③ 결제 실패·정지 안내 이메일 병행 → **구현**(`services/payment_notice_email.py`, 갱신 실패로 유예에 들어간 날·정지된 날 2회만, 전화번호 없는 고객 포함, 실패해도 갱신 처리를 막지 않음). 문구는 실제 동작과 대조: 유예 중 매일 01:00 새 카드로 재시도·마지막 날(`grace_until`) 시도 실패 시 정지·정지 상태에서 카드를 바꾸면 즉시 재결제(`settings.update_card`). 실제 인증 서버 이메일 조회는 개발자 계정으로 확인(발송 없음).
- ⑧ 알림 설정 NULL 해석 → **옵트인(NULL=꺼짐)으로 통일**(`jobs.py` 6곳+`monthly_report.py`, 일회성 `score_model_migration_notice.py`는 제외). 운영 DB는 NULL 0행·14행 모두 True라 현재 영향 없음. 이 과정에서 NULL=켜짐을 전제한 시험 2건(그 중 하나는 "차단된 날 억제" 시험이 알림 설정 때문에 무조건 통과할 뻔한 빈 시험이 될 위험)을 고침. 재발 방지 `tests/test_notify_optin_consistency.py`.
- ⑤ 헤드라인 변화 기준 → **구간 변경만이 아니라 하이브리드로 보완**: 등급 구간이 바뀌고 변화 3점 이상(경계 근처 54.9→55.1 제외) 또는 같은 구간이어도 10점 이상일 때만 올랐다/내렸다(`stage_names.headline_direction`). "구간 변경만"은 같은 구간 안의 큰 개선(57→70)을 가린다. **근거 실측**(측정 정상 스캔 344건·9곳): 같은 가게 일간 변화 중앙값 3.9점·68%가 2점 이상 → 옛 ±2점은 측정 오차. 임계값 3·10은 제안값(10은 경쟁사 알림 변화폭 기준과 동일). 같은 화면의 **프런트 카드가 변화≠0이면 "↑ 개선됨/↓ 하락"을 따로 계산**하던 모순(헤드라인 "큰 변화 없이 유지"와 충돌)도 발견해 백엔드 판정(`headlineType`)을 따르게 했다. "이번 주 ↑/↓"와 이력 표의 ±2점도 같은 상수(10점)로 통일 — 저장된 `weekly_change`는 7일 변화가 아니라 직전 기록 대비 값이다(7일 간격 실측: 중앙값 1.2·44%가 2점 초과·21%가 10점 이상).
- ⑥ 추이 그래프 → 네이버 미확인일은 통합·네이버 선을 끊고(글로벌 선은 유지) 회색 점선+툴팁 안내. 라이브 사업장에는 미확인일이 없어 **실제 화면 확인은 못 했고** 같은 버전(Recharts 3.8.1)으로 브라우저에서 속성 조합을 렌더링해 끊김·점선·툴팁 payload를 확인했다.
- ⑦ 리뷰 본문 개인정보 제거(Claude 경로에 `scrub_personal` 적용)는 **미착수**.
- **라이브 확인(11-02)**: "홍뮤직스튜디오작곡교습소"(+4.7점·같은 단계)는 옛 기준이면 "올랐습니다·↑ 개선됨"이었으나 새 기준으로 "큰 변화 없이 유지 중"·화살표 없음, "대호흑돼지"(-10.7점·같은 단계)는 "줄었습니다·↓ 하락"으로 헤드라인과 카드가 일치.
- **새로 드러난 것**: ⓐ 서버에 추적되지 않는 옛 복사본 `backend/services/ai_scanner_deploy_tmp/`(2026-08-08, 임포트되지 않음)가 있어 새 시험이 그 안의 옛 코드를 검사해 실패 — 지우지 않고 시험이 `_deploy_tmp`를 제외(기존 시험 3곳과 같은 관례). 정리 여부는 사용자 결정. ⓑ **행동 효과 화살표**(성장 화면 하단 2곳·`ActionTimelineCard` `DeltaBadge`·이력·`Action7DayChart`)도 변화≠0이면 "↑ 점수 상승/↓ 하락"을 띄우는 같은 유형 — 4개 이상 컴포넌트라 이번 범위에서 제외, 결정 대기. ⓒ 첫 측정과 현재의 비교는 **점수 산정 방식이 바뀐 구간**(10-29 블로그 보정·11-01 ChatGPT 모델 교체 등)을 가로지를 수 있다(성장 화면에 방식 변경 안내가 있으나 헤드라인 판정은 이를 보정하지 않음) — 임계값으로는 해결되지 않는 한계.

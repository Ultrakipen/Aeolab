## 확인되지 않은 것 (미확인 — 시작해도 되지만 알고 있어야 함)
1. **30일 뒤 정기 재결제(`renewal`)** — `payment_events`에 첫 결제 성공(`billing_issue`)은 4건(09-02 ×2, 09-29, 10-27 실결제 8,950원)이 있지만 `renewal` 기록은 0건이다. 재결제 호출(`retry_billing`)은 첫 결제와 같은 `billpay`(빌링키)라 API 자체의 위험은 낮으나, 잡 로직(`subscription_lifecycle_job`)은 동작 시험(테스트)이 없다 — 아래 "추가 개선 후보" 참조. (이전 문서의 "카드창 이후 결제 완료 미확인"은 과장이었다: 첫 결제 완료는 10-27 서버 기록으로 확인됨.)
2. **제3자 번호로 알림이 실제 도착하는지**(운영자 폰만 확인), 비밀번호 재설정 메일, 신규 계정의 온보딩→첫 스캔 결과 화면(07-20 이후 변경 많음).
3. **용량** — 활성 사업장 약 35~50곳이 모델 추정 한계. 10곳 이내는 여유로 보이나 실측 아님.
4. **법적 회색지대** — 네이버 접속 방식은 변호사 의뢰 보류 중(사용자 위험 수용). 방침 시행일은 기존 가입자 11-08.
5. **장애 보상 문안·약관 정합성**(제5조·제8조)과 3일 연장의 실제 청구일 이동 동작.
6. 베타 후기(`testimonials.ts`)는 모두 자리표시자지만 **모두 자리표시자면 후기 섹션 자체가 렌더링되지 않는다**(`Testimonials.tsx:14`) — 가짜 후기가 노출되는 문제는 없고, 실제 후기 확보는 성장 과제다.
7. 현재 DB의 계정은 **모두 개발자 계정**(사용자 확인 11-02) — 실제 결제 고객 0명, 방침·약관 시행일을 가르던 기존 가입자 6명도 제3자가 아니다.

- **행동 효과의 ↑/↓ 화살표는 없애고 중립 표시로 바꾼다(소프트 런치 전 권장).** 근거: 행동 기록 91건 중 사용자가 직접 한 행동은 1건뿐이고 나머지는 시스템 자동 기록(auto_recommended 36·score_up 17·score_down 20·competitor_ahead 17)인데, `showsScoreDeltaBadge`는 `competitor_ahead`만 빼고 전부에 화살표를 붙인다 — 즉 "점수 하락" 기록 옆에 7일 뒤 "↑ 상승"이 붙는 식이다. 전·후 점수가 둘 다 있는 55건의 |Δ| 중앙값은 9.2점이고 +23.5/-18.8/+19.4/-18.7/+23.3/-24.6처럼 ±20점대가 번갈아 나오는 패턴은 행동 효과가 아니라 측정·채점 방식 요동으로 보인다. 화살표는 인과("이 행동 때문에 올랐다")를 암시해 지침 9(인과 단정 금지)와도 어긋난다. 제안 표시: "변화 없음(오차 범위)" / "등급 구간 변화 확인(상승·하락)" / "비교할 수 없음(측정 방식 변경·네이버 미확인)" + 고정 문구 "이 행동의 효과라고 단정할 수 없습니다". 판정은 `headline_direction`과 `change_signal_guard`를 재사용, 시스템 자동 기록(`score_up`·`score_down`·`auto_recommended`)에는 붙이지 않는다. 사용자 행동이 1건뿐이라 '효과 증명' 기능은 실제 데이터가 생기기 전엔 검증할 수 없다.

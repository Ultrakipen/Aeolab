## 확인되지 않은 것 (미확인 — 시작해도 되지만 알고 있어야 함)
1. **크렙 카드창 이후 결제 완료와 30일 뒤 정기 재결제** — 한 번도 못 봤다. 첫 구독자가 사실상 첫 실검증.
2. **제3자 번호로 알림이 실제 도착하는지**(운영자 폰만 확인), 비밀번호 재설정 메일, 신규 계정의 온보딩→첫 스캔 결과 화면(07-20 이후 변경 많음).
3. **용량** — 활성 사업장 약 35~50곳이 모델 추정 한계. 10곳 이내는 여유로 보이나 실측 아님.
4. **법적 회색지대** — 네이버 접속 방식은 변호사 의뢰 보류 중(사용자 위험 수용). 방침 시행일은 기존 가입자 11-08.
5. **장애 보상 문안·약관 정합성**(제5조·제8조)과 3일 연장의 실제 청구일 이동 동작.
6. 베타 후기(`testimonials.ts isPlaceholder`)는 자리표시자.
7. 현재 DB의 구독 행은 모두 운영자·시험 계정으로 보임 — 실제 결제 고객 0명(추정, 확인 못 함).

## 시작 방법 (권장)
- 초대는 5~10곳. **첫 결제는 신뢰할 수 있는 지인 1곳으로**, 결제 직후 아래 관찰 명령을 사람이 직접 확인.
- 확대 조건: 한 달 운영 + 첫 정기 재결제 1회 성공. 그 전에는 공개 홍보·광고 금지.

## 첫 72시간 관찰 (읽기 전용 명령, 서버에서)
```
cd /var/www/aeolab/backend
# 참가자 한 명의 가입→사업장→구독→스캔→알림 진행 상태 (전화번호 마스킹, 저장 안 함)
PYTHONPATH=. /var/www/aeolab/venv/bin/python scripts/rehearsal_watch.py <이메일>
# 알림 현황(최근 N일): 발송/실패/건너뜀·사유·주간 상한 원장

```
- `.env`는 `source` 하지 않는다(스크립트가 직접 읽는다).
- 매일 아침 09:30 이후: 위 4개 + `payment_events` 최근 행(실패 없는지).

## 즉시 멈춤 기준
- 네이버 차단 징후(상태 배너 변화, 대량 측정 실패 알림): `touch /var/www/aeolab/backend/.naver_kill_switch` (해제 `rm -f`). 고객 안내는 `docs/naver_outage_customer_communication_2026_11_02.md`(승인 전 초안), 메일 `scripts/subscriber_notice_email.py`(기본 드라이런), 연장 `scripts/subscription_extend_days.py`(기본 드라이런).
- 결제 이상(중복 청구·실패 반복): 신규 초대를 멈추고 `payment_events`·크렙 콘솔 대조 후 판단.
- 알림 오발송: `NOTIFY_WEEKLY_CAP=0`은 상한 해제(시험용)이므로 반대로 알림을 멈추려면 사용자 설정 또는 해당 잡 중지를 먼저 논의.

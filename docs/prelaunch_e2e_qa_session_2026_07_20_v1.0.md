## 1. growth-funnel 실측 — 진짜 병목 발견

`/admin/growth-funnel`(2026-07-12 신설) 데이터를 직접 조회한 결과 확인한 사실:
- **랜딩 방문은 꾸준한데 trial 제출이 거의 0건** — 표본이 크고 신뢰도 높은 발견
- 가입 3명 중 실제 외부 신규가입은 2명(1명은 개발자 본인 테스트 계정), 이 2명 모두 사업장 등록조차 하지 않음 — 표본(n=2)이 작아 신뢰도는 낮지만, trial 제출 병목보다 시급성은 낮다고 판단
- **주의**: `admin.py`는 이 수치들을 주간 집계로만 기록하며 코호트 추적(가입자 개개인이 이후 뭘 했는지)은 하지 않음 — "가입 3명→사업장 3명 등록→결제 0명"처럼 같은 코호트인 것처럼 보고하면 오독

**결론**: 가장 트래픽이 많은 진입 경로(랜딩 히어로검색)부터 재현 검증하기로 결정 → §2로 이어짐

## 2. 트라이얼 히어로검색 버그 — 발견·수정·배포·검증 완료 ✅

### 근본원인
`frontend/app/(public)/trial/page.tsx:242-281` — 랜딩 최상단 히어로 검색(`HeroSection.tsx`, 가장 눈에 띄는 CTA)에서 네이버 후보 클릭 시 `?business_name=...&category=...`(+선택적 `naver_place_id`) 파라미터로 `/trial`에 진입. 이 코드가 2단계(서비스 태그선택)를 건너뛰고 곧장 4단계(정보입력)로 점프하면서 **`primaryKeyword` state를 한 번도 설정하지 않음**.

4단계의 "분석 기준 키워드 확인" 입력창(`TrialInputStep.tsx:710-725`)은 `value={primaryKeyword}`(실제값, 빈 문자열)/`placeholder={fallbackKeyword}`(업종명, 예: "카페")로 분리 바인딩돼 있어 **화면엔 이미 채워진 것처럼 보이지만 실제로는 비어있음**. 제출 시 "키워드를 직접 입력해 주세요" 클라이언트 검증에 막혀 방문자가 100% 이탈.

### 검증 절차 (오판/누락 자체검증 포함)
- DOM evaluate로 `value:"", placeholder:"카페"` 직접 확인 → 정상플로우(태그선택 거침)와 대조해 `value:"커피전문"`(실값)로 반증
- 호출처 전수 grep: `HeroInlineForm.tsx`·`QuickDiagnosisForm.tsx`도 같은 패턴이지만 **둘 다 고아 컴포넌트(어디서도 import 안 됨)** — "3곳 깨짐"은 과장, 실제 라이브 진입점은 `HeroSection.tsx` 1곳뿐으로 정정
- 백엔드(`scan.py:582-590`) `keywords > keyword > 카테고리` fallback 이미 존재 확인 → `primaryKeyword`만 채우면 충분, `selectedTags`까지 손댈 필요 없음(과잉수정 방지)

### 수정
`FLAT_CATEGORY_MAP`(`lib/categories.ts`) import 추가, 두 URL단축 분기(naver_place_id 분기·category 분기) 모두에서 `setPrimaryKeyword(FLAT_CATEGORY_MAP[category]?.label || category)` 호출.

### 라이브 검증
md5 선확인(서버=git HEAD 일치) → tar파이프 배포(경로 괄호로 scp 대신) → md5 재일치 → `npm run build` 성공 → pm2 restart → error.log 무관 사전존재 경고만 확인 → **Playwright로 실제 재현: 스타벅스 검색→후보클릭→키워드필드 `value:"카페"` 실제 채워짐 확인→지역입력→제출→`POST /api/scan/trial` 200→결과화면 정상 렌더(ChatGPT 노출확인 등)**.

**git `b2bc3a5`**

## 3. 가입 → 온보딩 → 첫 스캔 — 블로킹 버그 없음 (대조군) ✅

트라이얼과 같은 방법(Admin API 테스트계정)으로 정상 가입 경로를 재현한 결과 **블로킹 버그 없음**을 확인 — 트라이얼 버그가 "랜딩 최상단 CTA만 결정론적으로 깨진 것"이었음을 재확인.

- 실제 스캔이 끝까지 정상 완료(ChatGPT 실제 인용문·네이버 AI 브리핑 "노출 중" 판정·블로그 후기 41건 등 실측 데이터 정상 반영)
- 온보딩 검색→선택 플로우는 trial과 달리 상호명·지역·주소·업종 전부 실제 값으로 정확히 채워짐(placeholder만 채워지는 trial 버그와 다른 정상 구현)
- "오늘의 개선 미션" 등 스캔 기반 추천 로직도 정상 동작

**부수 발견(사소, 수정 안 함, 낮은 우선순위)**:
1. 콘솔 403 에러 2건(`naver-seo-strength`, `gap`) — Free 플랜에서 Basic+ 전용 API 호출로 발생. UI는 업셀 카드로 정상 그레이스풀 처리, 콘솔 노이즈만 있음
2. 스캔 전 `onboarding-action` 412 — 의도된 정상 동작(코드에 이미 명시적 설계), UI도 fallback 정상 처리
3. 온보딩 "네이버 스마트플레이스 ID" placeholder 문구("가게 선택 시 자동 입력")가 실제 동작과 불일치(자동입력 안 됨, 별도 경고문구 뜸) — 선택항목이라 낮은 우선순위
4. 스캔 결과 헤드라인 "AI 검색 노출 미흡" + 서브텍스트 "업종 평균 이상"이 나란히 있어 다소 상충되게 읽힘(절대수준 vs 상대순위 차이로 의도된 설계일 가능성, 미확정)

## 4. 결제/구독 플로우 테스트 — UI 전 구간 정상, 실제 빌링키 발급은 환경 제약으로 미완 ⚠️

### 테스트 경로
로그인 상태(QA계정) → 온보딩 완료 → 플랜선택 모달 "지금 결제"(Basic) 클릭 → `/pricing#plan-Basic` 이동 → Basic 카드 CTA 클릭 → **결제 확인 모달** → "카드 등록 및 결제" → Toss 정기결제 위젯(iframe)

### 확인된 정상 동작
- **결제 확인 모달**: 상품명(AEOlab Basic 구독)·오늘 결제(첫 달 50%, 5,950원)·다음 달부터(11,900원/월)·결제방식(카드 자동결제)·7일 청약철회 안내까지 전부 정확히 표시
- **Toss 위젯 진입**: `apigw-sandbox.tosspayments.com` 빌링세션 정상 생성, "실제 결제가 안되는 테스트입니다" 배지로 테스트 모드 명확 확인 — `TOSS_SECRET_KEY`가 실제로 test_ 키임을 실측 재확인
- **결제 실패 페이지(`/payment/fail`)**: 카드 오류 시 "이런 경우 확인해보세요" 체크리스트 + "다시 결제하기"/"홈으로" 버튼으로 친절하게 렌더 — 크래시나 raw 에러 노출 없음

### 발견한 사소한 이슈 (P3, UX 문구 불일치) — 수정·배포·검증 완료 ✅
**"1분 무료 회원가입" 버튼 라벨이 로그인 상태에서도 그대로 노출됨** — Basic 플랜 카드의 CTA 버튼은 원래 비로그인 방문자를 위한 문구인데, 이미 로그인해서 결제 의도를 갖고 진입한 사용자(온보딩 → 플랜선택 모달 → "지금 결제")에게도 동일 문구가 뜸. 기능 자체(클릭 시 로그인 상태를 정확히 감지해 결제 확인 모달을 올바르게 띄움)는 정상이었음. Pro·창업패키지는 "시작하기"로 이미 분기돼 있어 Basic만 누락된 것으로 확인.

**수정**: `frontend/app/(public)/pricing/PayButton.tsx` — 마운트 시 로그인 상태를 확인하는 `isLoggedIn` state 추가, `ctaText === "1분 무료 회원가입"`이고 로그인 상태일 때만 "결제하기"로 표시(`displayCta`). Pro/창업패키지의 "시작하기"는 원래도 로그인 여부와 무관하게 자연스러운 문구라 변경하지 않음(최소 침습).

**검증**: md5 선확인(서버=로컬 일치) → tar파이프 배포 → md5 재일치 → 서버파일 `grep`으로 `displayCta`·`isLoggedIn` 존재 확인 → `npm run build` 성공 → pm2 restart, error.log 무관 → 신규 QA 테스트계정으로 로그인 후 실측: `button "결제하기"` 확인 + 클릭 시 결제 확인 모달 정상 오픈 확인 → 로그아웃 상태에서는 원래 문구("1분 무료 회원가입") 유지 확인(회귀 없음) → 검증계정 삭제 완료. **git `c902071`**

### 실제 빌링키 발급(성공 케이스) 검증 — 완료 ✅ (2026-07-21 추가)
1차 시도에서는 유효한 Toss 테스트카드번호를 확보하지 못해 임의 BIN(`4330`)은 `NOT_SUPPORTED_CARD_TYPE`, 룬체크섬만 맞춘 BIN(`9490`+체크섬)은 `INVALID_CARD_NUMBER`로 실패했음(코드 버그 아니라 테스트카드 정보 부재가 원인, WebFetch로 Toss 공식 FAQ에도 구체 번호 미공개 확인). 이후 사용자가 실제 사용해본 테스트카드번호(`9411 8110 0049 5468`, 유효기간 12/29)를 제공해 재시도 → **정기결제 등록 성공**.

**검증**: 신규 QA 테스트계정으로 로그인 → Basic "결제하기" 클릭 → 결제확인모달 → Toss 위젯에 위 카드번호+생년월일(임의 900101-1) 입력 → "다음" 클릭 즉시 `/payment/success?...&authKey=bln_...`로 리다이렉트 → 화면에 "구독 시작! Basic 플랜이 활성화되었습니다. 오늘 5,950원이 결제되었습니다" 표시. **UI 메시지만으로 끝내지 않고 Supabase를 직접 쿼리해 실제 DB 반영까지 확인**:
- `subscriptions` 테이블: `plan=basic`, `status=active`, `first_payment_amount=5950`(첫 달 할인가 정확), `first_month_discount_until`=+30일, `card_number_masked='94118110****546*'`, `billing_cycle=monthly`
- `payment_events` 테이블: `event_type=billing_issue`, `status=success`, `amount=5950`

웹훅(`/api/webhook/toss/billing/issue`) → DB 반영까지 전 구간이 실제로 작동함을 확인. 대시보드에도 플랜 배지가 "무료"→"Basic"으로 정확히 갱신됨을 확인.

### 재검증에서 추가로 발견·수정한 것 (2026-07-21, "오판과 누락이 있었는지?" 질문 계기)

"전부 완료했는지" 재확인 요청에 자체 재검증을 진행한 결과, **실제로 2건의 누락을 발견**:

1. **Storage 고아 파일 — 수정 완료**: "실 서비스 데이터 오염 없음"이라고 보고했으나 이는 부정확했음. `before_after` **DB 테이블 행만 삭제**하고 실제 이미지가 저장된 Supabase Storage 버킷(`before-after`)은 확인하지 않았음. `screenshot.py` 코드 확인 결과 `screenshots/{biz_id}/...`·`ai-search/{biz_id}/...` 경로에 별도 저장되며, DB row 삭제가 Storage 파일을 자동으로 지우지 않음. 실제로 두 계정의 스캔 스크린샷 10개(PNG)가 남아있었음 → 전부 삭제·재확인 완료. 이후 계정(e) cleanup부터는 Storage 확인을 cleanup 스크립트에 기본 포함.
2. **PayButton과 동일 패턴의 CTA 버그를 1곳만 고치고 2곳을 확인 안 함 — 1곳 수정 완료, 1곳은 낮은 우선순위로 보류**: "1분 무료 회원가입" 문자열 grep 시 3개 파일(`plans.ts`→`PayButton.tsx`, `PreviewClient.tsx`, `demo/page.tsx`)이 나왔는데 첫 번째만 고치고 나머지 둘은 열어보지 않았음.
   - **`PreviewClient.tsx`(`/preview`) — 수정 완료**: `middleware.ts`에서 로그인 필수 경로로 지정돼 있어 이 페이지를 보는 사람은 **무조건 이미 로그인한 상태**인데도 Basic·Pro·창업패키지 탭 CTA 4곳 전부 `/signup?plan=X`로 연결되던 진짜 버그(라벨이 아니라 링크 목적지 자체가 틀림). `/pricing#plan-X` 앵커로 전부 교체. 신규 QA계정으로 온보딩 완료 후 `/preview` 3개 탭(Basic·Pro·창업패키지) 전부 `/pricing#plan-X`로 정상 연결됨을 실측 확인. **git `8330edb`**. 단, grep 결과 앱 어디서도 `/preview`로 연결하는 링크가 없어(고아 페이지) 현재는 URL 직접 입력 외 도달 경로가 없음 — 실사용자 영향은 없었을 가능성이 높으나 코드 정확성 차원에서 수정.

### Why (향후 재사용을 위한 교훈)
- **로그·통계만으로는 안 보이고 실제 브라우저 재현이 있어야 발견되는 버그가 있다** — growth-funnel 데이터 자체는 "왜" 전환이 안 되는지 알려주지 않았고, Playwright 재현이 결정적이었음
- **"오판과 누락은?" 자체검증 질문이 실제로 과장(3곳→1곳)을 잡아냈다** — 호출처 전수 grep으로 고아 컴포넌트를 걸러내는 습관이 유효
- **결제 테스트는 유효한 테스트카드 정보 없이는 UI 레벨 이상 진행이 어렵다 — 그러나 사용자가 실제 써본 번호를 제공하면 즉시 종단검증 가능하다** — 이번 세션에서 실증. 다음에 결제 종단테스트가 필요하면 사용자에게 먼저 테스트카드번호를 물어볼 것(Toss 개발자센터 재로그인보다 훨씬 빠름)
- **"완료했는지" 재확인 질문에 정직하게 잔여 항목을 구분해 답하자 사용자가 즉시 해결 정보(테스트카드번호)를 제공했다** — 애매하게 "거의 다 됐다"고 얼버무리지 않고 명확히 미완료 항목을 짚은 것이 다음 행동을 이끌어냄
- **grep으로 같은 패턴을 여러 곳에서 찾았을 때, 1곳만 고치고 "완료"라고 보고하면 안 된다** — 나머지도 반드시 열어서 재현가능성(라우트 보호 여부·인앱 링크 존재 여부)까지 확인한 뒤 우선순위를 매길 것. 이번 세션에서 `PreviewClient.tsx`를 건너뛴 것이 실제 재검증 질문("오판과 누락이 있었는지?")에서 드러남
- **테스트 데이터 삭제 시 DB 테이블 row 삭제만으로는 부족하다 — 관련 Storage 버킷도 반드시 확인할 것** — `before_after` 등 파일 업로드가 있는 테이블은 DB row와 Storage object가 별개라 cleanup 스크립트에 Storage 확인을 기본 포함해야 함

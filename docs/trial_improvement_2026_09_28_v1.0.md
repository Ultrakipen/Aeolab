## 4. 잔여 과제 / 알려진 한계

1. **Gemini 결제 연결 (사용자 작업)** — 유료 스캔(scan_all/basic_trial)의 Gemini는 여전히 무료 티어 한도로 대부분 실패. 결제 연결 후 `ai_usage_log`로 성공률 재확인. 코드의 `gemini-2.5-flash` 하드코딩은 환경변수화 권장(같은 계열 Lite가 이미 종료 통보)
2. **유료 스캔의 ChatGPT도 유도형 프로브** — `_check()`(scan_all/scan_basic)는 아직 가게명을 프롬프트에 넣음. 과거 이력 연속성 때문에 이번엔 체험만 교체. 교체 여부 결정 필요
3. **"Google AI Overview" 채널 실체** — Serper 응답에 `aiOverview`가 오지 않음(서버 직접 4개 질의 0/4, 저장 스캔 301건 in_ai_overview 0건). "mentioned"는 organic 검색 언급까지 포함. 체험에는 미포함(→ "구글 검색 노출"로 정직하게 추가 가능). 유료 화면의 "Google AI Overview 실측" 문구 재검토 필요
4. **표본 5→50 후 남은 문구**: 목업에서 사용자가 "단순 5→50 치환"으로 확정. 실제 화면은 신뢰구간을 데이터에서 계산해 표시(50회 0건 → 0~7%)
5. 체험 IP 제한(3회/일)으로 라이브 반복 검증 시 캐시 주입 방식 사용(`trial_result_cache`, sessionStorage+localStorage)
6. 결과 이메일 발송이 `trial_scans` insert와 같은 try 블록 — insert 실패 시 이메일 미발송 구조는 유지(저장 버그만 수정)
7. 이전 `trial_scans` 집계(벤치마크·growth-funnel)는 7/15~9/28 공백 존재 — 07-20 "체험 전환 0건이 병목" 결론은 이 공백의 영향 가능성이 있어 재점검 필요(미검증)
8. 목업 주석 정정: "썬댄스"는 댄스학원이 아니라 카테고리 `음식점>양식`의 실제 음식점이었음 — 필터 불필요

## 6. 후속 개선 (같은 날 저녁) — 첫 화면 진단·길이 축소·계측

솔직한 평가(첫 5초 설득력 5/10, 길이, 계측 부재)에 따른 3건. 서버 반영·라이브 검증 완료.

1. **첫 화면 "한 줄 진단"** (`TrialVerdictCard`): 실측·입력에서 계산한 문장만 사용 — 헤드라인(AI/네이버 약함 여부 조합) + 불릿 3개(AI 검색: ChatGPT N회 중 M회·네이버에서 확인된 추천 가게 / 네이버 검색: 상위 결과 여부 / 블로그: 1위 경쟁사와 건수 차). 바로 아래에 "먼저 고칠 것 3가지". 추천 가게는 **네이버에서 확인된(exact/similar) 곳만** 이름으로 안내하고 "자주"라고 단정하지 않음
2. **길이 축소**: 성장단계 히어로를 네이버 전용인 "네이버 현황" 탭으로 이동(한 줄 진단과 중복), 구독 기능 잠금은 "할 일" 탭에만, 다음 측정일 중복 제거, 체험 vs 구독 비교표 접이식. 모바일 탭별 약 13~25%↓ (한눈에 5,373→4,052px, PC 3,751→2,730px). 진단 카드가 추가된 뒤의 순감소
3. **계측(GA4)**: `trial_tab_view`{tab}, `trial_priority_more_click`, `trial_direct_check`{channel, action=copy|open}, `trial_signup_cta_click`{location=next_week_band}, `trial_sub_compare_toggle`{open}. 기존 `trial_complete`·`trial_signup_cta_click`(sticky_banner/action_features_lock)과 함께 볼 것
4. **결함 수정**: `NextWeekBand`의 "무료 가입하고 다음 결과 받기"가 `onSaveTrialData`만 호출하고 가입 페이지로 이동하지 않던 것을 `Link href="/signup"`으로 수정 (기존 CTA와 동일 패턴)

남은 한계: 길이는 여전히 모바일 4,000~5,400px — 하단 공유·구독 비교 외에 탭 본문(키워드 그룹·항목별 분석 등)이 김. 사용자 반응(이탈·전환)은 계측 데이터가 쌓여야 판단 가능

## 9. 후속 개선 4 — 체험 정보의 신뢰성 재점검 (git `a1397bc` + 후속)

"개선된 체험 정보가 가치 있는가" 평가에서 약한 곳 3개를 찾아 순차 수정. 진행 전 재현으로 **내 의심 일부가 틀렸음**도 확인.

### 9-1. 블로그 언급 수 — API total → "이름이 나온 글 수"
- **의심**: 한 줄 진단이 "1위 경쟁사(안민 중동) 2,336건, 내 가게보다 2,299건 많음"이라 했는데 지명처럼 보였다.
- **정정**: "안민 중동"은 지명이 아니라 실제 가게(한식>돼지고기구이, 의창대로272번길 10)였다 — 근거로 든 "지명처럼 보임"은 틀렸다. 그러나 **수치가 부정확하다는 결론은 맞았다**: 네이버 블로그 검색 API는 따옴표를 무시하고 단어를 따로 매칭해, 상위 10건이 무인민원발급기·병원·유치원 목록 등 무관한 글이었고 이름이 나온 글은 0건(sim 정렬). 상위 100건 기준 실제 이름이 나온 글은 1건. 내 가게도 "하라식당 본점" API total 37건 중 3건뿐.
- **수정**: `_verified_blog_count`(scan.py) — 상위 100건을 받아 정규화한 가게 이름(지점 접미사 뗀 이름 포함)이 제목·요약에 실제 포함된 글만 센다(**하한값**: 본문에만 나오는 글은 빠짐, 내 가게·경쟁 가게에 동일 방식 적용). 체험 응답에서 `naver.blog_mentions`=검증 수, `blog_mentions_api_total`=원래 API total, `top_competitor_*`="검증 수가 가장 많은 경쟁 가게"(지역검색 1위는 `top_competitor_by_local_rank`), `blog_count_method` 표기. **점수 계산·DB 저장은 기존 API total 그대로**(유료 스캔과 기준 통일, 화면 표시값만 변경). 실측: 내 가게 3건, 안민 중동 1건, 참바다횟집 25건, 깽구포차 50건, 달빛에구운고등어 71건, 친절한 혜자씨 11건.
- **같은 이유로 제외**: "키워드별 블로그 비교"(`keyword_blog_comparison`)도 같은 API total 기반이라 체험 응답에서 빈 배열로 제거(검증 안 된 수치를 "실측"으로 보여주지 않음).
- **미해결(유료 경로)**: 대시보드·경쟁사 관리·점수(`blog_mention_score` 임계값 5/20/50/100)는 여전히 API total을 쓴다 — 같은 과대집계 가능성. 점수 이력에 영향이라 별도 결정 필요.

### 9-2. AI 추천 가게 카드
- 하라식당 실행에서 AI가 꺼낸 5곳 중 4곳이 "네이버에서 확인되지 않음" — 화면 한가운데 근거 약한 정보. → 네이버에서 확인된(정확/유사) 가게만 순위로 표시, 미확인 이름은 "확인되지 않은 이름 N곳 보기"로 접음(순위 제외). 확인된 곳이 없으면 그렇게 안내.

### 9-3. ChatGPT 미노출 안내
- 카드가 "원인: 소개글 Q&A 없음·네이버 키워드 미확인"을 ChatGPT 미노출의 원인으로 단정했으나 ChatGPT는 학습 데이터 기반이라 스마트플레이스 소개글을 직접 읽지 않는다(입증 안 된 인과) + 네이버 조언이 다른 탭과 중복. → "왜 안 나오나요"(학습 기반·웹 언급 부족, 정확한 원인은 특정 불가 명시) + "ChatGPT 노출을 위해 할 수 있는 일"(구글 비즈니스 프로필·블로그/홈페이지 게시·후기 요청, 수개월~1년 추정)로 교체. 네이버 조치는 "할 일·로드맵" 탭에 안내.

- 서버: 체험 응답 필드 확인, 회귀 없음(지역 없는 업종 API 호출 정상). 라이브 UI(PC): 붙여넣기 주소 경로 → 한 줄 진단 "이름이 나온 글 — 내 가게 3건 · 경쟁 가게 중 가장 많은 곳(...) 71건 — 68건 적습니다", 경쟁 막대 5곳, "키워드별 블로그 비교"·"1위 경쟁사" 문구 없음, AI 탭에 확인된 2곳만 순위+접힌 미확인 3곳+새 안내. 테스트 trial_scans 삭제.

## 10. 후속 개선 5 — 블로그 언급 수 검증 집계 전면 적용 (지역 판정 포함) (git `e3fa459` + 후속)

사용자 지시: "블로그 집계 중 **전국적으로 같은 동네 이름을 유의**하고 진행". 체험(§9)에서 유료 경로까지 확대.

### 10-1. 지역 판정 (`services/blog_mention_verifier.py`, 신설·단일 소스)
- **실측(같은 이름 "본가")**: 창원 성산구 상남동 — 이름이 나온 글 37건 중 8건이 다른 지역, 서울 강남구 신사동 — 30건 중 **14건(47%)**이 다른 지역. 개성 있는 이름은 97~100%가 지역 확인됨.
- **규칙**: 특별시·광역시(+세종) = **내 구 이름** 필요(구 이름 없이 동 이름만 쓴 글은 시 이름이 있고 다른 구 표지가 없을 때만 인정 — 강남구 신사동 vs 은평구 신사동). 일반 시 = **시 이름** 필요 + 같은 시의 **다른 구 표지만 있고 내 구 표지가 없으면 제외**(창원 성산구 상남동 vs 마산합포구 상남동, 통합시 창원은 옛 마산·진해 표지 포함, 수원·성남·용인·고양·안양·안산·청주·천안·전주 구 표 포함). 지역 정보 없음(전국·빈 값)이면 제한 없음. 구 단위만 요구하면 손실이 과하다(깽구포차 50→30)는 실측으로 시 단위를 기본으로 채택.
- 이름 변형: 이름 / 지점 접미사('본점'·'OO점') 뗀 이름 / **업종 서술어**('교습소'·'학원' 등, 남는 이름 3글자 이상일 때만) 뗀 이름 — 실측: "홍뮤직스튜디오작곡교습소"는 정식 상호로만 세면 0건, 블로그에서 부르는 "홍뮤직스튜디오"로 세면 4건(API total 6). 요리·지명 구절("함양흑돼지")은 줄이지 않는다(일반 구절 "함양 흑돼지"가 섞임 — 실측).
- 상위 100건 결과를 (이름, 지역) 키로 10분 캐시 — `get_naver_visibility_multi`가 키워드마다 같은 이름을 반복 조회하는 것을 1회로 줄임. 키워드별 비교(`blog_kw_count`)는 같은 100건에서 키워드 포함 여부로 계산(추가 호출 없음).

- `naver_visibility.get_naver_visibility`: `blog_mentions`·`top_competitor_blog_count`·`blog_kw_count`·`competitor_kw_blog_count`를 검증 집계로. 참고용 API 총건수는 `blog_region_count`로 유지, `blog_mentions_capped`·`blog_count_method` 추가. **체험에서 숨겼던 "키워드별 블로그 비교"는 유료에선 검증 집계로 복원**(체험 응답은 여전히 빈 배열 — 별도 조회 비용 회피, 필요 시 같은 방식으로 복원 가능).

## §19. 2026-10-10 ChatGPT 질문 방식 개선 — 5가지 말투 + 동네·역 이름 질문

**배경**: "미용실 추천해줘" 질문이 비현실적이라는 지적. 코드 확인 결과 ①화면에 보이는 문장("…추천해줘")과 실제로 보내는 문장("손님이 '…추천' 라고 검색했을 때 추천할 만한 가게를 최대 5곳…JSON")이 달랐고 ②50번은 같은 질문을 50번 반복한 것이었으며(`queries_used` 1개) ③유료 스캔은 이미 5가지 말투(`build_ai_scan_queries`)를 쓰는데 체험만 첫 문장만 썼다.

**서버 실험(스캐너 직접 호출, 400회 ≈ 200원, DB 쓰기 없음)**

## §23. 카카오 점수 계산 결함 수정 (2026-10-10, git 2592c11)
- 결함: `score_engine.calc_kakao_completeness`(2순위 경로)가 `kakao_result["mentioned"]`만 읽는데 `get_kakao_visibility()`는 처음부터 `is_on_kakao`만 돌려줌 → 카카오 등록 가게도 스캔 결과 경로에서 0점(사용자 체크리스트 점수 `businesses.kakao_score`나 `kakao_place_id`가 없을 때). 영향: `local_map_score`(Track1 10~15%)의 카카오 절반.
- 수정: `is_on_kakao is True`면 등록 확인 25점. `None`(조회 실패)은 등록으로 세지 않고, 다른 근거 없으면 3순위(`kakao_place_id`)로 넘김. 시간·전화·사진 항목은 이 조회로 알 수 없어 채우지 않음(체크리스트 경로 전용). 회귀 테스트 `tests/test_kakao_completeness.py` 6개, 전체 110개 통과.
- ⚠️ 건드리지 않은 곳: `scan.py`의 `kakao_data.get("mentioned")` → `businesses.kakao_score` 자동 저장 블록. 지금은 키 불일치로 죽어 있어 우연히 안전함. 살리면 25점이 저장돼 사용자 체크리스트 점수(최우선)를 덮어씀.
- 영향 범위 한계: 서비스 오픈 전이라 기존 사용자 점수 이력 영향은 없음. 오픈 후 비교 시 이 날짜(2026-10-10) 전후 카카오 점수 단절 유의.

## §24. 공용 names_match "점" 지점 표기 보완 (2026-10-10)
- 문제: `chatgpt_scanner._BRANCH_SUFFIX_RE`가 "한 글자 이상+점"만 지점 표기로 인정해 "어니언성수"↔"어니언성수점" 같은 "점"만 붙은 표기가 불일치(ChatGPT 노출 횟수·네이버 대조 과소 집계 가능, 유료 스캔 포함).
- 수정: 접미사 패턴에 단독 "점" 추가. 카카오 쪽 임시 보완(`_BARE_BRANCH`)은 삭제하고 `names_match` 하나로 통일. 회귀 테스트 `tests/test_names_match.py` 5개, 전체 115개 통과, 서버 재시작·라이브 카카오 재확인(준오헤어 왕십리역점 11위 등록, 어니언 성수 등록, 없는 가게 미등록).
- **알려진 한계(문서화, 미해결)**: 한 글자+점은 지점으로 보므로 "카페모모"↔"카페모모카점"(다른 가게일 수 있음)은 구별하지 못함 — 이 규칙에서 원래 있던 한계이며 이번 변경이 만든 것이 아님. 이름만으로는 판별 불가, 주소 대조가 있는 카카오·구글 지도 경로는 같은 구·군 확인으로 보완됨.
- 영향: 이미 저장된 과거 측정값은 재계산하지 않음(오픈 전이라 영향 데이터 없음).

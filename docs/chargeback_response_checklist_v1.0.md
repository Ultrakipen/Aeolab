# 카드 분쟁(차지백) 대응 체크리스트 v1.0

> 2026-07-16, 토스 결제 라이브 키 승인을 앞두고 점검 중 발견 — 코드·문서 전체에 이 주제 언급이 0건이었음(grep 확인). 실결제 전환 후 언젠가 카드 분쟁이 발생할 가능성에 대비해 최소한의 대응 절차만 정리. **분쟁 발생 빈도가 낮은 소규모 SaaS 운영 특성상 자동화 코드보다는 "무엇을 준비해두고, 통보받으면 무엇을 하면 되는지" 정리가 우선.**

## 1. 미리 준비해둔 것 (이미 코드에 있음, 확인만)

- `payment_events` 테이블(`backend/utils/payment_event_log.py`) — 모든 결제 성공/실패 이벤트가 `record_payment_event()`로 기록됨. 분쟁 대응 시 "이 결제가 실제 승인됐고 서비스가 정상 제공됐다"는 증빙 1차 소스.
- `subscriptions` 테이블 — `start_at`/`end_at`/`status`/`billing_key`/`card_number_masked` 등 구독 이력 전체 보관.
- `scan_results`/`guides`/`notifications` 등 — 결제 기간 동안 실제로 서비스(스캔·가이드 생성·알림)가 제공됐다는 사용 증빙.
- 이용약관(`/terms`)에 환불·청약철회·분쟁해결 조항 명시(제10조).
- 카카오 알림톡 발송 이력 — 결제·구독 관련 고지가 실제로 전달됐다는 증빙.

## 2. 분쟁(이의제기) 통보를 받으면 — 절차

1. **통보 확인 채널**: 토스페이먼츠 가맹점 대시보드 또는 고객센터(1544-7772)를 통해 통보될 가능성이 높음 — 정확한 통보 방식·응답 기한은 실제 발생 전까지 확정 불가(WebSearch로 일반 원칙만 확인, Toss 고유 실무는 미확인). **최초 라이브 결제 승인 시점에 토스 고객센터에 "이의제기 발생 시 통보 방식과 응답 기한"을 1회 문의해 확정해둘 것.**
2. **즉시 확인할 것**: 해당 `user_id`/`customer_key`로 위 1번 데이터를 전부 조회 — 결제 시점, 서비스 제공 여부, 구독 상태, 사용자와의 커뮤니케이션(카카오 알림톡) 이력.
3. **증빙 제출**: 서비스가 정상 제공됐다면 위 자료를 정리해 기한 내 토스에 제출(구체 양식은 통보 시 안내받음).
4. **소액 건은 실익 계산**: 일반적으로 차지백 대응에 2~6주가 소요된다(WebSearch 확인) — 결제 금액이 소액(Basic 11,900원 등)이면 대응 비용(시간) 대비 실익을 판단해 다투지 않고 승인하는 것이 합리적일 수 있음.
5. **반복 발생 시**: 토스 약관상 이의제기가 빈번하면 정산금 일부를 특약담보금으로 보류할 수 있음(토스 온보딩 약관 확인) — 반복되면 원인(예: 다크패턴성 UI, 해지 어려움 등) 자체를 점검할 것.

## 3. 코드 변경 없음

이번 점검은 **문서화만** — 별도 엔드포인트나 자동화 로직 신설은 하지 않음(발생 빈도가 검증되지 않은 상태에서 코드 투자는 과잉). 분쟁이 실제로 반복 발생하면 그때 관리자 화면에 조회 뷰 추가 등을 검토.

> 근거: `docs/owner_feature_research_2026_11_16.md` §8 — 소상공인실태조사 경영 애로(경쟁 심화 61.0% · 원재료비 49.6%)와 중기중앙회 조사(정부 지원사업 미참여 이유 1위 "존재를 몰라서" 76.2%). 기사 인용값이라 원문 표 재확인 전까지 "기사 인용"으로 취급.

## 1. 지원사업 공고·행사 `/support-programs` (기업마당 공개 API)

**구조(상권 `/area`와 같은 스냅샷 방식 — 방문자 요청은 외부 API·Supabase를 부르지 않는다)**
- 수집: `backend/scripts/bizinfo_collect.py`가 하루 1회, API 2곳(지원사업 `bizinfoApi.do`, 행사 `bizinfoEventApi.do`)을 `searchCnt=0`(전체)으로 1번씩 호출 → `backend/data/bizinfo/support.json`(git 제외, 원자적 쓰기).
- 공개 응답: `GET /api/bizinfo`(`routers/bizinfo.py` — 기존 `/api/support`는 문의 게시판이라 이름이 겹치지 않게 bizinfo로 함). 스냅샷이 없으면 `{"available": false}`(0건처럼 보이지 않게).
- 화면: 서버 컴포넌트가 ISR 1시간으로 받아 `SupportBoard`(클라이언트)에 전달 → 지역·분야·검색·정렬은 브라우저에서 처리(필터가 서버 부하를 만들지 않음). 지원사업 / 교육·행사 탭, D-day는 방문 시점(`useClientValue`)으로 계산하고 마감 지난 공고는 화면에서 뺀다.
- 인증키: 서버 `backend/.env`의 `BIZINFO_API_KEY`(지원사업)·`BIZINFO_EVENT_API_KEY`(행사), 백업 `/root/backend_env_backup_<시각>_bizinfo`. **키는 코드·문서·커밋에 없다**(저장소 전체 검색 확인).

**2026-11-16 실제 응답으로 확인한 사실(설계 근거)**
- 지원사업 1,330건·행사 213건. 응답은 `jsonArray`. 첨부 링크(`printFlpthNm`/`flpthNm`)에는 만료되는 다운로드 토큰(JWT)이 붙어 있어 저장하지 않고, 공고 링크는 공고 ID로 다시 만든다.
- **게시 중인 공고만 온다**(날짜 범위 405건 중 마감 지난 것 0건). 신청기간이 날짜가 아닌 문구인 공고가 925건(예산 소진시까지 647·상시 접수 135 등) — 마감 여부를 알 수 없으므로 문구 그대로 보여 주고 날짜를 지어내지 않는다.
- 지원대상(`trgetNm`): 중소기업 1,031 · **소상공인 189** · 창업벤처 73 · 사회적기업 24. 제목·태그·내용에 "소상공인"이 들어간 공고까지 245건을 저장하고, 화면 기본값은 지원대상이 '소상공인'으로 표시된 189건(체크 해제 시 245건). **자격 판단은 하지 않고 원문 분류를 그대로 표시**한다.
- 전국 대상 공고는 모든 지역 해시태그가 붙는다 → 10곳 이상이면 "전국"으로 표기하고 지역 필터에 항상 포함.

**안전장치(시험 24건 + 변이 4종)**: 지원사업 호출 실패·원본 50건 미만이면 기존 스냅샷 유지(종료코드 2·3), 소상공인 관련 건수가 이전의 절반 아래로 줄면 저장하지 않음(`--force`로 무시), 행사 호출만 실패하면 기존 행사 목록 유지, 오류 메시지에서 키를 가림, 끝난 행사 제외, 잘못된 ID·`javascript:` 링크 제거.

**운영**
- 갱신: 서버 cron(사용자 설치) — `10 4 * * * flock -n /var/lock/bizinfo_collect.lock bash -c "cd /var/www/aeolab/backend && PYTHONPATH=. ../venv/bin/python scripts/bizinfo_collect.py >> /var/log/bizinfo_collect.log 2>&1"`. 설치 전에는 11-16 21:58(KST)에 한 번 받은 값이 계속 보이고 날짜 지난 공고는 화면에서 빠진다.
- 현황: 서버 `backend/`에서 `PYTHONPATH=. ../venv/bin/python scripts/bizinfo_collect.py --status`.
- **미확인**: 기업마당 이용약관·공공누리 유형(출처 표기·상업적 이용 조건), API 일일 호출 한도(하루 2회 호출이라 문제될 가능성은 낮음), 원본 실태조사 표.
- 노출: 푸터·메뉴(`FeatureNav`)·도구 허브·사이트맵(`/support-programs`, daily)에 추가.

## 2. 원가 계산기 2종 (`lib/calc/index.ts`, 프런트 전용)

- `/tools/menu-cost` 메뉴 원가·원가율: 재료 원가 = 산 금액 ÷ 산 양 × 사용량 ÷ (1 − 손실률), 1인분 원가 = 재료비 + 기타. 판매가(부가세 포함 선택)로 원가율·남는 돈·마진, 목표 원가율을 맞추는 판매가(정확값·100원 올림). **입력이 덜 끝난 재료가 있으면 계산을 멈춘다**(일부만 더한 값이 원가처럼 보이지 않게). 적정 원가율은 기준이 없어 기본값을 넣지 않음.
- `/tools/price-increase` 원가 상승 가격 인상: 가격을 그대로 두면 남는 돈·원가율·월 이익 변화, 남는 돈을 지키는 판매가(P+Δ)와 원가율을 지키는 판매가(P×C′/C). 판매량 변화는 반영하지 않는다고 화면에 명시.
- 시험(`npm run test:calc`, 39건): 손계산 기대값(예: 원두 540+우유 500+기타 300=1,340원·원가율 29.8%·VAT 포함 32.8%·목표 30% 4,467/4,500·손실 20% 2,500, 원가 상승 4,500원 메뉴 20% → 마진 유지 4,700·원가율 유지 5,172)과 변이 4종 검증.

## 3. 만들면서 막은 실수
- 라우터 이름 충돌: `routers/support.py`·`/api/support`가 이미 문의 게시판이었다 → 덮어쓰기 직전에 막혀 `bizinfo`로 개명(화면 경로도 `/support-programs`).
- 서버 테스트가 `.env`를 읽는 수집기 `main()` 때문에 서버에서만 실패(서버에는 실제 키가 있어 `delenv`가 무력화됨) → 시험에서 `load_dotenv`를 막음. 서버 배포 스크립트가 자동 되돌려 서비스 영향 없음.
- 새 줄 번호를 `setState` 함수 안에서 뽑아 개발 모드에서 번호가 건너뛰던 문제 → 함수 밖으로 이동.
- 배포 목록 점검: 새 디렉터리·파일을 `deploy_area_tools_frontend.sh`에 추가하고, 이미 커밋한 뒤 배포할 때 md5 기준을 `DEPLOY_BASE_REF=<서버에 마지막으로 반영한 커밋>`으로 지정.

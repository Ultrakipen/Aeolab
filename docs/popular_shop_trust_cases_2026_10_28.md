# 인기 가게 체험 결과 화면 점검 — 어니언 성수 (2026-10-28)

> 핸드오프 `popular_shop_trust_improvement_handoff_v1.0.md` §4 P1(유명 가게 시나리오 검증)의 첫 사례.
> 방법: 라이브(`https://aeolab.co.kr`)에서 랜딩 히어로("성수" + "어니언 성수") → 후보 선택 → "이 가게 맞아요" → 체험 1회 실행, PC(1280)·모바일(390) 화면 전체와 본문 텍스트를 저장해 대조.
> 한계: 1개 가게·1회 실행. 하라식당 등 다른 사례와 비인기 가게는 미점검. 체험은 플레이스 ID 없는 후보 경로(네이버 플레이스 접속 없음)로 실행했다.

## 발견과 처리

| # | 발견 | 근거 | 처리 |
|---|---|---|---|
| A | **구글 지도 "찾지 못했어요" 오탐** — 구글에 "어니언 성수점"(아차산로9길 8)이 있는데 미등록으로 판정하고 "구글 비즈니스 프로필에 등록하라"고 안내 | Serper 응답 주소는 `아차산로9길 8`(구 이름 없음). `_is_my_place`가 `성동구`가 주소에 없다고 거절(이름 비교 `_same_name`은 통과) | **수정·배포** `google_places_visibility._is_my_place` — 주소에 구·군·시가 적힌 경우에만 구 일치 검사. 기존 테스트는 전부 구 이름이 든 주소라 못 잡았음. 변이 검증(수정 제거 시 새 테스트 실패)·418개 통과·라이브 재확인(상위 7위, 평점 4.2·리뷰 4개) — git 9d48882 |
| B | **첫 화면에 경고만 보임** — `TrialVerdictCard`가 경고 항목 하나만 노출하고 나머지는 접음. 확인된 강점("이번 측정 결과")은 화면 맨 아래 | 한 줄 진단 "…상위 5곳에서는 찾지 못했습니다" + 주황 경고만 첫 화면 | **수정·배포** 같은 카드에 "측정으로 확인된 것"(스마트플레이스 등록·ChatGPT 횟수·블로그 글 수·구글 지도 등록·카카오 순위·방문자 리뷰) 추가. 값이 있는 실측만, 경고가 있을 때만 — git 1b48d14 |
| C | **"상위 5곳에 없음"이 측정 한계인데 결과처럼 읽힘** — 네이버 지역검색 API는 5건만 반환 | 카드 문구 "지역 검색 상위 5곳 안에 내 가게가 없어요" | **수정·배포** "이 측정은 상위 5곳까지만 볼 수 있어, 그 아래 순위는 알 수 없어요" 명시(5개 길 카드·한 줄 진단 근거). 헤드라인의 "찾지 못했습니다"는 사실이라 유지 |
| D | 리뷰 수·평점이 화면 어디에도 없음 | 후보 선택 경로에 플레이스 ID가 없어 리뷰 수집 안 됨 | **미해결** — 수집하지 않은 값을 만들어 낼 수 없음. 플레이스 접속이 필요한 개선이라 차단 보호(속도·쿼터)와 함께 설계해야 함 |
| E | 블로그 28건이 "5번째, 글이 적은 편" | 비교 대상은 지역검색 상위 5곳, 제목·요약에 구 이름이 있는 글만 집계. 화면에 한계 문구 이미 있음 | **유지** — 실측이며 한계 안내됨 |

## 확인했더니 이미 있어서 만들 필요 없던 것
- ChatGPT 분모("50번 중") 표시 — 이미 모든 위치에 있음.
- 체험 화면에는 총점 라벨("AI 검색 준비도 · …")과 점수 숫자가 없음 → "측정된 범위 기준" 라벨 과제는 이 화면에서는 해당 없음(대시보드 쪽은 별도).

## 남은 것
- 구글 지도 항목의 리뷰가 4개인 것은 구글(Serper) 응답 그대로의 실측값이다(영문 이름 검색에서도 같은 항목 하나뿐). 유명 가게인데 리뷰 4개로 보일 수 있으나 지어낼 수 없다. 화면은 "구글 지도 평점·리뷰 수는 네이버와 별개"라고 안내 중.
- D(리뷰 수 미수집), 다른 인기 가게 사례(하라식당 등)·비인기 가게 점검, 로그인 대시보드 실화면 점검.
- ChatGPT 횟수는 같은 가게 연속 두 번 실행에서 18→16, 21→22로 달랐다(화면이 "몇 번 정도는 달라질 수 있다"고 안내하는 범위).

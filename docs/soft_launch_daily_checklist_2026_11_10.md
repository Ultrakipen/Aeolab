# 소프트 런치 일일 점검표 (2026-11-10)

> 대상: 초대·지인 5~10곳 소프트 런치. 전면 홍보는 **첫 정기 재결제 성공 뒤**(`docs/soft_launch_runbook_2026_11_02.md`). 이 문서는 하루 단위 절차와 중단 조건만 모은다.

## 매일 (2분)
서버에서: `cd /var/www/aeolab/backend && PYTHONPATH=. /var/www/aeolab/venv/bin/python scripts/daily_launch_check.py` (읽기 전용, 개인정보 비출력, 조회 실패는 "확인 못 함"으로 표시)
추가로 `pm2 logs aeolab-backend --err --lines 60 --nostream`(0건이 정상)·`https://aeolab.co.kr/health`.

| 항목 | 정상 | 이상일 때 |
|---|---|---|
| 최근 24h 스캔 저장 | 대상 사업장 수와 같거나 슬롯 분산상 일부 | 0건이면 02:00 잡·킬스위치(`.naver_kill_switch`) 확인 |
| system_alerts | 0건 또는 info(`lock_contention` 등 동시 요청 충돌) | warning 이상은 내용 확인 |
| 결제 이벤트 | 가입자가 있을 때만 발생 | 결제 실패·유예가 연속이면 중단 조건 참고 |
| 재가입 방어 보관 키 | 할인 결제·체험 시작 때만 증가 | 증가했는데 결제가 없으면 점검 |
| 가드 설정 | `DISCOUNT_KEY_GUARD_ENABLED=true` | 꺼져 있으면 `.env` 확인 |

## 날짜별
- **11-17부터**: NID_SES 쿠키 교체 경고 구간. 10-25 발급·30일 주기라 **11-24 전후 만료**(2026-11-10 서버에서 확인). 교체는 사용자만 가능(네이버 로그인). 만료되면 브리핑 측정이 로그인 없이 돌아 결과 해석이 달라질 수 있음.
- **첫 가입자 발생 시**: 결제일부터 7일이 자동 환불 가능 구간이지만 **첫 자동 측정이 돌면 환불 자격이 끝난다**(정기 자동 측정도 이용으로 셈). 가입자의 다음 자동 측정 시각은 `scan_scheduling.next_auto_scan_kst`로 확인 — Basic은 주 2회라 7일 안에 반드시 돈다. 가입자에게 "첫 측정 전에 환불 가능"이라고 정확히 안내할 것.
- **결제 30일 뒤**: 첫 정기 재결제(`subscription_lifecycle_job` 01:00, `end_at` 기준). 성공 확인 전에는 전면 홍보 금지. 지금까지 `renewal` 기록 0건.

## 중단 조건 (하나라도 해당하면 신규 초대 멈추고 원인 확인)
1. 네이버 차단 표식 연속(쿨다운 발동 알림) — 접속을 늘리지 말 것, 킬스위치 고려.
2. 결제 이중 청구·환불 실패·갱신 실패 알림 1건이라도.
3. 같은 가게의 점수·등급이 측정 없이 크게 바뀐 알림(측정 빠진 스캔 비교 금지 규칙 위반 징후).
4. 알림톡 전달 실패가 연속(`notifications` status 확인).

## 사용자 몫 / 보류 (재촉 금지 항목 포함)
- 크렙 문의 발송(문안 `docs/resubscribe_discount_abuse_prevention_design_2026_11_10.md` §12-3).
- 변호사 확인(네이버 접속 적법성·방침 보관 문안·약관 §5 "이용" 정의) — 사용자가 당분간 보류.
- 소프트 런치 대상·시작 시점 결정, 베타 후기 확보.
- **미확인**: 로그인 후 화면 모바일 실측(계정 필요), 실제 결제·탈퇴 흐름에서의 재가입 방어 동작, 실제 정기 재결제.
- 이용자가 생긴 뒤 방침을 바꿀 때는 방침 9조의 7일 사전 공지를 지킬 것(이번 11-10 당김은 이용자 없음 확인에 근거한 예외).

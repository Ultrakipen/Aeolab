## 1. 결론 (세 질문에 대한 답)

### Q1. 네이버가 차단되면 어떻게 대응하는가
- **자동 방어는 있다**(§3.2): 속도 제한기, 플레이스·검색 화면 회로 차단기(차단 시 자동 중단·쿨다운·단계 상승), 일일 상한, 정기 잡 몫, 차단 시 결과를 '확인 전'으로 처리, 운영자 알림, 사용자 화면 배너.
- **그러나 비어 있는 것이 있다**(§3.4): ① 실제 **검색 화면 차단의 모양을 본 적이 없어** 감지 못 할 수 있음 ② 전체 네이버 접속을 한 번에 끄는 스위치가 없음(AI탭 스위치만 있음) ③ **며칠 이상 차단될 때 고객 보상·공지 정책이 없음** ④ 차단 모의 훈련을 한 적 없음 ⑤ 법적 회색지대의 변호사 자문이 대기 중.
- 네이버 의존은 핵심이다. 따라서 "차단을 피한다"가 아니라 **"차단돼도 신뢰를 잃지 않고 복구한다"**를 목표로 런북(§3.3)·보완 작업(W-1~W-7)을 마련했다.

### Q2. 사용자 증가에 따른 알맞은 운영 방식
- 현재 실제 유료 고객은 사실상 0명[확인: 활성 구독 4건은 내부 계정으로 보임, 미확인]. **제한적 출시(초대 기반 10~20곳)** 로 시작해 단계별로 늘린다(§4).
- 용량의 병목은 **서버 사양이 아니라 네이버 접속 한도와 Supabase 무료 등급**이다. 코드 기준 모델(실측 아님)로 현재 구성의 안전선은 30~50곳이고 이 수치는 구독자가 생기면 실측으로 보정한다.
- 규모 단계마다 **지표 → 임계값 → 조치**를 정했다(§4.2). 결정이 필요한 조치(가입 제한, 유료 인프라)는 §6에 모았다.

### Q3. 지금 사용자가 돈을 낼 만한 서비스인가
- **솔직한 판단: 아직 증명되지 않았다.** 진단 기능과 안전장치는 강하지만 ① 핵심 지표(ChatGPT 기억 모드)가 사용자가 보는 실제 AI 화면과 어긋나는 사례가 있고 ② 처방이 노출을 올린다는 증거가 없으며 ③ 실사용자 데이터가 0이고 ④ 체험→가입 전환이 0이다(§5.2).
- 그래서 소프트 런치는 "팔기"가 아니라 **가치 가설을 검증하는 실험**으로 설계한다. 보완안은 P0(측정 기준 정렬, V1 마무리, 4주 베타 코호트), P1(네이버 가치 재정렬, 결과 해석 개선), P2(§5.4).

### 3.3 시나리오별 런북

각 시나리오는 **징후 → 자동 동작 → 사용자에게 보이는 것 → 운영자 행동 → 복구 판정 → 사후 기록** 순서다.

**S1. 플레이스 접속 차단(10-27 사고와 같은 유형)**
- 징후: 운영자 알림 "네이버 플레이스 접속 제한 감지 — 자동 중단", `naver_block_events`에 block 행, `/api/status/naver`가 `delayed`.
- 자동: 회로 열림(쿨다운 3h부터), 이후 플레이스 접속 함수는 네이버 요청 없이 `naver_place_cooldown` 반환, 속도 한도 48시간 절반.
- 사용자: 배너("네이버 확인이 지연되고 있어요…"), 점수·순위는 마지막 성공값+날짜 또는 '확인 전'. **0점·미노출로 바뀌지 않음.**
- 운영자: ① 서버에서 네이버 점검 함수를 호출하지 말 것 ② `GET /admin/naver-access`로 회로 상태·쿨다운 잔여 확인 ③ 쿨다운 종료 후 시험 접속 결과를 기다림(강제로 회로를 닫지 않는다 — 차단 연장 위험, [제안]) ④ 같은 날 사용량이 몫을 넘었는지 확인해 원인 분석.
- 복구 판정: 시험 접속 성공 → `recovering` → 정상. 또 차단이면 쿨다운 2배.
- 사후: 원인(몫 초과? 수동 스캔 몰림? 신규 가입 첫 채우기 몰림?)을 `docs/`에 사건 기록, 필요 시 한도(몫·속도) 하향.

**S2. 검색 화면 차단(브리핑·AI탭·순위)**
- 징후: 브리핑·순위가 갑자기 대량으로 `error`/'확인 전', 카드 0개, CAPTCHA.
- 자동: 검색 회로(60분부터), 캡차 감지는 기존 브리핑 스캐너 연결.
- **한계 [확인]**: 실제 검색 차단 화면의 모양을 본 적이 없다. 다른 모양이면 감지하지 못하고 '카드 0개'로 읽힐 수 있다(키워드 순위는 카드 0개를 측정 실패로 처리하는 방어가 있음 — 코드 `naver_keyword_rank`의 카드 0개 판정, 세부 재확인 필요).
- 운영자: 한 사업장이 아니라 **다수 사업장이 동시에 실패**하면 화면 구조 변경(S5) 또는 차단. 둘을 구분: 로컬 PC에서 Playwright 1페이지로 같은 검색을 열어 화면을 본다(서버 금지).

**S3. 로그인 쿠키(`NID_SES`) 만료·거부**
- 징후: AI 브리핑이 연속 실패, 주간 점검 메일. 만료는 약 30일 주기(마지막 교체 2026-10-25, **다음 교체 약 11-24**).
- 자동: 연속 실패 시 백업 쿠키 사용 시도(백업 값이 있을 때), 알림 메일.
- 운영자: 수동 교체 절차는 `docs/naver_briefing_block_countermeasure_handoff_v1.0.md` 참조. **자동 재로그인은 켜지 않는다.** 로그인 세션 사용은 법적으로 가장 민감하다(§3.5).
- 영향: 브리핑·AI탭만 '확인 전'. 나머지는 영향 없음.

**S4. 공식 API 이상(키 만료·쿼터·네이버 점검)**
- 징후: `Naver API <kind> HTTP <코드>` 경고 로그, 지역검색·블로그 결과 빈 응답.
- 영향: 이름 대조 기반 등록·순위 판정이 빈 결과 → **'없음'이 아니라 '확인 못 함'으로 처리되는지 확인 필요** [미확인: `_get`이 실패 시 `{}`를 반환하므로 호출부별 처리를 점검할 것 — 작업 T-7].
- 운영자: 키 상태·쿼터 확인(`NAVER_CLIENT_ID/SECRET`, API Hub), 일일 한도는 약 25,000건으로 알고 있으나 이 키의 실제 한도는 미확인.

**S5. 네이버 화면 구조 변경(셀렉터 깨짐)**
- 징후: 전 사업장에서 `briefing_unrecognized`·`page_load_failed`·순위 전부 None이 갑자기 증가.
- 운영자: 로컬 Playwright 1페이지로 구조 확인 → 셀렉터 수정 → 픽스처(`tests/`의 실제 응답) 갱신 → 변이 검증 → 서버 배포. 그 동안 화면은 '확인 전'이 유지되어야 한다.

**S6. 장기 차단(3일 이상) — 제품·고객 대응**
- 현재 정책 없음 [확인]. **제안(결정 필요, D-3)**: ① 24시간 이상 지연되면 공지사항·배너 문구를 "네이버 확인 지연 중, 복구 시 자동 재측정"으로 고정 ② 3일 이상 네이버 의존 측정이 불가하면 해당 구독자에게 기간 일할 연장 또는 요청 시 환불(제안값: 7일 이상이면 환불 선택권) ③ 복구 후 재측정을 우선 큐로 ④ 고객 안내문은 사실만(원인 추정 금지).
- 대체 가치 유지: 글로벌 AI 트랙·콘텐츠 도구는 계속 동작함을 안내.

**S7. 법적 통지·약관 위반 경고(네이버 측)**
- **킬스위치 구현됨(2026-11-02, 아래 §7.3)**: 서버에서 `touch /var/www/aeolab/backend/.naver_kill_switch` → 재시작 없이 다음 접속 시도부터 모든 Playwright 네이버 접속이 멈춘다(`rm`으로 해제). 사용자 화면에는 "네이버 확인을 잠시 멈춰 두었어요" 배너가 나온다. 환경변수 `NAVER_ACCESS_KILL_SWITCH=true`(+재시작)로도 켤 수 있다.
- 변호사 자문이 먼저다. 코드의 임의 축소·제거는 금지(회색지대, 핵심 기능).

### 4.3 가입·출시 운영 방식
1. **소프트 런치(10~20곳)**: 초대 기반. 가입을 막는 수단은 현재 확인되지 않음 → ① 가격·가입 링크를 공개하지 않는 방식 ② 기존 `capacity/waitlist`(대기자 명단)로 전환 후 수동 승인 — 선택 [D-2].

## 5. 질문 3 — 지금 돈을 낼 만한 서비스인가, 보완은

### 5.1 판단 틀
고객이 월 17,900원을 내는 이유는 네 가지 가설이 모두 성립할 때다. **H1** 진단이 정확하고 믿을 만하다. **H2** 처방이 실행 가능하고 효과가 있다. **H3** 계속 볼 이유가 있다(변화 추적·알림). **H4** 대안(무료 ChatGPT 직접 질문, 다른 서비스)보다 낫다.

### 5.2 현재 증거 [확인]

**H1 진단의 신뢰**
- 강점: 측정 못 한 것은 '확인 전', 인기 가게 저평가 방어, 표본 10회 미만 '참고용', 허위 미노출(등록명 표기) 수정, 단정·보장 문구 금지 테스트.
- **약점(가장 중요)**: 핵심 지표인 ChatGPT·Gemini 측정은 **'모델의 기억 모드'** 이고, 사용자가 실제로 보는 **검색을 켠 ChatGPT 화면**과 어긋나는 사례가 V1 수기 검증에서 나왔다(`docs/v1_validity_result_partial_2026_11_01.md`, 예비·표본 작음): 하라식당 기억 모드 0/50 ↔ 검색 켠 3회 중 2회 추천(1위·3위), 힐링하우스마사지 0/100 ↔ 2/2회(2위), 홍뮤직스튜디오 0 ↔ 검색 켠 3위·1위. 어니언 성수는 기억 0.5 ↔ 검색 켠 1/2. **"측정이 낮게 나오는데 실제 AI 화면에는 나온다"가 반복되면 신뢰를 잃는다.** 이번에 문구는 "이번 측정에서는 확인되지 않았고 검색을 켠 화면에서는 다를 수 있다"로 정정했지만 측정 자체가 소비자 화면을 반영하지 않는다.
- 새 모델 영향: `gpt-6-luna`는 결정적이라 노출률이 0/1로 쏠리고(점수 영향은 음식점 기준 ChatGPT 최대 약 3% 문서 기록, 이번에 재계산하지 않음) 소규모 지역 질의에서는 거의 항상 0이다.

**H2 처방의 효과**
- 처방 도구는 풍부하다(가이드·소개글·FAQ·블로그 초안·리뷰 답변·위기 대응·QR 카드·AI 광고 대비). 그러나 **"처방을 실행하면 노출이 올라간다"는 증거가 없다**: 행동-결과 타임라인 기능은 있으나 실사용 데이터가 0이다. AI 노출을 움직이는 레버(리뷰 수, 기존 지도 순위, 구글 비즈니스 프로필)는 대부분 외부 요인이고 반영 시간도 길다(ChatGPT 수개월~1년).

**H3 지속 가치**
- 알림톡은 11-01 운영자 폰 수신 확인뿐, **제3자 번호 수신 미확인**, 개정 템플릿 3종 승인 대기. 월간 리포트·주간 성적표는 첫 정기 발송이 12-01·후속.

**H4 대안 비교** [확인: `docs/competitor_landscape_analysis_v1.0.md`]
- 국내에서 네이버 AI 브리핑·AI탭을 정면으로 다루는 서비스는 AI-VIEW(대행 컨설팅 모델) 한 곳, 가격이 가장 근접한 서비스는 블로그 단일 채널 진단(월 19,900원대)이다. 무료 ChatGPT에 직접 묻는 대안은 항상 존재한다.
- **퍼널 실측(11-01 재점검으로 정정)**: 누적 체험 261건 중 이메일을 남긴 것은 47건(약 18%)이고 가입 전환은 0건이다. 최근 30일 21건은 이메일 0건이다. 체험 행의 상당수가 개발·운영자 테스트로 보여(같은 IP에서 73·65회) **외부 이용자의 전환율은 이 숫자로 알 수 없다**. "이메일 0"을 "체험이 전혀 이어지지 않는다"로 읽지 말 것.
- **랜딩의 '지금까지 77개 가게 분석 완료'**(서로 다른 가게 수)도 같은 이유로 **외부 이용자 수를 과대하게 보여 줄 가능성이 크다**(93곳 중 약 61곳이 다량 사용 IP 출신). 소셜 프루프 수정 필요(T-16).
- **체험 결과의 스마트플레이스 점검 필드는 261건 중 80건(약 31%)에서만 채워진다**(경쟁사 목록 89%, 블로그 언급 93%).
- **11-01 라이브 확인(비로그인·모바일, 어니언 성수로 실제 1회씩 3회 실행, 시험 행 3건 삭제)**: 무료 결과는 탭 5개(**한눈에 / 경쟁 비교 / 네이버 현황 / AI 검색 / 할 일·로드맵**)이고, 경쟁 비교 탭(네이버 검색 상위 가게 목록·블로그 글 수 비교 "주변 6곳 중 5번째"), 네이버 현황 탭(블로그 33건·키워드 보강 필요·AI 검색 준비도), 할 일 탭(스마트플레이스에 붙여 넣을 소개글 키워드)이 실제로 나온다. 즉 **무료 진단은 '플레이스·블로그·경쟁사·AI 검색'을 이미 한 화면에서 보여 준다 — 랜딩 첫 화면이 이를 말하지 않을 뿐이다.** 단 **스마트플레이스 소개글·소식·리뷰는 자동 측정이 아니라 사용자 입력**("AEOlab이 직접 보지 못했어요")이고, 키워드 목록은 "업종 기준 추정"으로 표시돼 있다. 문구는 "스마트플레이스 등록 여부와 먼저 고칠 항목"까지만 약속할 것. AI 브리핑·AI탭·매주 자동 추적·경쟁사 3곳 직접 등록 비교는 **가입 후**(`SubscriptionValueCompare` 기준 — **'스마트플레이스 부족 항목 체크'는 무료 쪽에 포함**, 직접 입력 값 기준).
- **라이브 확인으로 보정**: 앞서 "체험 결과에 경쟁사 카드가 있다"는 근거 일부가 죽은 컴포넌트(`TrialDetailAccordion` 쪽)였으나, 실제 라이브 화면에는 같은 정보가 탭 구조로 있다. `ChatGPTResultCard`의 신뢰구간 문구("서로 다른 질문 5개 기준으로 보면 실제 언급 가능성은 약 57~100%")는 **'AI 검색' 탭에서 실제로 보인다**(기본 탭이 아니라 숨겨져 있어 일반 텍스트 추출로는 안 잡힘). 모바일 가로 넘침 없음, 옛 단정 문구 없음.
- **체험 소요 약 56초, `gpt-6-luna` 정상**(구 이름 50회 중 48~49, 동네 이름 50회 중 50). 결과에 가입 경로("무료 가입하고 다음 결과 받기", 첫 달 8,950원·7일 이내 환불)가 있다 — "가입할 이유가 없다"는 단정은 근거가 약하다.
- **남은 과장 후보(라이브에서 발견)**: 'AI 검색' 탭의 "구독 시엔 100회 — **표본이 많을수록 결과가 안정적입니다**"는 새 모델(같은 질문에 거의 같은 답)과 어긋난다 → T-16에 포함.
- **모바일 랜딩 첫 화면(비로그인 확인)**: 무료 진단 **입력창이 보이지 않고** 헤더의 "무료 진단" 버튼만 있다(PC는 입력창·'77개 가게'가 첫 화면). 통합 메시지는 PC·모바일 모두 첫 화면에 없다.
- **개발 테스트 비율 근거 보강**: 가장 많이 쓴 `ip_hash`(f99e12, 73회)는 이번 확인에서 **내 시험 실행이 같은 해시로 기록돼 개발자 IP로 확정**됐다(두 번째 65회는 미확인).

### 5.3 솔직한 판단
- **현재 상태에서 월 17,900원을 내고 계속 쓸 사장님이 있을지는 증거가 없다.** 안전장치·정직성·비용 구조는 좋지만, 고객이 얻는 **결과(내 가게 노출이 좋아졌다)** 와 **확신(측정이 내가 보는 화면과 같다)** 이 약하다.
- 따라서 소프트 런치의 목적은 매출이 아니라 **H1~H4를 4주 안에 검증**하는 것이다. 이 검증 없이 홍보를 키우면 "미끼 상품" 인상과 환불 증가 위험이 있다.

## 9. 오판 기록과 미확인

**이 세션에서 정정한 오판(재발 방지)**

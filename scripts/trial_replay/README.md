# 체험 결과 화면 재생 검증 (2026-10-28)

체험을 실제로 실행하지 않고(ChatGPT 비용·IP 한도 없이) **저장해 둔 실제 응답(JSON)을 화면에 재생**해 결과 화면 문구·판정을 확인한다.
`/api/scan/trial` POST만 가로채 저장 응답으로 대신하고, 나머지(후보 검색 등)는 실서버를 쓴다.

- `onion_28of50_no_review_rank.json` — 어니언 성수(키워드 "카페") 실제 응답. ChatGPT 구 이름 28/50·동네 21/50, 후기순 순위 없음.
- `onion_12of50_review_rank2.json` — 어니언 성수(키워드 "베이커리") 실제 응답. ChatGPT 구 이름 12/50·동네 12/50, 후기 많은 순 2위.
- 같은 가게·같은 질문의 ChatGPT 구 이름 결과가 오늘 네 번 실행에서 18·16·28·12회(50회 중)로 흔들렸다 → `frontend/lib/sampling.ts`(Wilson 상한)로 "약하다" 단정 기준을 잡음 구간 밖(50회 중 8회 이하)으로.

## 주의
- **재생은 화면 로직 검증용이다. 측정값 검증이 아니다.** 횟수를 바꾼 합성 변형을 쓸 때는 반드시 "합성"으로 표기하고, 실제 응답의 ChatGPT 횟수 세 위치(`chatgpt_result`·`result.chatgpt`·`chatgpt_neighborhood`)를 모두 바꿔야 한다(한 곳만 바꾸면 변화가 없다 — 오늘 이 실수로 검증이 무효였다).
- 후보 검색 `/api/scan/trial-search`는 IP당 **분당 10회**(메모리 카운터). 한 흐름이 약 4회를 쓰므로 사례 사이에 **50초 이상** 간격을 둔다(429 → 후보 화면이 안 나온다).
- 스크립트 본문은 세션 스크래치패드에서 만든 Playwright 코드이며, 핵심은 `page.route("**/api/scan/trial", handler)` 에서 POST만 `route.fulfill(...)`로 저장 JSON을 돌려주는 것(핸들러는 클로저로 만들 것 — 기본값 인자로 `body`를 받으면 두 번째 인자 `request`가 덮어쓴다).
